# pickDday 실데이터 기반 고도화

## Goal

지역 공무원이 다양한 공공데이터를 활용해 관광 활성화에 기여할 축제를 기획·개선하도록 돕는다.
기존 축제 개선·새 축제 기획을 두 핵심 제품 흐름으로 두고 필요한 데이터를 정제·가공·연결·시각화한다.
핵심 질문은 정보 설계 기준이며 시스템이 정답을 확정하거나 사용자에게 답변·기록을 강제하지 않는다.
기획·판단·메모·결과 기록과 다음 회차 재사용은 선택 기능이다. 공모전과 실무 활용을 같은 비중으로 검증한다.

## Scope

- 2026-09-26 사용자 정정·진행 승인: 특정 축제 표본을 계속 추가하는 대신 담당자가 고른 축제에서 공통 방문·자원·시기 경험을 제공한다. 공식 TourAPI 식별자와 전국 지역별 방문 API를 기준으로 자료를 보관·갱신하고, 기존 개최 기록은 검토된 동일 축제 연결로 함께 보여 준다. 지역 방문을 축제 실적으로 바꾸거나 현재 날짜로 과거 회차를 추정하지 않는다. 아래 9월24일 범위의 전국 확대 제외는 이번 범위에 한해 대체한다. 실제 Claude Opus 5.5 위임·직접 검수와 기존 게시·정리 정책을 유지한다.

- 2026-09-24 사용자 후속 진행 승인: 공식 임실 2023·2024년 방문자 특성을 새로 확보해 2025년과 두 회차 비교로 연결한다. 성·연령 비율 차이, 외지인 구성 변화, 동일 목적지 순위 비교를 제공하고 검증된 기존 자료를 갱신 실패 때 보존한다. 실제 Claude Opus 5.5 설계·구현 위임과 직접 검수, 선택적 기록·최종 시각 디자인 후속 원칙을 유지한다. 전국 확대·축제별 거주지·주기적 자동 수집은 이번 범위가 아니다.

- 2026-09-24 다음 개선 진행 요청: 방문자 특성·연계 관광정보를 실제 Claude Opus 5.5에 조사·설계·구현 위임하고 직접 검수한다. 확인된 자료의 첫 표본은 임실이다. 축제 회차 방문 구성·지역 연간 추세를 공개하며 성·연령·거주지·목적지 순위는 기간을 추정해 연결하지 않는다. 현재 관광자원 조회는 유지하고 과거 인기 순위의 연결 완료로 확대하지 않는다.

- 2026-09-24 사용자 후속 요청: 두 핵심 흐름 구현 뒤 관련 자료 검색·원문 연결을 Claude Opus 5.5 설계·구현 위임과 직접 검수로 진행한다. 위임 범위에서 공식 검색 URL 형식을 확인해 DuckDuckGo 새 탭 연결을 채택한다. 기사 수집·수치 반영·AI 요약은 포함하지 않는다. 실제 검색 결과·원문 검증과 앱의 검색어·새 탭 동작 검증은 구분한다.
- 2026-09-23 사용자 요청: 제품 표시 이름을 `pickDday`로 바꾸고 소개·화면·현재 문서를 정리한다. 새 축제 전용 흐름을 이어 구현한다. 저장소·배포·기존 저장 형식의 식별자는 이번 표시 이름 변경에서 유지한다.
- 2026-09-23 사용자 요청: 기능·기획 개선에 집중하고, 화면 작업은 기획에 따른 목표·와이어프레임·기본 레이아웃까지 전달한다. 최종 시각 디자인은 사용자가 개선하며 이전 시안의 색·폰트·간격을 확정값으로 고정하지 않는다.
- 2026-09-22 확정 기준은 docs/product/planning-principles.md다. 관광 활성화·지역 공무원·두 제품 흐름·선택적 기록 원칙을 이후 기획에 우선 적용한다. 아래 마일스톤은 기존 승인·구현 이력이며 기록 중심 전체 완주를 필수 이용 조건으로 확대하지 않는다.
- 2026-09-22 후속 확정: 기존 축제 개선부터 공공데이터 활용 핵심 기능을 설계·구현한 뒤 뉴스 검색·원문 연결을 추가한다. 외부 보도자료 수치 자동 반영은 첫 버전에서 제외하고 AI 요약은 나중에 검토한다. 당시 DuckDuckGo 등 검색 제공자는 후보였으며 2026-09-24 위임 범위의 선택은 위 항목을 따른다.
- 기존 축제 첫 버전의 세 핵심 기능은 과거 방문 흐름 비교·주변 관광자원 연결·다음 개최 시기 검토다. 전국 기본 관광정보·행사 탐색을 제공하고 과거 분석은 자료 확보 지역부터 확장한다. 축제 선택 뒤 과거 방문 흐름을 먼저 보여주되 세 기능을 기록 없이 자유롭게 탐색하도록 설계한다.
- 데이터 차이는 정보 노출·배치·위계·글자 크기·차트와 지표 제목으로 전달한다. 내부 수집·검증 규약을 화면 제약 안내문으로 노출하지 않으며 법적으로 필요한 고지만 별도 표시한다.

- 승인된 7단계: 현재 점검 → 데이터 검증·샘플 선정 → 예측·운영 판단 검증 → 기획 확정 → 화면 설계 → 실제 축제 샘플 구현 → 공모전·실무 종합 평가.
- 축제의 과거·현재·향후 전망, 운영 결정, 결과와 다음 개최회차 재사용을 연결한다.
- 2026-09-08 사용자 목표 명확화: 내 지자체 정보가 1차, 주변 축제와 과거 기록의 비교검색이 2차 정보 수요다.
  이 순서를 가설로 검증하며 지도·조회·비교·기획을 제품의 중심 동선으로 구현한다.
- 제품 마일스톤은 `docs/design/07-region-planning-milestones.md`의 M1~M6를 따른다.
  2026-09-08 후속 지시에 따라 D0 기획·요구사항·화면설계·와이어프레임을 먼저 작성해 traceboard에 게시한다.
  문서·시안 검수 후 M1 지역 지도 → M2 비교검색 → M3 기획 대안을 구현하며, 모델 정확도 추가 연구는 뒤로 미룬다.
- 개발 정본은 WSL `~/dev/side/fest-compass`(GitHub `gitvssh/fest-compass`)이며 수정은 `~/dev/worktrees/fest-compass-<topic>`의 전용 브랜치에서 수행한다.
- 단계별 계획과 증거는 `docs/validation/`, 과거 기획 원문은 `docs/archive/2026-08-planning/`에 둔다.

## Non-goals

- 핵심 질문을 필수 설문으로 만들거나 답변·선택 이유·기획안 저장을 공공자료 이용의 선행 조건으로 요구하지 않는다. 데이터만으로 관광객 선정·방문 동기·최종 기획 판단을 확정하지 않는다.

- 지역 방문자를 축제 입장객으로 치환하거나, 사용자 가정을 실측 또는 검증된 예측으로 표시하지 않는다.
- 과거 회차 몇 개만으로 예측 성능을 단정하지 않는다. 예측 자체는 제품 목표이며, 데이터·비교실험으로 제공 범위를 결정한다.
- 외부 기관에 연락하거나 새로운 제공자 자격을 발급하는 것은 이번 개발 지시만으로 실행하지 않는다.

## Constraints

- Preserve repository instructions and safety boundaries.
- Do not expose credentials, tokens, or private session transcripts.
- 사용자가 승인한 개발·검증·일반 Git 게시·작업공간 정리는 재승인 없이 진행한다. 범위 밖의 파괴적 변경과 저장소 정책의 사람 전용 작업만 별도 확인한다.
- 공개 운영의 읽기 전용 경계와 기존 배포 ADR은 유지한다. 실제 편집 기능 공개는 선행 요건을 구현·검증하고 후속 결정으로 관리한다.

## Completion criteria

- 기존 축제 개선·새 축제 기획에서 기록 없이 공공자료를 탐색·비교하고 목적에 맞는 정보를 확인할 수 있다. 2026-09-23 기존 축제, 2026-09-24 새 축제 전용 흐름을 구현·공개 검증했다. 최종 시각 디자인과 실제 사용자 검증은 후속이다.
- 담당자가 원할 때 근거 보관·기획안·결과 기록과 재사용으로 이어진다. 기록 기능을 선택한 경우 당시 자료·조회 조건을 보존하며 전략적 질문 전체의 답변 완료를 요구하지 않는다.
- 실제 축제 한 곳의 과거·현재·예측·운영 결정·결과 기록 흐름이 구현되고 주요 수치의 출처가 추적된다.
- 예측 대상·시간 단위·예측 시점·오차·단순 기준 대비 성능 및 미검증 한계가 기록된다.
- 공모전 완성도와 실무 활용성을 같은 비중으로 평가한다. 실무자 검증 미실시는 완료로 기록하지 않는다.
- 단계별 검증 증거와 후속 개발을 남긴다. 개발환경 이전이나 첫 조사 도구 완성만으로 전체 목표를 완료로 표시하지 않는다.
- 개인 운영 기록 흐름의 공개만으로 지도 기반 축제 기획 MVP 전체가 완료됐다고 표시하지 않는다.

## 2026-09-08 탐색·시각화 구체화

아래는 당시 지역 탐색 결정이다. 2026-09-22 제품 첫 화면의 두 목적 분리 원칙이 우선하며, 지도 내부의 전국 탐색과 구분한다.

첫 지도는 전국에서 시작해 시도→시군구로 좁힌다(2026-09-08 사용자 후속 요청으로 '전국' 표기 확정). 우리 지역은 명시적 바로가기다. 과거 비교는 실제 출처·회차·지표별 확보 상태를 드러내고 그래프·파이/도넛·수치 표를 통해 기획 근거로 연결한다. 브라우저 자동 검증은 headless로 실행한다.
