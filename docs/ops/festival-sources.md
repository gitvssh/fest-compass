# 전국 축제 분석 자료 운영

공식 한국관광공사 API의 지역별 일별 외지인 방문과 전국 축제 등록 일정을 보관한다. 축제 하나를 지원하기 위해 제품 코드를 추가하지 않는다. 공개 웹은 읽기만 한다.

- `festival-source-worker`는 기존 앱 Pod에서 독립 실행한다. `/data/festival-sources` PVC 하위 폴더만 쓴다. 업무 SQLite와 `/data/forecast`를 마운트하지 않는다. 기존 논산 예측 입력·고정 14개 코드·사전 시험은 변경하지 않는다.
- 첫 실행에서 2023-01부터 전월까지 채운다. 하루 과거 수집 상한 180회(방문 최대 162회, 축제 최대 18회), 정상 일상 갱신은 최대 30회(방문 12회, 축제 18회)다. 첫 실행은 당월도 별도로 갱신하며 두 작업이 같은 날 수행되면 축제 조회는 공유한다. 무제한 재시도는 없다.
- 과거 수집이 중단되면 저장한 달은 다시 받지 않고 다음 날 남은 달부터 이어간다. 영구 누적 상한 때문에 재개가 막히지 않도록 일별 호출 기록으로 제한한다. 정상 이후 매일 최근 90일에 걸친 달과 축제 등록을 갱신한다.
- 기존 제공자 키를 사용한다. 새 자격·권한·서비스를 만들지 않는다. 키는 환경변수로만 전달하고 URL·응답 오류 원문은 로그·화면에 출력하지 않는다.
- 커널 파일 잠금으로 중복 실행을 막는다. 프로세스 종료 시 잠금이 풀리고, PID 파일 삭제나 오래된 잠금 추측으로 재시작을 복구하지 않는다.
- 원천별 실패는 분리한다. 페이지 누락·중복·전체 건수 변화는 보관본을 교체하지 않는다. 방문 보관본은 원자적으로 교체하고 이전 정상본을 함께 보존한다. 파일 검증·128MiB 상한·최소 여유 64MiB·40일 호출 기록 보존을 적용한다.
- 값 없는 날짜는 `null`이다. 한 달의 모든 날짜가 있어야 월평균을 계산한다. 통계 미공표·행정구역 개편으로 기간이 짧아져도 이전 인원을 복제·배분하지 않는다. 날짜별 원 수집시각을 보존하며 다른 달의 갱신으로 옛 관측값의 시각을 바꾸지 않는다.
- 지역 대응은 현재 관광조회 코드와 [공식 코드 변경 근거](../research/imported/mois-2026-region-codes/README.md)를 따른다. 분할·합병한 구는 새 코드 관측만 사용한다. 지도 경계 정확성 인증으로 확대하지 않는다.
- 축제 일정은 동일 콘텐츠 ID·지역에서 관측한 등록 이력이다. 회차 개최 사실·취소 확인이 아니다. 지난 회차와의 검토된 연결은 별도 데이터이고, 일치하지 않는 이름을 자동으로 병합하지 않는다.

## 조회·복구

`SOURCE_DATA_DIR`가 없으면 기존 보관 자료를 사용한다. 기본 운영 경로는 `/data/festival-sources`다. 작업 상태는 해당 경로 `status.json`, 생존 시각은 `worker-heartbeat.json`에서 확인한다. 이 파일들은 내부 운영 자료로 화면·API 응답에 포함하지 않는다.

정상 작업자는 매일 한 번 실행하며 컨테이너 재시작 후 같은 날 이미 완료한 요청은 반복하지 않는다. 소스 파일이 손상되면 이전 정상본을 읽는다. 현재·이전본 모두 손상되면 웹의 이전 정상 읽기 결과 또는 기존 묶음으로 돌아가며 손상된 수치로 성공을 꾸미지 않는다.

수동 수집도 `collect-festival-sources.cjs --dir <전용 경로> [--backfill] [--max-calls N]`을 사용하고 같은 커널 잠금·호출 상한을 적용한다. 새 경로에서 기존 호출 예산을 우회하려고 반복 실행하지 않는다. 운영 디렉터리에 후보 파일을 수동 덮어쓰지 않는다.

코드·출처 조건이 바뀌어 기존 투영 자료를 다시 만들어야 하면 해당 변경의 범위·호출 예산을 확인해 별도 후보를 검증한 뒤 교체한다. 비공식 데이터랩 차트 조회 주소는 이 작업자의 원천으로 추가하지 않는다.
