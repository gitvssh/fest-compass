# 두 목적의 기능 상세와 디자인 작업 입력

2026-09-23 사용자의 요청에 따라 **기능·기획을 구체화하고 화면 목표·와이어프레임·기본 배치까지 전달한다.**
최종 시각 디자인은 사용자가 진행한다. 기존 v5·v6 그림의 색·폰트·간격·컴포넌트 모양은 확정값이 아니다.
이 문서는 승인된 제품 방향 안의 상세 계약이다. 기존 축제의 구현·실행 검증·공개 상태는 [검증 기록](../../validation/34-existing-festival-journey.md)을 따른다.
새 축제 전용 흐름은 사용 가능하며 실행 결과는 [검증 기록35](../../validation/35-pickdday-new-festival.md)를 따른다. 실제 담당자 업무 인수는 후속이다.
[기획 기준](../../product/planning-principles.md) → 이 문서 → [화면 목표·배치](screens.md) →
[흐름](flows.md) 순서로 읽는다. 수치·집계·공급은 [데이터와 시각화](data-visualization.md)가 정본이다.

## 1. 두 사용 목적과 완료 경험

| 상황 | 사용자가 하려는 일 | 제품이 제공할 결과 | 사용자가 선택할 부분 |
|---|---|---|---|
| 기존 축제의 다음 회차 준비 | 이전 개최 시기의 지역 방문을 읽고 주변 자원과 다음 일정을 검토 | 회차별 실제 날짜의 방문 추이, 현재 자원 위치·특징, 후보 날짜의 공개 일정 | 어떤 관광객에게 무엇을 바꿀지, 장소·주제·개최일을 어떻게 정할지 |
| 새 축제 구상 | 지역의 활용 가능한 관광정보와 방문 시기·요일 특성을 살펴봄 | 현재 자원의 사실 비교, 관측연도별 방문 분포, 후보가 없어도 열리는 달력 | 방문할 이유·아이템·대상·최종 개최안 |

정보를 보고 차이를 이해하면 탐색은 끝낼 수 있다. 기획안 제출·두 대안 완성·이유·저장 버튼을 완료 조건으로 만들지 않는다.
성별·연령·소비·숙박, 축제 입장객, 행사장 수용력은 아직 확보·연결하지 않은 분석 항목으로 추가하지 않는다.

## 2. 첫 진입과 기존 축제 검색

SCR-FC-011은 목적 선택 뒤 각 목적에 필요한 조건만 연다. 기존 축제는 **축제 선택**, 새 축제는 **시군구 선택**이 시작 조건이다.

| 동작 | 제공할 결과·다음 행동 | 유지할 조건 |
|---|---|---|
| 기존 축제 선택 | 축제명 검색과 선택적 지역 필터 | 목적. 담당 지역 입력을 별도로 강제하지 않음 |
| 검색어 입력 후 검색 또는 지역만 적용 | 이름·지역·확인된 개최연도/일정이 있는 결과 목록 | 공백을 정리한 검색어와 지역. 아무 조건도 없으면 입력 화면 유지 |
| 동명 축제 발견 | 이름뿐 아니라 시군구·실제 개최일로 구별해 선택 | 축제의 식별자와 지역. 같은 이름을 자동 합치지 않음 |
| 확인된 과거 회차를 가진 축제 선택 | SCR-FC-008에서 최신 비교 가능한 두 회차, 하나뿐이면 한 회차 | 선택 축제. 미래 등록 회차를 과거 개최 사실로 대체하지 않음 |
| 현재 등록 정보만 있는 축제 선택 | 2026-09-26 대체(개발 중): SCR-FC-008에 그 시군구의 외지인 방문 흐름([§12](#12-고른-축제-모두의-공통-분석-흐름)). 이전 판(기록34)은 짧은 조회 상태와 주변 관광자원·개최 시기 이동 | 선택 축제·지역. 과거 개최일·방문 수를 추정해 생성하지 않음 |
| 결과 없음 | 검색어·지역 수정, 지역 관광정보 살펴보기 | 검색어·지역. 새 축제 등록이나 수기 이력 입력을 요구하지 않음 |
| 검색 일부 공급원 실패 | 성공한 결과는 유지하고 실패한 검색 영역만 다시 조회 | 같은 조건·출처별 완료 여부. 부분 결과를 전체 0건으로 표현하지 않음 |

**식별 기준:** 기존 보관 회차의 `festivalId`·`editionId`와 TourAPI의 `contentid`는 같은 식별자 체계가 아니다.
운영 자료에 근거 있는 연결표를 두고 확인된 관계만 하나의 축제에 묶는다. 표에는 양쪽 ID, 연결 근거·확인일·버전을 남긴다.
이름·연도·좌표가 비슷하다는 이유로 자동 연결하지 않는다. 연결이 확인되지 않은 현재 등록 항목은 별도 결과로 선택 가능하게 한다.
날짜가 수정되더라도 기존 과거 회차의 일정·출처를 덮지 않는다. 과거 자료는 회차별 원문을 유지한다.

검색은 보관 축제 목록과 현재 등록 검색 결과를 독립 조회해 합친다. 한 공급원의 실패가 다른 결과를 지우지 않는다.
현재 `filterEditions()`의 이름·지역 필터와 편집기의 TourAPI 키워드 검색은 재사용 기반이다.
기존 축제는 전국 키워드 검색과 선택적 지역 필터를 연결했다. 확인된 식별 연결 행은 아직 없어 보관 축제와 현재 등록 항목을 별도로 선택한다. 지역 조회를 전국 전체 목록으로 간주하지 않는다.
2026-09-26 갱신(개발 중): 검토된 연결 행을 추가해 같은 축제로 확인된 현재 등록·보관 축제를 한 결과로 합친다. 연결이 없는 결과는 계속 별도다. [§12](#12-고른-축제-모두의-공통-분석-흐름).
검색의 추가 페이지는 계속 불러올 수 있게 하고, 전체 확인 전에는 총건수나 검색 완료를 단정하지 않는다.

## 3. 조회 조건과 화면 사이의 전달

**적용 전 입력과 적용한 조건을 구분한다.** 검색·회차/연도·위치/반경·후보 날짜는 적용 버튼으로 조회를 바꾸며
잘못된 입력은 해당 필드에서 고친다. 자원 유형 선택과 달력 이전/다음 월은 바로 적용한다.
입력 중 취소하면 이전 결과가 유지된다. 적용 후에는 바뀐 제목과 그 조건의 로딩/결과를 함께 표시한다.

| 조건 | 같은 목적 안에서 화면 이동 | 대상 변경 | 새로고침·주소 재진입 |
|---|---|---|---|
| 목적·지역·축제 | 유지 | 사용자가 선택한 대상으로 변경 | 주소에 포함한 대상·유효 조건 복원 |
| 기존 회차·차트 기간 | 유지 | 다른 축제 선택 시 그 축제의 기본 회차로 초기화 | 유효 ID·기간이면 복원, 유효하지 않으면 선택 화면에서 수정 |
| 지역 관측연도 | 유지. SCR-FC-010/013 각각의 선택 | 새 축제의 지역 변경 시 유지, 없는 연도는 변경 행동 제공 | 주소의 연도 우선. 없는 자료를 다른 연도로 자동 치환하지 않음 |
| 달력 연월 | 유지 | 새 지역·다른 축제 선택에도 연월 유지, 일정은 새 지역으로 조회 | 주소의 연월, 없으면 현재 연월 |
| 유형·자원 함께 보기·상세·위치 기준점·반경 | 같은 대상에서 유지 | 유형만 유지. 대상 축제/지역 변경 시 나머지 해제 | 유형 복원, 임시 선택·기준점·반경은 초기화 |
| 후보 기간 0~2개 | 유지 | 새 축제 지역 변경 시 날짜 유지·일정 재조회. 다른 기존 축제 선택 시 후보 해제 | 임시 선택이므로 초기화 |
| 펼친 표·출처·선택 날짜·스크롤·초점 | 같은 탐색으로 뒤로 갈 때 복원 | 대상 변경 시 닫고 새 제목으로 초점 이동 | 접힌 기본 상태 |

주소에 복원할 값은 목적·대상 ID·지역·관측연도·회차/차트 기간·달력 연월·유형이다.
임시 자원·중심·후보 선택은 같은 탭의 탐색 상태로만 유지한다. 개인 기획안 저장 요청이나 영구 보관을 자동 실행하지 않는다.
일반 메뉴 이동에는 현재 선택을 유지하며 목적을 바꾸면 첫 진입으로 이동한다. 브라우저 뒤로가기는 이전 목적의 탐색 상태를 복원한다.
`/existing/search`와 세 `/existing/{id}` 화면을 구현했다. 주소의 ID는 출처 접두사를 포함한다. `/existing`은 검색으로 이동한다. 출처창 열림·모든 스크롤 위치의 완전 복원은 완료 범위에 포함하지 않는다.
새 축제는 `/new`에서 지역을 고르고 `/new/{지역코드}/resources·visits·timing`을 연다(사용 가능).
지역코드는 5자리 행정 코드이며 세종 `/new/36110`은 지역 목록의 `36110/36110` 행에 명시적으로 연결한다.
주소에는 지역과 `types`·`year`·`month`만 남긴다. 함께 보기·상세·기준점·반경·선택 월·후보 기간은 같은 탭의 임시 기억이며
새로고침하면 사라진다. 지역을 바꾸면 지역별 선택만 해제하고 관측연도·달력 연월·후보 기간·유형은 유지한다. 브라우저 저장소나 쓰기 요청은 쓰지 않는다.

기존 축제의 세 화면 안에서 지역은 해당 축제의 확인된 지역으로 고정한다. 다른 시군구 탐색은 별도 SCR-FC-001에서 열며
그 지역을 선택 축제의 소속 지역으로 바꾸지 않는다. `축제로 돌아가기`는 기존 축제·회차·조회 조건을 복원한다.
여러 시군구에 걸친 축제 자료를 한 지역의 방문값으로 임의 합산하지 않는다. 첫 구현은 확인된 축제·시군구 연결 단위로 제공한다.

### 관측과 달력의 연결

- 방문 차트에서 월을 고르면 **그 관측연도·월의 일별 수치 표**를 연다. 원래 월·요일 평균은 바뀌지 않는다.
  월 선택은 자료 상세 탐색이며 임의 관찰기간 재집계를 추가하는 기능이 아니다.
- 이어지는 행동명은 `2025년 10월 일정 보기`처럼 **실제 연월**을 포함한다. 클릭했을 때만 달력을 그 연월로 연다.
  과거 행사 목록을 복원할 수 없으면 해당 일정 영역의 상태를 제공한다. 올해 행사로 치환하지 않는다.
- 단순히 `개최 시기` 메뉴를 누르면 이전 달력 연월, 처음이면 현재 연월을 연다. 그래프의 10월을 보고 있었다는 이유로
  다음 해 10월이나 추천 날짜를 자동 선택하지 않는다. 특정 과거 연월 링크로 이동한 뒤 뒤로가면 직전 상태를 복원한다.
- 달력의 `과거 방문 흐름 보기`는 기존 축제에서는 같은 화면의 관측 영역, 새 축제에서는 SCR-FC-013을 연다(새 축제 구현의 행동명은 `지역 방문 흐름 보기`).
  방문 조회 연도는 그 화면의 이전 선택 또는 최근 완전연도다. 달력 연월·후보 날짜는 그대로 남는다.
- 자원 상세·함께 보기의 선택은 자원의 방문 통계가 아니다. 방문으로 이동하면 시군구 전체라는 제목과 단위가 유지된다.
  지역 방문값을 선택 시설의 방문자나 행사장 반경 방문자로 붙이지 않는다.

## 4. 세 핵심 기능의 상세 조작

### 회차와 방문 흐름 · SCR-FC-008/013

기존 축제는 기본 두 회차, 필요하면 **한 번에 최대 세 회차**를 비교한다. 회차를 하나만 골라도 그래프를 제공한다.
선택을 모두 해제한 입력은 적용하지 않고 회차 선택을 제공한다. 네 번째는 기존 회차를 해제해 교체한다.
행사 전후 기간은 기본 전 7일~종료 후 7일이며 회차별 실제 시작·종료일을 입력해 조정할 수 있다.
변경하는 것은 차트 관찰 범위다. 개최기간 평균의 분모·기간은 기존 개최일 그대로 유지한다.
개최일이 없는 회차는 목록에서 확인하되 행사 음영·개최 전후 기본 차트·개최기간 평균을 만들지 않는다.

두 목적 모두 `수치 표`에서 날짜·요일·원값을 읽고 `출처·산식`에서 공급자·집계 정의·자료 시점·분자/분모를 본다.
차트 선택은 표의 날짜/월 선택으로도 가능하다. 표를 닫으면 실행한 버튼으로 초점을 돌린다.
출처는 현재 보고 있는 지역·기간·자료 버전에 연결하고 시설 홈페이지와 데이터 원문을 별도 이름으로 제공한다.
전체 연도의 요일 평균이 없더라도 유효한 월·일별 값은 남긴다. 최근 완전연도가 전혀 없으면 연도 선택과 제공 기간을
보여주고 사용자가 부분연도를 직접 선택할 수 있게 한다. 부분연도를 완전연도처럼 기본 선택하지 않는다.

### 관광자원 · SCR-FC-009/012

기존 축제는 현재 주변 자원의 위치·특징을 읽고 새 축제는 선택적으로 최대 두 자원을 함께 본다.
상세 열기, 새 축제의 `함께 보기`, `지도 중심 선택`은 별도 행동이다.
지도 핀과 목록은 같은 원천 ID로 연결하며 지도 이동만으로 조회 조건을 바꾸지 않는다.
지도 중심을 적용하기 전 취소하면 이전 중심을 유지한다. 키보드 사용자는 목록의 좌표 있는 자원을 기준점으로 지정하거나
키보드로 이동 가능한 지도의 중심을 적용할 수 있다. 위치 권한·주소 추정 좌표는 요구하지 않는다.

유형 기본값은 관광지·문화시설 둘 다다. 유형을 모두 끄면 `관광지`·`문화시설` 선택을 제공하고 원천 자료 없음으로 표시하지 않는다.
반경을 적용해도 조회 경계는 선택 시군구다. 좌표 없는 자원은 **거리 미확인** 목록에 남기고 반경 안 결과 건수에서 제외한다.
반경 안 판정과 별도로 실제 반환 자원 건수·좌표 있는 건수의 분모를 유지한다. 기본 정렬은 이름순,
중심을 적용했을 때 사용자가 거리순을 선택할 수 있다. 동률은 이름·ID로 안정적으로 정렬한다.
다른 필터로 함께 보기 항목이 목록에서 가려져도 선택한 항목은 비교 영역에 남기고 해제할 수 있다.
필터를 적용하기 전의 동일 지역·자료유형 전체 재조회가 성공해 원천에서 빠진 항목을 확인한 경우는 이전 상세를 현재 정보로 재사용하지 않고 해당 선택을 해제한다.
실패로는 선택을 지우지 않는다. 지도 배경만 실패하면 같은 목록·상세에서 탐색한다.

### 개최 시기 · SCR-FC-010/014

기존 축제는 지역 월별 방문 흐름 뒤에 달력, 새 축제는 달력을 먼저 둔다. **두 목적 모두 후보 입력 전 달력을 볼 수 있다.**
연월·요일은 독립적으로 표시하고 공휴일·등록 행사는 각각의 자료 영역으로 갱신한다.
등록 행사는 `축제·행사 조회`로 조회한 뒤 연월/지역 변경 시 새 조건으로 다시 조회한다.
공휴일 범위와 등록 행사의 조회 완료 여부는 서로 대신하지 않는다.

`후보 기간 비교`에서 0→1→2개를 선택한다. 기간은 시작/종료 양끝 포함, 같은 날·월/연도 경계·두 후보의 일부 중첩을 허용한다.
완전히 같은 기간은 두 번째로 추가하지 않고 기존 후보로 이동한다. 세 번째는 기존 후보 해제 후 추가한다.
입력 오류로 다른 후보·달력 결과를 지우지 않는다. 월 밖 후보도 날짜 표시에 남기고 `달력에서 보기`로 시작 월을 연다.
후보별 시작·종료일·요일·총일수, 확인된 공휴일 날짜/이름, 조회된 행사의 원 일정/겹치는 구간을 같은 순서로 읽는다.
월·연도에 걸친 후보는 **전체 기간**의 일정을 조회해야 개수와 겹침을 집계한다. 보고 있는 달만 조회한 값을 후보 전체의 0건으로 쓰지 않는다.
취소가 확인된 행사·일정 미확인 항목은 겹침 집계에서 제외하고 상세의 원 상태는 유지한다. 공휴일이 여러 이름으로 같은 날짜에 있어도
휴일 일수는 중복 날짜를 한 번 센다. 토·일요일 수와 공휴일 수를 더해 중복된 '총 휴일'을 만들지 않는다.
등록 일정 겹침은 관측 사실이며 자동 경쟁/상생 판정이나 추천 점수를 붙이지 않는다.

## 5. 부족한 자료·실패에서의 배치와 회복

아래 상태 이름은 내부 설계용이다. 고객 화면에는 **그 자리의 결과·짧은 상태·가능한 행동**만 둔다.

| 상황 | 남기는 정보 | 바꾸는 자리와 실제 문구 초안 | 다음 행동 |
|---|---|---|---|
| 축제의 과거 회차 없음 | 축제·지역·세 메뉴 | 2026-09-26 대체(개발 중): 시군구 방문 흐름을 보여주고, 시군구 자료도 없을 때만 짧은 자료 없음. 이전 판은 방문 본문에 `이 축제의 지난 개최 기록이 없어요`. 축제 확인 중에는 이 문구를 쓰지 않음 | `주변 관광자원 보기`·`개최 시기 보기`·`다른 축제 찾기` |
| 회차는 있지만 개최일 미확인 | 확인된 회차·연도·원문·지역 | 해당 회차에 `개최일 미확인`. 행사 음영·개최 전후 비교·개최기간 평균은 생성하지 않음 | 다른 회차·주변 자원·개최 시기 |
| 선택 지역·연도의 방문 관측 없음 | 지역·연도·세 메뉴 | 차트 자리 한 곳에 `이 기간의 방문 자료가 없어요` | `연도 바꾸기`·자원/시기 이동 |
| 일부 날짜 누락 | 유효한 선·월별 막대와 수치 표 | 누락 구간을 비우고 표 `—`, 범례 `값 없음`. 불완전 평균 요약행은 생략 | 표·연도/회차 변경 |
| 좌표 또는 소개 없음 | 자원명·유형·실제 주소 | 좌표 없는 항목은 목록, 없는 소개는 상세 블록 생략. 비교 한쪽만 없으면 해당 칸 `—`·`정보 없음` | 다른 자원 열기·출처 |
| 지도 배경 실패 | 조회한 목록·선택 상세 | 지도 자리에 `지도를 불러오지 못했어요` | `지도 다시 열기`·목록 계속 탐색 |
| 자원/행사 조회 실패, 같은 조건 이전 성공본 없음 | 조건·다른 정상 영역 | 해당 자리에 `관광자원을 불러오지 못했어요` 또는 `행사 일정을 불러오지 못했어요` | `다시 불러오기`·조건 변경 |
| 같은 조건 갱신 실패, 이전 성공본 있음 | 당시 결과·실제 조회 시각 | 결과 옆에 `새 자료를 불러오지 못했어요` | `다시 불러오기`. 새 조건의 결과로 전용하지 않음 |
| 공휴일 확인 기간 밖 | 달력 날짜·요일·독립 행사 결과 | 휴일 자리 `이 기간의 공휴일 정보를 불러올 수 없어요` | 연월 변경. 연결이 없는 상태에 반복 재시도를 제안하지 않음 |
| 현재 조건의 전체 행사 조회 완료·0건 | 달력·조건·공휴일 | 행사 자리 `이 기간에 등록된 행사가 없어요` | 연월·기간 변경 |

정보가 없는 요약 카드를 반복하지 않는다. 다만 사용자가 직접 연 기능의 실패나 자료 없음은 숨기지 않는다.
과거·현재·후보, 실제 0·누락·실패는 제목·날짜·구성·표에서 구별한다. 내부 준비 등급·수집 한도·검수 배너를 추가하지 않는다.
기존 출처 귀속·적용 중인 법적 고지는 유지한다. 새 법적 요건을 이번 설계의 가정으로 만들지 않는다.

## 6. 기능 인수 시나리오와 구현 순서

| 순서 | 제공할 사용자 가치 | 완료를 확인할 시나리오 | 현재 상태 |
|---|---|---|---|
| 1. 공통 자료 계약·조회 | 같은 지역·기간의 믿을 수 있는 결과 | 일별 최신 행·0/누락·전체 페이지·키/시점·공급원별 실패를 구분 | 기존 축제용 조회(`/api/existing/*`) 사용 가능 · 검증 기록34. 새 축제용 `/api/new/visits`·`/api/new/resource-detail`은 사용 가능 |
| 2. 기존 축제 기본 여정 | 지난 방문→주변 자원→다음 일정 탐색 | 논산딸기 검색→2025/24 비교→박물관 위치→후보 하나 일정→뒤로가기, 기록 0회 | 사용 가능 — 구현·자동 인수 시험·공개 반영은 검증 기록34. 실무자 인수 미실시 |
| 3. 새 축제 기본 여정 | 지역만으로 자원·방문·달력 탐색 | 논산 선택→자원 두 곳 함께 보기→2025 월/요일→달력→후보 없이 종료 | 사용 가능 — 시나리오 TS-FC-010, 결과는 검증 기록35 |
| 4. 상태·복귀·자료 갱신 | 자료가 부족해도 탐색 지속 | 방문 없는 지역, 일부 날짜 누락, 행사 실패, 지도 실패, 늦은 응답, 다른 연도 링크와 복귀 | 기존 축제는 검증 기록34에서 확인. 새 축제는 사용 가능 |
| 5. 디자인 적용·실제 검수 | 완성된 화면으로 핵심 과업 수행 | 키보드·390px·확대·실제 조회/재시도·출처 열기. 실제 담당자 피드백 | 시각 디자인은 사용자 작업, 구현 후 검증 |

1~4의 **기능 단위로 동작과 자료를 먼저 연결**하고, 사용자 디자인에 맞춰 5를 적용할 수 있게 조회와 화면을 분리한다.
자원 소개는 핵심 목록을 막지 않는 보강 정보다. 새 축제 구현은 TourAPI `detailCommon2`에서 같은 ID·유형·지역을 확인한 소개만 쓴다.
Foundry 상세는 조사 자료로 남으며 운영 API에서 Foundry를 직접 임의 조회하지 않는다.
과거 방문이 없는 지역도 지역 자원·일정은 이용할 수 있어야 한다. 모든 지역의 자료 수집 완료를 출시의 전제 조건으로 만들지 않는다.
다만 어느 지역에서 어떤 기능이 실제 작동하는지는 출시 전 내부 인수 목록에서 확인한다.
핵심 기능 후의 관련 자료 검색·원문 연결은 아래 §8에서 구체화한다. AI 요약은 후속 검토이며 기사 수치 자동 반영은 첫 버전에서 제외한다.

이번 범위 안에 새 사용자 결정이 필요한 항목은 없다. 검색·기간·상태의 세부값은 수정 가능한 구현 기준 제안이다.
국가 전체 이력 확대나 신규 유료 데이터/AI 도입은 이번 계획에 포함하지 않았다(2026-09-23 당시).
2026-09-26 사용자 정정으로 공식 API 기반 전국 시군구 방문 이력은 [§12](#12-고른-축제-모두의-공통-분석-흐름)에서 범위에 들어왔다. 유료 데이터·AI는 여전히 제외다.

## 7. 디자인 작업자가 유지할 내용과 조정할 내용

**유지할 기능 의미:** 화면 목표, 주된 정보와 행동 순서, 대상·단위·실제 기간, 자유로운 메뉴 이동,
조회와 기록의 분리, 빈 결과·누락·실패의 구별, 목록/표/날짜 입력으로 가능한 접근, 복귀·조건 유지.

**디자인에서 조정 가능:** 색·폰트·크기·간격·그리드 비율·카드/표 스타일·탭 모양·상세 패널의 외형.
문구를 다듬을 때도 지표의 대상·연도·단위와 행동 결과는 바꾸지 않는다. 자료 규칙을 고객에게 설명하는 장문을 추가하지 않는다.
기존 v5·v6는 정상 상태의 참고 그림, v7은 부족한 자료와 실패를 다루는 기본 와이어프레임이다.
그림은 정적 배치 근거이며 클릭·검색·키보드 동작의 구현 증거가 아니다.

인수 기준은 [UC-FC-009](../1-analysis/usecases/UC-FC-009.md)와 [UC-FC-010](../1-analysis/usecases/UC-FC-010.md)에 둔다.
검수 결과와 미평가 항목은 [디자인 기준](design-system.md)에 기록한다.

## 8. 관련 자료 검색·원문 연결

사용자가 개발을 요청한 보조 기능이다. Claude Opus 5.5 설계 후 주 담당자가 아래 범위를 정리했다.
구현·검증 상태는 [기록36](../../validation/36-related-material-search.md)을 따른다.

**사용자·완료:** 지역 공무원이 데이터에서 생긴 질문을 당시 프로그램·운영 자료나 지역 관광사업·자원 활용 사례로
이어 확인한다. `관련 자료 검색` → 주제·연도·검색어 확인/수정 → DuckDuckGo 새 탭 → 검색 결과의 원문 순서다.
핵심 세 메뉴와 기존 출처는 유지한다. 앱이 검색 결과나 기사 수치를 가져오거나 요약하지 않는다.

| 위치 | 버튼을 제공할 때 | 검색어에 넣는 공개 정보 | 기본 연도 |
|---|---|---|---|
| 기존 축제 머리 | 축제명과 지역이 확인됐을 때 | 축제명 + 시도·시군구 + 선택한 연도/주제 | 방문 화면의 적용 회차가 정확히 하나면 해당 연도. 비교 중이거나 다른 화면이면 연도 전체 |
| 새 축제 머리 | 지역을 선택한 뒤 | 시도·시군구 + 주제 | 연도 입력 없음 |
| 새 축제 자원 상세 | 사용자가 상세를 연 자원 | 자원명 + 시도·시군구 + 주제 | 연도 입력 없음 |

지역명은 `region.name`의 전체 이름을 사용한다. 지역 자체를 검색할 때 같은 이름을 중복하지 않는다.
기존 축제의 연도 선택지는 확인된 회차 연도, 현재 등록 축제는 확인된 시작 연도만 쓴다. `editions` 주소가 없으면
확인된 기본 회차를 따른다. 알 수 없는 회차·중복 매개변수·일부만 유효한 주소는 연도를 추정하지 않는다.
관측연도, 달력 연월, 후보 날짜, 오늘 날짜를 축제 회차 연도로 대입하지 않는다.

**기본 배치:** 기존 `InfoDialog`와 보조 버튼 모양을 재사용하며 새 주 메뉴나 화면을 만들지 않는다.

```text
축제명 또는 지역명                         관련 자료 검색
과거 방문 / 관광자원 / 개최 시기
선택 조건과 공공데이터 차트·목록

[관련 자료 검색 창]
대상 이름 · 관련 자료 검색                       닫기
찾을 내용   전체 / 프로그램 / 운영 결과 / 보도자료
연도        연도 전체 / 확인된 연도들 (기존 축제만)
검색어      [공개 대상·지역·연도·주제, 수정 가능]
            기본 검색어로 (수정했을 때)
DuckDuckGo에서 검색 ↗
새 탭에서 검색 결과가 열려요.
```

새 축제 지역의 주제는 `관광사업`·`축제 사례`, 자원은 `행사`·`축제`다. 기본 주제는 `전체`다.
창을 열 때마다 현재 확인된 대상과 주소로 초기화한다. 연도/주제 변경은 검색어를 다시 구성한다.
직접 입력한 검색어는 창 안에만 두고 주소·브라우저 저장소·서버·분석 이벤트에 기록하지 않는다.
외부 검색을 실행할 때에는 표시된 검색어가 DuckDuckGo에 전달된다.

**상태·복구:** 첫 대상 조회 중·미확인·찾지 못함에는 검색 버튼이 없다. 같은 대상의 이전에 확인된 공개 정보가
남아 있고 갱신에 실패한 경우에는 기존 정보와 기존 갱신 실패 표시를 따르며 검색할 수 있다.
검색어가 공백뿐이면 링크 대신 `검색어를 입력해 주세요.`를 표시한다. 수정 후 `기본 검색어로`로 복구한다.
닫기·Esc 뒤 초점은 실행 버튼으로 돌아간다. 대상이 바뀌거나 사라지면 이전 검색창·입력도 해제한다.
외부 탭을 열어도 앱의 회차·달력·자원 선택은 바꾸지 않는다. 검색 결과 유무·외부 오류를 앱이 성공으로 표시하지 않는다.

**구현 경계:** `https://duckduckgo.com/`에 `q`만 URL 인코딩한 일반 링크를 사용한다. 새 탭,
`noopener noreferrer`, `referrerPolicy="no-referrer"`를 적용한다. 외부 폼 제출·결과 API·미리 가져오기를 추가하지 않는다.
현행 CSP와 공개 읽기 전용·기록 선택 원칙을 유지한다. 320/390px, 키보드·Enter/한글 조합·Esc,
잘못된 회차/대상 변경·빈 검색어·새 탭의 원래 화면 보존을 인수 대상으로 삼는다.
최종 시각 디자인은 후속이며 내부 절차 설명을 제품 화면에 옮기지 않는다.

## 9. 방문 구성과 지역 연간 추세

2026-09-24 추가 범위다. 임실N치즈축제와 임실군의 기간·대상이 확인된 보관 자료를 사용한다.
원자료 검토와 실행·공개 상태는 [검증 기록37](../../validation/37-visitor-context.md)을 따른다.
새 메뉴를 만들지 않고 기존 방문 화면의 보조 영역을 보강한다.

| 위치 | 화면 목표 | 기본 배치와 행동 |
|---|---|---|
| 기존 축제 SCR-FC-008 | 선택 회차마다 개최 행정동을 찾은 방문의 구성·규모 파악 | 기존 시군구 일별 차트 아래 독립 영역. `축제가 열린 읍·면·동의 방문 구성` → 회차별 날짜·일수 → 같은 절대 축의 구분별 일평균 막대 → 외지인 비율·값 → 기간 합계 표·출처·모든 개최연도 |
| 새 축제 SCR-FC-013 | 지역 관광 수요의 장기 추세와 특정 연도의 계절·요일을 이어 살펴보기 | 기존 월·요일 차트 아래 `임실군 연도별 방문 합계`. 2018~2025 외지인 연간 합계 → 월별로 볼 수 있는 연도 버튼 → 전체 수치 표·출처 |

```text
기존 축제 · 과거 방문 흐름
  적용 회차 / 임실군 전체 일별 차트·요약       (기존 기능)
  축제가 열린 읍·면·동의 방문 구성             (독립된 대상)
    2025년 · 개최 날짜 · 5일   [구분별 하루 평균 막대]
    2024년 · 개최 날짜 · 4일   [같은 축의 하루 평균 막대]
    기간 합계 표 보기 / 방문 구성 출처 보기 / 모든 개최연도 보기

새 축제 · 임실군 방문 흐름
  관측연도 / 월별·요일별 일평균                (기존 기능)
  임실군 연도별 방문 합계 · 2018~2025
    외지인 연간 추세 / 월별로 볼 연도 2023 · 2024 · 2025
    연도별 수치 표 보기 / 연간 추세 출처 보기
```

축제 구성은 현재 응답에서 확인한 적용 회차와만 결속한다. 차트 앞뒤 기간을 조정해도 원래 개최기간·일수는 바뀌지 않는다.
외지인 비율은 외지인÷전체, 일평균은 각 구분의 기간 합계÷개최일수다. 좁은 화면에서는 회차를 위아래로 배치한다.
외국인 값도 문자·표로 읽을 수 있게 하고 작은 막대가 보이지 않는다고 0으로 바꾸지 않는다.
자료가 없는 축제·회차, 취소·일수 불일치는 빈 카드 없이 해당 구성만 생략한다.

연간 추세는 월별 관측연도와 독립된 기간 개요다. 날짜별 자료가 완전한 연도만 월별 이동 버튼으로 제공하며,
선택 후 일치하는 월별 제목이 준비되면 초점을 옮긴다. 직접 들어온 2019년 주소에는 월·요일별 자료가 없다는 상태와
사용 가능한 연간 추세를 함께 유지한다. 다른 지역으로 바꾸면 임실 자료를 남기지 않는다.

연도·지역·단위·대상을 제목과 그룹으로 표현하고 출처·산식은 사용자가 열어 확인한다.
이 절의 이전 CSV에는 성·연령·거주지·목적지 선택 기간이 없다. 후속 §10은 별도로 확보한 공식 2025년 원본만 사용한다.
거주지와 실제 방문 경로는 이번에도 제공하지 않는다.

## 10. 방문자 특성과 관광자원 연결

임실N치즈축제 2025년 회차에 [새 공식 원자료](../../research/imported/datalab-imsil-2025/README.md)를 연결한다.
실행·공개 상태는 [검증 기록38](../../validation/38-visitor-profile.md), 인수 기준은 [TS-FC-013](../3-testing/scenarios/TS-FC-013.md)을 따른다.
이 절과 기록38·TS-FC-013은 **2025년 한 회차**를 연결한 기록으로 보존한다. 그중 "2025년 회차가 적용됐을 때만 제공"하는
표시 조건만 [§11](#11-두-회차-방문자-특성-비교)이 대체한다. 한 회차를 볼 때의 제목·차트·표·출처·관광자원 연결은 이 절 그대로다.

| 위치 | 사용자 목표 | 정보와 행동 |
|---|---|---|
| SCR-FC-008 방문 구성 아래 | 과거 방문자의 성·연령 분포를 프로그램 검토에 참고 | 2025년 방문자 특성 → 개최기간·성수면 → 성·연령별 비율. 8개 연령대의 남성·여성을 같은 축의 가로 막대와 숫자로 표시 |
| 같은 영역의 목적지 목록 | 축제기간에 검색된 장소를 관광 연계 후보로 살펴보기 | 목적지 검색순위 → 외지인(기본)·현지인·전체 → 원문 순위·장소·주소·분류 → 확인된 장소의 관광자원에서 보기 |
| SCR-FC-009 관광자원 상세 | 선택한 과거 목적지의 현재 관광정보 확인 | 같은 지역의 최신 조회에 해당 식별자가 있으면 상세 선택·초점 이동. 실패 시 재시도, 현재 목록에서 사라졌으면 짧은 결과 안내와 목록 유지 |

```text
과거 방문 흐름
  기존 회차 비교 / 개최 행정동 방문 구성
  2025년 방문자 특성
    2025.10.8–10.12 · 임실군 성수면
    성·연령별 비율 · 내국인 전체 중 비율(%)
      연령대   남성 [가로 막대] 값   여성 [가로 막대] 값
    축제 기간 목적지 검색순위
      [외지인] [현지인] [전체]
      순위 · 장소 · 분류 · 주소    [관광자원에서 보기]
    수치 표 / 출처
                         ↓
주변 관광자원 · 현재 목록에서 해당 장소 선택
```

2025년 회차가 적용됐을 때만 이 영역을 제공한다. 다른 연도·지역·늦은 이전 응답에 남기지 않는다.
차트 앞뒤 구간을 바꿔도 관측기간은 10월 8~12일로 유지한다. 비율에 전체 인원 수를 곱해 방문 인원을 만들지 않는다.
순위는 내비게이션 검색 기준이며 음식점·숙박을 제외한다. 실제 방문·함께 이동한 코스·추천 점수로 바꾸지 않는다.

관광자원 연결은 직접 확인한 세 곳만 제공한다. 확인되지 않은 행에는 연결 버튼만 생략한다.
새로 누른 장소가 이전 선택보다 우선하며 성공한 현재 목록을 기다린다. 이동용 주소 값은 한 번 처리하고 제거한다.
기존 회차·표시 기간은 뒤로가기에 유지한다. 출처 창은 필요한 정의와 원문·수집 시점만 담고 내부 검사 절차는 넣지 않는다.
고정 글자 크기·줄바꿈·공통 축·문자 레이블을 유지하고 320px에서도 값과 조작이 겹치지 않게 한다.
기존 세 메뉴와 기록 없는 흐름을 유지하며 최종 시각 디자인은 사용자 후속 작업이다.

## 11. 두 회차 방문자 특성 비교

**상태: 사용 가능 — 원자료·구현·공개 검증 완료.** 사용자가 승인한 임실N치즈축제 이전 회차 연결과 두 회차 비교다.
구현·실행·공개 결과는 [검증 기록39](../../validation/39-edition-profile-comparison.md), 인수 기준은
[TS-FC-014](../3-testing/scenarios/TS-FC-014.md)를 따른다. §10의 한 회차 표시는 유지하고 세 해의 회차 선택에 맞춰 비교한다.

**사용자 목표:** 축제 담당자가 두 해의 방문자 성·연령 구성과 축제 기간 목적지 검색순위가 어떻게 달라졌는지 읽고,
다음 회차의 프로그램 대상이나 함께 소개할 관광자원을 검토하는 데 참고한다. 비교는 선택 사항이며 기록·저장·선택 이유를 요구하지 않는다.
제품은 차이를 숫자로 보여줄 뿐 원인·효과·추천을 판정하지 않는다.

**기본 배치:** 기존 SCR-FC-008 방문 화면 안의 같은 자리다. 새 메뉴·선택기·안내 배너를 만들지 않는다.

그림의 성·연령 값과 목적지 순위는 보존한 원응답의 실제 값(외지인 구분)이다. 방문 구성의 `○`는 자리 표시다.
연령대는 0~9세부터 70세 이상까지 오름차순이다. 좁은 화면에서는 연령대마다 남성·여성 각각의 두 해 막대를 위아래로 둔다.
목적지는 장소별 카드에 이름·주소를 먼저 두고, 두 해 순위·변화를 세 칸으로 나란히 표시한다.
페이지 전체 가로 넘침 없이 320px에서 값과 버튼이 겹치지 않아야 한다.

### 표 1. 회차별 확인 자료

| 회차 | 개최기간 | 일수 | 관측 지역 | 성·연령 | 목적지 검색순위 | 현재 관광자원 연결 |
|---|---|---|---|---|---|---|
| 2023년 | 10.6–10.9 | 4일 | 임실군 성수면 | 8개 연령대 × 남녀 | 외지인·현지인·전체 각 6곳 | 임실치즈테마파크·상이암 |
| 2024년 | 10.3–10.6 | 4일 | 임실군 성수면 | 8개 연령대 × 남녀 | 외지인·현지인·전체 각 7곳 | 임실치즈테마파크·상이암 |
| 2025년 | 10.8–10.12 | 5일 | 임실군 성수면 | 8개 연령대 × 남녀 | 외지인·현지인·전체 각 7곳 | 임실치즈테마파크·상이암·소충사 |

세 회차 모두 같은 공식 공개 화면·같은 성수면 코드로 조회했다. 개최일수가 다르므로 순위·비율은 각 회차의 기간 안에서만 읽는다.
장소는 원문 식별자로만 같은 곳으로 본다. 같은 식별자의 이름이 바뀐 경우(성수산자연휴양림 → 2025년 성수산왕의숲자연휴양림)
비교 표에는 최신 이름을 쓴다. 이름이 비슷하다는 이유로 다른 식별자를 합치지 않는다.

### 표 2. 선택한 회차와 표시

| 적용 회차 중 확인된 방문자 특성 | 화면 |
|---|---|
| 없음 | 방문자 특성 영역을 만들지 않는다. 빈 카드나 사유 문구 없음 |
| 하나 | §10의 한 회차 표시 그대로. 제목 `2025년 방문자 특성`처럼 그 연도 |
| 둘 | 오래된 해 → 최근 해 순서의 비교. 제목 `방문자 특성 · 2024년과 2025년` |
| 셋 | 확인된 회차 중 최근 두 회차를 오래된 해 → 최근 해 순서로 비교. 제목은 비교하는 두 연도 그대로(예: `방문자 특성 · 2024년과 2025년`). 제목 옆에 짧은 `최근 두 회차` 표시를 둘 수 있음(선택) |

선택하지 않은 회차의 자료는 비교에 넣지 않는다. 한 회차의 자료만 검증에 실패하면 그 회차만 빠지고 남은 확인 회차 수로 위 규칙을 적용한다.
고객 화면에는 자료가 빠진 이유나 내부 규칙을 쓰지 않는다. 회차 선택기의 선택 개수·기본값은 기존 동작을 바꾸지 않는다.
회차 선택기는 지금처럼 최대 세 회차를 받으며(`MAX_EDITIONS = 3`) 세 회차 선택을 그대로 유지한다.
`최근 두 회차` 표시는 지금 비교 중인 회차를 알리는 짧은 상태 표시이며, 제한을 설명하거나 안내 배너를 두지 않는다.
다른 두 회차를 비교하려면 위쪽 기존 회차 선택에서 그 두 회차를 고른다.

### 표 3. 성·연령 비교

| 항목 | 규칙 |
|---|---|
| 값 | 각 해의 원문 비율(내국인 전체 중 %, 소수 한 자리). 인원으로 환산하지 않음 |
| 막대 | 연령대 × 성별마다 두 해 막대. 두 해 모두 같은 축. 막대마다 `2024`·`2025` 연도 글자와 값을 함께 표시 |
| 변화 | 수치 표에서만 %p로 표시. 원문 한 자리 값 × 10을 정수로 반올림해 뺀 뒤 10으로 나눔(최근 − 이전). 예: 4.4 → 4.6 = `+0.2%p` |
| 표기 | 증가 `+0.2%p`, 감소 `−0.3%p`, 같음 `0.0%p`. 색은 보조이며 부호·문자로 읽힘 |
| 수치 표 | 열: 연령대·성별·이전 해·최근 해·차이(%p). 남성·여성 모두 |

차트에는 설명 없는 증감 숫자만 따로 두지 않는다. 두 해 값을 모두 보인 뒤 차이는 표에서 읽는다.

### 표 4. 목적지 검색순위 비교

| 항목 | 규칙 |
|---|---|
| 행 | 두 해 목록의 합집합. 최근 해 순위 순서, 이어서 이전 해에만 있는 장소를 이전 순위 순서로 |
| 같은 장소 | 원문 장소 식별자가 같을 때만. 이름·주소·분류는 최근 해 값 |
| 순위 열 | 각 해 `N위`. 그해 목록에 없으면 `—`. 없는 순위를 0이나 `신규`로 쓰지 않음 |
| 변화 | 이전 순위 − 최근 순위. 양수 `N위 상승`, 음수 `N위 하락`, 0 `같음`, 한쪽이 `—`이면 `—`. 아이콘만으로 표시하지 않음 |
| 관광자원 연결 | 직접 확인한 장소만 `관광자원에서 보기`. 두 해 중 최근 연결 정보 사용. 연결 없는 행은 버튼만 생략하고 행은 유지 |
| 구분 | 외지인(기본)·현지인·전체 전환은 기존과 같음. 전환해도 두 해가 함께 바뀜 |

순위는 내비게이션 검색 기준이며 실제 방문량·이동 경로·추천이 아니다. 기존 관광자원 상세 이동, 실패 후 재시도,
돌아왔을 때 누른 장소로의 초점 복귀는 한 회차 표시와 같다.

### 표 5. 방문 구성 두 회차 요약

| 항목 | 규칙 |
|---|---|
| 표시 조건 | 기존 `축제가 열린 읍·면·동의 방문 구성`에 두 회차 이상이 표시될 때 막대 아래에 한 줄 요약을 추가 |
| 비교 대상 | 표시된 회차 중 값이 있는 최근 두 회차. 세 회차가 표시돼도 기존 막대·표의 세 행은 그대로 두고 요약만 최근 두 회차로 계산. 제목은 `두 회차 비교 · 2024년 → 2025년`처럼 비교하는 두 연도 그대로 |
| 하루 평균 변화 | 화면에 표시된 한 자리 값끼리 뺌. `○.○명/일 → ○.○명/일 (+○.○명/일)` |
| 외지인 비율 변화 | 표시된 한 자리 % 값끼리 뺌. `○.○% → ○.○% (+○.○%p)` |
| 유지 | 기존 구분별 막대·기간 합계 표·출처·모든 개최연도 링크는 그대로 |
| 대상 구분 | 이 영역은 외국인을 포함한 방문 구성이고, 방문자 특성의 성·연령은 내국인 기준이다. 두 영역의 분모를 섞지 않음 |

요약은 두 회차 값의 차이만 말한다. `효과`, `증가 원인`, `입장객` 같은 표현을 쓰지 않는다.

**출처 창:** 해마다 조회 기간·지역·수집 날짜를 나란히 두고, `%p는 두 해 비율의 차이`, `—는 그해 순위에 없음`을 한 줄씩 설명한다.
원본 경로·해시·조회 인원·검색 건수·내부 검사 절차는 넣지 않는다.

**유지할 것:** 한 회차 표시의 제목·차트·표·출처·관광자원 연결, 기존 회차 선택과 차트 기간, 뒤로가기 복원, 세 메뉴, 기록 없는 탐색.
최종 색·간격·막대 모양은 사용자의 디자인 작업에서 정한다.

## 12. 고른 축제 모두의 공통 분석 흐름

**상태: 개발 진행 중.** 구현·시험·공개 확인은 끝나지 않았고 검증 기록은 주 담당자가 갱신한다.
화면 목표·기본 배치·원천 확인 사실은 [통합 설계 18](../../design/18-unified-festival-analysis.md), 인수 기준은
[TS-FC-015](../3-testing/scenarios/TS-FC-015.md)를 따른다.

**사용자 목표:** 담당자가 검색해 고른 어떤 등록 축제든 축제별 코드 추가 없이 방문 흐름·관광자원·개최 시기로 들어가
그 시군구의 방문 계절성을 읽고 다음 회차를 검토한다. 기록·저장은 필요 없다.

| 항목 | 규칙 |
|---|---|
| 방문 기본 | 검토된 과거 회차가 없는 현재 등록 축제는 확인된 `festival.region`의 시군구 외지인 방문을 `/api/existing/monthly`로 보여준다. 월별 일평균 → 고른 월의 일별 선(값 없는 날은 끊음)과 수치 표. 제목 `<시군구> 외지인 방문 흐름` |
| 연도·월 기억 | 방문 전용 조건으로 주소·탭 기억에 둔다. 개최 시기의 달력 연월·후보, 다른 화면의 선택을 덮지 않는다 |
| 등록 일정 | 현재 축제 응답의 선택 필드 `periods`(id·start·end·collectedAt)에 있는 날짜만 `등록된 일정`으로 표시하고 그 연월 바로가기를 둔다. 같은 콘텐츠 ID·같은 지역의 실제 관측만 쓰고 시작 연도별 최신 하나. 개최 확정·회차로 부르지 않음 |
| 쓰지 않는 표시 | 선택 월을 개최기간으로 표시, 전년 같은 날짜의 가짜 기간, 부분 월로 계산한 기간 평균, 방문 인원을 축제 입장객·효과로 표시 |
| 과거 회차 연결 | 검토된 연결표의 `linkedArchiveId`가 있으면 현재 축제의 이름·경로를 유지한 채 방문 본문에 기존 회차 비교를 같은 화면에서 표시. 보관 축제 응답·기존 주소와 시험 자료는 바꾸지 않음 |
| 검색 결과 | 같은 연결로 확인된 현재·보관 결과만 현재 카드 하나로 합치고 과거 개최연도를 덧붙인다. 이름만 같은 결과는 별도. 원천별 실패 재시도·페이지 이어보기·기억한 선택 유지 |
| 확인 중 | 축제 확인이 끝나기 전에는 확인 중 상태만. `지난 개최 기록이 없어요`를 먼저 보이지 않음 |
| 자료 없음·실패 | 시군구 자료 없음은 짧은 상태 + 관광자원·개최 시기 이동. 방문 조회 실패는 그 자리만 재시도 |
| 보조 자료 | 임실 방문 구성·방문자 특성·회차 비교(§9~11)는 해당 축제에만. 다른 축제에 빈 영역·사유 문구 없음 |

**원천:** 방문은 공식 `DataLabService/locgoRegnVisitrDDList`의 전국 시군구 일별 자료, 등록 일정은 TourAPI `searchFestival2` 전국 조회다.
하루 한 번 수집기가 보관하며 공개 웹은 쓰지 않는다. 코드 대응·호출 한도·실패 시 보존 규칙은 설계 18 §5~6을 따른다.
데이터랩 공개 화면의 비공식 차트 조회는 자동 수집 기반으로 쓰지 않는다.
