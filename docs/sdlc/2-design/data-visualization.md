### 결과 단위와 자료 시점

조회 결과는 화면이 요청한 지역·지표/자료유형·기간·식별자·언어와 자료 버전에 결속한다.
관광자원 지도·목록·개수, 방문 차트·표·평균은 각자 같은 결과 묶음을 사용한다. 조건이 다른 늦은 성공·오류는 모두 무시한다.
지도 기준점·반경으로 파생한 거리·목록은 현재 조회 묶음에 다시 계산하며 지역 방문의 공간 범위를 반경으로 바꾸지 않는다.

- **관측기간:** 숫자가 다루는 실제 날짜. 항상 제목·축·표에 표시한다.
- **수정/공표 시각:** 공급자가 제공한 경우만 출처에서 표시한다. 수집 시각으로 대신 만들지 않는다.
- **수집 시각:** 원 자료를 받아 저장한 시각. 목록과 소개, 공휴일과 행사 등 독립 자료는 각각 추적한다.
- **조회 시각:** 보관본/캐시를 읽은 시각. 최근 조회했다는 이유로 원 자료를 최신이라고 표시하지 않는다.

새 결과는 검증이 완료된 묶음으로 바꾸며, 부분 페이지나 서로 다른 버전의 차트와 표를 섞지 않는다.
같은 조건 갱신 실패로 직전 성공본을 보여줄 때는 그 자료의 조회 시각과 짧은 갱신 실패·재시도만 해당 영역에 둔다.
다른 조건의 성공본을 대신 표시하지 않는다. 새 원천에서 삭제·취소를 확인한 항목을 과거 성공본으로 되살리지 않는다.
상세의 이전 성공본도 동일 자원·언어일 때만 사용할 수 있다. 필터로 목록에서 가려진 자원의 선택·상세는 유지한다.
필터를 적용하기 전의 동일 지역·자료유형 전체를 완전히 재조회해 원천 부재를 확인하거나 제공처의 삭제를 확인한 경우만 재사용하지 않는다.
오래된 상세를 새로운 목록 시각으로 표시하지 않으며, 같은 자원의 이전 상세임을 그 상세의 자료 시각으로 구분한다.

상태는 결과 있음·정상 0건·일부 관측 누락·확인 범위 밖·조회 실패를 구별한다. 내부 상태 코드와 원천 오류 원문은
고객 응답으로 그대로 내보내지 않는다. 사용자 문구와 복구는 [기능 상세 §5](functional-spec.md)를 따른다.
등록 행사의 후보 기간 집계는 모든 월·연도를 포함한 전체 기간, 공휴일 0일 판정은 해당 기간의 완전한 달력 범위를 전제로 한다.

### SCR-FC-012 · 지역 관광자원

축제명·주제·목표 관광객·방문 이유·행사장 입력 없이 지역 전체에서 시작한다.
현재 정보의 지도와 목록을 먼저 보여 주고, 자원 이름을 선택하면 제공된 사실을 읽을 수 있다.
기본 유형은 관광지·문화시설이며, 검증하지 않은 분류 코드로 테마 이름이나 추천 순위를 만들지 않는다.
최대 두 자원의 `함께 보기`는 이름·유형·주소·위치·실제 소개를 같은 순서로 읽는 비교다.
자원을 고르지 않거나 하나만 골라도 탐색할 수 있다. 자원 선택은 축제 소재·행사장 확정이나 계획 저장이 아니다.

거리는 SCR-FC-009의 명시적 중심점·시군구 조회 경계·직선거리 규칙을 재사용한다.
자원 상세를 열거나 함께 보기 대상으로 골랐다는 이유만으로 중심점을 바꾸지 않는다.
별도 `지도 중심 선택`을 열어 기준점을 적용했을 때만 거리·반경을 적용한다.
대관·운영시간·수용력·주차·접근성·축제 적합도는 확인한 필드가 없으면 항목을 만들지 않는다.
목록에 소개가 없는 자원도 이름·유형·주소로 탐색할 수 있으며 빈 소개 카드를 나열하지 않는다.

시안의 세 POI 이름·좌표는 아래 SCR-FC-009 표본과 같다. 추가 소개는 2026-09-22
`dw_schema` 후 `silver.tourapi_detail_common`의 한국어·동일 ID를 직접 읽어 대조했다.
query hash `4d106b0686261609fd398c5eaef7fb3c521f3d294f85dd6e1479c570a3e0f7d5`, 2행·잘림 없음이다.

| 자원 | 시안에서 쓰는 원문 기반 짧은 소개 | 소개 수집일(KST) |
|---|---|---|
| 백제군사박물관 | 백제의 군사문화를 주제로 유물과 당시 군사 모습을 전시하는 박물관. | 2026-04-13 |

위 문장은 시안 편집용 발췌·축약이며 AI 요약 기능의 도입이 아니다. 실제 연결은 제공된 소개를 안전하게

### SCR-FC-013 · 연도별 지역 방문 흐름

축제 회차·D0·개최 구간 없이 선택 지역의 최근 완전한 연도를 기본으로 삼는다. 현재 논산은 2025년이다.
v6 첫 버전의 방문 조회 입력은 연도 선택이다. 임의 시작·종료일로 집계 기간을 바꾸는 기능은 후속 범위다.
월별 그래프와 요일별 그래프는 모두 `논산시 외지인 방문`이라는 대상, 실제 연도, `일평균 · 명/일 · 추정`을 가진다.
요일은 월~일 달력 순서로 배치하며 높은 값 순위나 추천 개최 요일로 바꾸지 않는다.
공휴일·기존 축제 기간을 포함한 관측 자료이므로 `평소`, `축제 없이도`, `예상 관람객`이라는 이름을 붙이지 않는다.

일별 값 선택·0/결측·월 전체 관측·정수 반올림은 아래 공통 지표 계약을 그대로 적용한다.
요일 w의 일평균은 **선택 연도에 해당 요일인 날짜의 V(d) 합 ÷ 실제 날짜 수 N(w)**다.
선택 연도 전체가 유효할 때만 연도 기준 요일 평균을 계산한다. 그래프만 숨기는 것이 아니라 수치 표의 합·평균도 만들지 않는다. 항상 52로 나누지 않는다.
윤년·연도 시작 요일에 따라 분모가 달라진다. 후속 기간 조회에서도 N(w)=0이면 항목을 0으로 채우지 않는다.
불완전한 연도를 직접 요청하면 유효한 월·일별 자료를 유지하되 연도 기준 요일 평균은 생성하지 않고
해당 영역에 `이 연도의 요일별 흐름을 불러올 수 없어요`와 `연도 바꾸기`를 제공한다.
관측 자체가 없는 지역에서도 관광자원·개최 시기 이동과 지역 변경은 계속 가능하다.

### SCR-FC-014 · 개최 달력과 선택적 기간 비교

후보 입력 전에도 조회 연월의 달력·공휴일·등록 행사 영역을 읽을 수 있다. 기본 조회는 현재 연월이며
시안은 월 이동 후인 **2026년 10월**을 표현한다. 날짜를 골라 기간 하나를 살펴보거나 두 개까지 비교한다.
기간 두 개·행사명·개최 이유·저장은 요구하지 않는다. 미래 방문 수치나 과거값을 미래 날짜 위에 넣지 않는다.
과거 방문 흐름은 SCR-FC-013 이동으로 확인하며 달력의 실제 연월과 별개로 보존한다.

시안의 10월 3일 개천절·5일 개천절 대체공휴일·9일 한글날은
[보관 공휴일](../../../apps/web/data/nonsan-calendar.json)의 `annual-2026`과 대조했다.
원천은 한국천문연구원 [2026년 월력요항](https://www.kasi.re.kr/kor/post/newsMaterial/32031),
공표일 2025-06-30, 보관일 2026-09-07이다. 보관본의 확인 범위는 2026년 1~12월이다.
2027년 자료는 2월 1일까지이므로 그 뒤를 공휴일 0건으로 채우지 않는다.

Foundry에서 확인한 강경젓갈축제 행은 **2025-10-23~26**이다. 해당 자료를 2026년 10월 일정으로 복사하지 않는다.
원천 조회 hash `c13ee60b546d2240b157fedf81fe5024001f91ea74063170968e5ebb01242c96`의
기존 지역 코드34/3 행은 3건이며 2026-04-04 수집본이다. 이 부분 목록은 미래 일정이 없다는 증거가 아니다.
시안은 `축제·행사 조회` 행동을 두며 확인하지 않은 행사 개수·겹침을 표시하지 않는다.
운영 조회가 지역·기간·전체 페이지 범위를 정상 완료했을 때만 `이 기간에 등록된 행사가 없어요`를 쓴다.
이는 모든 현장 행사 부재나 경쟁 부재를 뜻하지 않는다. 실패·일부 응답을 0으로 취급하지 않는 계약은 두 목적에 공통이다.

### 새 축제의 조건 변경과 화면 간 연결

지역은 세 과업에 공통이다. 변경하면 이전 지역 자원 ID·중심점·반경·선택 상세를 해제하고 해당 지역 자료를 다시 조회한다.
사용자가 고른 방문 연도·달력 연월·후보 날짜는 유지하되 새 지역의 제공 여부를 다시 판정한다.
새 지역에 해당 연도 자료가 없으면 이전 지역 그래프나 다른 연도로 조용히 대체하지 않는다.
자원 유형 등 지역에 종속되지 않은 조건은 유지할 수 있다. 뒤늦은 응답은 조회 키가 현재 조건과 같을 때만 반영한다.
화면 이동·뒤로가기에서 조회 조건을 복원하되 다른 지역의 상세가 남지 않도록 한다.
자원과 기간 선택은 현재 탐색을 위한 상태이며 저장·로그인·기획 기록을 요구하지 않는다.

## 기존 축제 · v5에서 이어지는 계약

2026-09-22 확정된 세 핵심 기능을 구체화한 **개발 전 설계**다. [화면설계](screens.md)의
SCR-FC-008~011, [사용자 흐름](flows.md), [UC-FC-009](../1-analysis/usecases/UC-FC-009.md)에 적용한다.
이 절부터 `이전 v3 설계` 앞까지가 새 흐름의 지표·표현 계약이다. 아래 v3는 이전 화면의 이력이며
자료 확보 행렬·보류 사유를 그래프보다 먼저 보게 하는 순서를 새 화면에 적용하지 않는다.
전략적 답변·메모·저장은 선택 사항이고 뉴스 수치·AI 요약은 이번 범위에 넣지 않는다.

현행 코드는 [현재 상태](../../review/2026-09-current-state.md), 데이터 보유·수집 경계는
[데이터 현황](../../research/2026-09-data-inventory.md)이 정본이다. 여기의 가공 규칙·새 배치는
구현 완료가 아니다. 기존 자료를 써도 새 계산·동선·화면의 개발과 인수 검증은 필요하다.
이후 SCR-FC-008~010의 집계·화면을 구현하고 자동 인수 시험·공개 확인을 마쳤다([검증 기록34](../../validation/34-existing-festival-journey.md)).

앱의 지역 코드 연결은 `lib/region/model.ts`, 조회는 `lib/region/service.ts`, 회차·일정 계산은
`lib/comparison/model.ts`를 확인했다. 다른 공급자의 동일 명칭·다른 코드만으로 합치지 않는다.
Foundry의 전국 관광정보·행사 자료는 추가 연결 후보이며 현재 화면이 이미 소비하는 데이터로 쓰지 않는다.
연관 관광지 API의 식별자와 TourAPI contentid 대응은 미검증이므로 이번 지도에 자동 혼합하지 않는다.
성별·연령·소비·숙박·이동시간·축제 입장객은 이번 자료에서 파생하지 않는다.

## SCR-FC-008 · 과거 방문 흐름의 지표 계약

### 선택과 기본 비교

- 축제·지역 선택 뒤 일정과 같은 정의의 방문 자료가 있는 최신 두 회차를 기본 비교한다.
  현재 논산 예시는 **2025/2024**다. 한 회차만 있으면 하나를 넓게 표시한다. 이 규칙은 최신 축제 개최연도 판정이 아니다.
- 차트 범위는 각 회차의 **시작 7일 전부터 종료 7일 후까지, 양끝 포함**이다.
  2023은 19일, 2024/2025는 각각 18일이다. 기존 `relativePoints()`의 D−7~D+7 15점을 그대로 쓰지 않는다.
- 회차마다 같은 폭의 하루 간격과 동일한 Y축 범위·단위를 쓴다. 실제 날짜·요일을 가진 작은 그래프를 나란히 배치하고
  모바일에서는 같은 순서로 쌓는다. 길이가 다르면 공통 최대 일수 폭을 사용하고 짧은 회차의 끝은 비워 둔다.
  행사 구간은 연한 음영과 `개최기간` 직접 라벨로 표시한다. D0 상대일 겹쳐 그리기는 기본값에서 제외한다.
- 비교 카드의 제목은 `2025년 · 3.27–3.30 · 목–일 4일`, 차트 공통 제목은 `논산시 외지인 방문 추이`,
  단위는 `명/일 · 추정`이다. `축제 방문객`, `축제 효과`, `성공률`로 바꾸지 않는다.
- 증감률·순위·최적 회차는 기본 요약에 넣지 않는다. 2023의 요일 구성이 다른 점은 기간·요일·일별 곡선으로 읽힌다.
  같은 요일만 추출하거나 비개최 기준선을 추가하는 기능은 별도 정의 후 확장한다.

### 산식과 결측

날짜 d의 값 V(d)는 같은 시군구·방문 유형·측정 방법의 유효한 비음수 관측값이다.
동일 날짜에 보관본이 여럿이면 현재 `selectHistory()`처럼 수집 시각 순 최신 행을 선택한다.
최신 행이 누락이면 이전 값을 조용히 되살리지 않는다. 원천·snapshotId·수집일은 점 단위로 추적한다.

| 지표 | 계산·분모 | 표시 조건·숫자 표현 |
|---|---|---|
| 일별 외지인 방문 추정 | 원천의 해당 날짜 값 | 실제 0은 0, 누락은 null. 점 사이 누락은 선을 끊고 표에서 `—` |
| 개최기간 일평균 | 시작~종료 모든 날 V(d)의 합 ÷ 개최 일수 N | N일 모두 유효할 때만 요약행 생성. 부분 기간을 온전한 평균으로 표시하지 않음 |
| 방문이 가장 많았던 날 | 같은 기간의 max(V(d)) + 실제 날짜·요일 | N일 모두 유효할 때만 생성. 동률은 모든 날짜를 상세에서 제공. 수용인원·동시 체류인원으로 해석하지 않음 |
| 월별 일평균 | 해당 월 모든 날 V(d)의 합 ÷ 달력 일수 | 한 달 전체가 유효할 때만 막대 생성. `월별 일평균 · 명/일 · 추정`으로 명명. 월 고유 방문객 아님 |

요약 값은 계산 마지막에 가장 가까운 정수로 반올림하고 `추정` 단위를 유지한다.
수치 표에는 원천 일별 값(소수 포함)을 그대로, 계산 상세에는 분자·분모와 평균 소수 최대 3자리를 제공한다.
개최기간 안에 누락이 있는 회차도 일별 선·관측 범위는 유지하지만 개최기간 평균·최대일 요약행은 만들지 않는다.
전후 비교 구간에만 누락이 있고 개최기간은 완전하면 개최기간 요약은 유지한다.
사용자가 평균 항목을 직접 요청했다면 그 위치에 `이 회차의 평균을 계산할 수 없어요`와 `회차 바꾸기`를 제공한다.
차트의 조회 기간을 좁히더라도 개최기간 요약의 분모는 임의로 바꾸지 않는다.
차트 빈 구간은 표의 `—`와 `값 없음` 범례로 설명한다. 내부 품질 코드·수집 규약은 고객 문구로 전달하지 않는다.

## SCR-FC-009 · 관광자원과 위치 연결

지역은 선택 축제에서 이어받고, 초기 범위는 `논산시 전체`다. 유형은 `관광지` / `문화시설`을 선택한다.
자원은 **현재 등록 정보**이므로 과거 회차를 바꿔도 당시 관광자원인 것처럼 목록을 바꾸지 않는다.
제목 옆의 조회 시점·현재 정보 표시와 출처 상세가 시점을 담당한다.

과거 논산 회차에는 좌표가 없다. 행사장으로 간주한 임의 중심점이나 현재 행사장의 자동 소급 연결을 만들지 않는다.
`지도 중심 선택`은 지도 클릭/키보드·주소 검색으로 기준점을 명시한 뒤 적용하는 조회 조건이다.
주소 검색 공급자는 이번에 확정하지 않으며 첫 구현은 기존 지역 선택과 지도·좌표 입력으로도 완결할 수 있다.
중심점 선택 뒤 유효 좌표로 구면 직선거리(km)를 계산하고 거리순·반경을 적용할 수 있다.
거리 라벨은 `선택한 위치에서 직선거리 약 3.2km`처럼 쓴다. 운전 시간·추천 이동 경로는 생성하지 않는다.
거리 숫자는 예시 문구일 뿐 실제 자원의 대조값이 아니다.

지도와 목록은 같은 contentid로 선택을 공유한다. 좌표가 없으면 지도 핀만 생략하고 이름·주소가 있는 목록을 유지한다.
상세는 이름→유형/주소→제공된 위치·원문 순서다. 영업시간·입장료·대관·수용력은 실제 상세 응답을 연결한 경우에만 추가한다.
현재 `/api/regions`가 제공하지 않는 상세 필드를 시안에서 실제 값처럼 채우지 않는다.
앱 로컬 보관본에는 관광자원 POI 응답이 없어 Foundry의 실제 자료 세 건을 v5 배치 표본으로 사용했다.

음식점·숙박·주차장과 연관 관광지 순위는 식별자·신선도·가공 연결을 검증한 뒤 확장한다.

## SCR-FC-010 · 관측된 계절성과 앞으로의 후보 일정

처음에는 선택 지역의 최근 **완전한 연도** 월별 일평균과 실제 연월 달력을 제공한다. 후보 기간 입력은 선택적으로 연다.
현재 논산은 2025년이다. 2026년 자료 끝에 누락이 있으므로 최신 연도라는 이유만으로 완전한 연도로 선택하지 않는다.
상단에 실제 관측 연도를 유지하고 다른 연도 선택을 제공한다. 미래 후보 기간을 입력해도 과거 그래프의 연도를 바꾸지 않는다.

후보는 우선 두 개까지 나란히 비교한다. 두 개 작성이 화면 조회의 전제는 아니다.
시작·종료 날짜만 조회 조건이고, 이유·목표 관광객·기획명은 입력받지 않는다.
기간 오류는 해당 필드에서 수정하고 다른 후보·정상 자료는 유지한다.
윤일 등 대응 날짜가 없는 과거 연도는 자동으로 다른 날로 바꾸지 않고 해당 과거 기간을 직접 고른다.

| 정보 그룹 | 보여주는 것 | 비교 기준 |
|---|---|---|
| 과거 지역 방문 | 관측 연도별 월별 일평균, 선택한 실제 과거 기간의 일별 값 | 앞 절의 지역·지표·단위·완전 기간 규칙. 미래 날짜 위에 과거값을 투영하지 않음 |
| 후보 A / 후보 B | 날짜·요일·일수와 입력한 기간 | 실제 날짜를 사용. 같은 길이가 아니어도 달력으로 차이를 그대로 표시 |
| 공휴일 | 후보 기간에 들어오는 휴일의 날짜·이름 | 조회 범위를 완전히 확인한 목록만 0건을 판정. 확인 범위 밖을 평일로 채우지 않음 |
| 같은 기간 등록 행사 | 선택한 지역의 등록 행사·원래 일정·겹친 구간 | 양끝 포함 `max(0, min(end)-max(start)+1일)`, 취소/일정 미확인 제외. 조회 완료한 결과만 집계 |

현재 `nonsan-calendar.json`의 공휴일 목록은 2023~2026과 2027년 초 일부만 있다.
2027년 3~4월 시안을 위해 휴일이나 등록 행사를 만들어 넣지 않는다. 일반 공휴일 조회를 연결하고
기간 전체의 제공 여부를 확인하는 작업이 필요하다. 논산 연구 달력의 연1회·최대5일 제한은 일반 후보 달력에 옮기지 않는다.
등록 행사의 개수·겹침을 경쟁 강도·방문 감소 예측으로 바꾸지 않는다.
성수기·최적 날짜·흥행 점수는 이 자료만으로 산출하지 않는다.

v5 그림의 월별 막대는 실제 논산 2025 자료(365/365일)다. 정수 반올림 대조값은
1~12월 순서로 **43,616 / 42,853 / 51,620 / 47,321 / 53,956 / 47,779 /
44,142 / 49,821 / 45,212 / 55,910 / 48,046 / 42,882명/일**이다.
입력 후 상태 그림의 2027년 두 후보 날짜는 입력 예시이며 미래 방문값·공휴일·등록 행사 실조회 결과가 아니다.

## 공통 표시·복구·출처

- 처음 보이는 본문은 해당 과업의 차트·지도·목록이다. 지표가 전혀 없는 카드·배지·자료 등급 표를 나열하지 않는다.
  사용자가 요청한 자료를 불러오지 못한 경우는 숨기지 않고 해당 영역에 한 문장과 복구 행동을 둔다.
- `수치 표`와 `출처·산식`은 차트 옆의 보조 행동이다. 후자는 공급자·지역·기간·단위·수집일·snapshotId·원문·집계를 제공한다.
  대상·기간·단위는 펼치기 전에도 읽혀야 한다. 상세 출처가 법적 고지의 대체물은 아니다.
- 지도 배경의 기존 제공자 귀속 표기는 지도 가까이에 유지한다. 적용 중인 필수 고지는 임의 삭제하지 않는다.
  이번에 새 법적 고지나 전역 경고 배너를 만들지는 않는다.
- 로딩은 해당 영역의 진행 상태, 실패는 `불러오지 못했어요` + `다시 불러오기`, 조건에 맞는 결과 없음은
  `선택한 조건의 등록 결과가 없어요` + `조건 바꾸기`로 전달한다. 실패를 0건으로 표시하지 않는다.
- 회차·지역이 바뀌면 이전 그래프를 새 제목 밑에 그대로 두지 않는다. 최신 조회 조건과 응답이 일치할 때만 교체한다.
  같은 조건 재조회 실패로 이전 결과를 유지할 때는 그 결과의 조회 시점을 남기고 실패·재시도를 함께 표시한다.
- 키보드·보조기술·작은 화면의 표현과 문구 길이는 [디자인 시스템](design-system.md)을 따른다.

## 사용자 결정과 구현 상태

2026-09-22 확정 방향은 [두 목적별 진입과 선택적 기록](../../product/planning-principles.md)이다.
아래 전국지도 시작은 지역 탐색 화면의 기존 시안이며 새 제품 첫 화면 전체를 확정하지 않는다.
실제 기능은 [현행 점검](../../review/2026-09-current-state.md), 사용 가능한 자료·단위·연결 제한은
[데이터 현황](../../research/2026-09-data-inventory.md)을 따른다.
출처·결측·비교 가능성·표 대체 원칙은 재사용하되 목적별 정보 우선순위·차트 상세는 후속 설계한다.

2026-09-08 사용자는 첫 화면을 전국지도로 시작하고 지역을 좁혀 가며, 비교에는 그래프·파이차트 등 시각자료를 적극 사용하도록 요청했다.
이번 문서는 그 요청을 반영한 개발 전 설계다. 지자체 담당자의 자기 지역 정보 수요는 유지하되, 첫 화면을 특정 지자체로 고정하지 않는다.
실제 자료의 확인 범위는 [과거 자료 점검](../../research/2026-09-historical-comparison-review.md), 객체·계산 정본은 [자료 계약](../1-analysis/data-contract.md)을 따른다.

## 전국 → 시도 → 시군구

1. 기본 진입은 제주와 도서 지역을 포함한 전국지도다. 위치 권한·담당 지역·사업 정보 입력을 요구하지 않는다.
2. 시도 클릭 또는 동일한 지역 목록 선택으로 좁히고, 시군구를 선택하면 그 지역의 자원·등록 축제·방문 추세를 표시한다.
3. 상단 경로 `전국 > 충청남도 > 논산시`에서 상위 지역으로 돌아갈 수 있다. 지역 변경에도 연도·기간·자료 종류는 유지한다.
4. '우리 지역 바로가기'와 '이전 탐색 이어보기'는 사용자가 누를 때만 이동한다. 일반 재방문도 전국이 기본이며 명시적 회차 링크는 해당 상세로 진입한다.
5. 전국·시도에서는 지역 요약과 자료 보유 상태, 확대 후에는 확인된 좌표의 자원·행사 마커를 제시한다. 배경 지도 범위와 통계 확보 범위는 별개다.
6. 지도 이동은 표시 범위만 변경한다. '이 영역 조회'를 누른 경우에만 공간 필터를 적용하고 해제할 수 있게 한다. 계층 지역 선택은 즉시 공통 필터에 반영한다.

지도 경계는 제공처·기준 연도·좌표계·지역 코드 대응을 확인한 범위에서 사용한다. 시안의 해안선은 개념도이며 실제 경계 자료가 아니다.
`미확보`, `부분 확보`, `조회 오류`, `확인된 0`은 글자·무늬로 구분한다. 자료 없음에 수치 0을 넣거나 논산 값을 다른 지역에 재사용하지 않는다.
시군구 통계를 합쳐 전국 또는 시도 고유 방문객을 만들지 않는다. 상위 지역은 그 집계 수준의 원자료를 따로 확인한 경우에만 표시한다.
첫 페이지만 조회한 축제 건수는 전국 총수가 아니다. 전 페이지 조회·중복 정리·조회 기간과 완료 여부를 표시한 뒤에도 '조회된 등록 축제'로 명명한다.

## 비교 화면의 읽는 순서

SCR-FC-002는 필터·회차 선택 → 자료 확보 현황 → 주요 그래프 → 선택 수치·출처 → 근거 담기 순서다.
2~3개 회차를 선택한다. 예산이 없더라도 회차를 제외하지 않고 방문 추세 등 비교 가능한 지표를 남긴다.
숫자를 못 그리는 이유는 해당 차트 자리에서 설명한다. 비교 보류 자료는 원문 카드로 읽을 수 있다.

| 질문 | 기본 시각자료 | 표시·비교 기준 |
|---|---|---|
| 개최 전후 방문 흐름이 어땠나? | 일별 선그래프 | 같은 지역·방문 유형·단위·방법. 실제 날짜 또는 행사 시작일 D0 기준. 행사 구간과 개최 일수 표시 |

## 차트 공통 계약

- 선그래프는 실제 값으로 좌표를 계산한다. 결측 사이를 이어 그리거나 보간하지 않는다. 비교하는 선들은 공통 축·단위를 쓰고 서로 다른 방문 유형을 한 합계로 만들지 않는다.
- 막대는 0부터 시작한다. 이중 축·3D·면적 왜곡은 사용하지 않는다. 각 회차는 색 외에 선 모양·기호·직접 라벨로 식별한다.
- 파이·도넛은 최대 5개 주요 항목과 '기타'를 제안한다. 기타의 세부 항목을 펼칠 수 있어야 하며 단위·금액·분모·비율을 함께 제공한다.
- 미산정·겹친 범위·알 수 없는 분모가 있으면 전체 구성비를 그리지 않는다. 부분 소계는 금액 막대와 '총액 미확정'으로 표시한다. 총액 0이면 빈 상태와 0원 표를 제공한다.
- 확정/예정 재원은 다른 상태다. 계획 재원 구성을 그려도 확보액은 별도 표시한다. 재원과 지출을 한 파이에 합치지 않는다.
- 현지인·외지인·외국인은 제공·집계 방법을 확인하지 않은 채 파이의 한 전체로 묶지 않는다. 지역별 방문 추정치를 전국 방문객 점유율 파이로 만들지 않는다.
- 모든 차트에서 지표명·단위·지역·실제 기간·원자료 확인일·자료 성격을 보인다. '수치 표 보기'와 '출처·비교 기준 보기'는 항상 접근할 수 있다.
- 선택한 점·막대·기간을 '기획 근거에 담기'로 저장한다. 마우스 드래그와 같은 일을 키보드로 날짜/항목 선택해 수행할 수 있어야 한다.
- 저장 대상은 그림만이 아니라 선택 당시 값·누락 상태·필터·회차·원문 참조·집계 방식·선택 범위다. 새 조회 결과는 기존 근거를 덮지 않는다.
- 390px에서는 그래프를 한 열로 배치한다. 축 라벨을 줄여도 원래 날짜·값·단위는 표에서 확인한다. hover 전용 설명을 만들지 않는다.
- 출력에는 선택된 그래프와 대응 표·출처·기간·미확인 상태를 함께 담는다. 흑백에서도 구분 가능해야 한다.

## 임실 2025년 성·연령과 목적지

연령대별 100% 정규화나 인원 환산은 하지 않는다. 같은 축의 남녀 가로 막대·값·수치 표를 제공한다.

세 곳만 직접 확인한 TourAPI 식별자로 연결한다. 관광자원 도착 화면은 현재 자료이고 과거 방문을 입증하지 않는다.
축제별 거주지는 확보되지 않았으며 임실군 전체 외지인 거주지를 대신 넣지 않는다.
DTO에는 원본 경로·해시·내부 규약을 넣지 않는다. [기능 상세 §10](functional-spec.md#10-방문자-특성과-관광자원-연결), [검증 기록38](../../validation/38-visitor-profile.md).
