# 기획 기간과 겹치는 등록 행사 찾기

## 목적과 확인한 문제

담당자가 올해 기획 기간을 정하고 주변 지자체의 등록 행사 일정을 비교한다. 지역은 직접 1~3곳 선택하며 거리순 검색은 후속이다.

기존 앱은 행사 시작일이 조회 시작일보다 빠르면 응답 전체를 거부했다. 실제 공개 API를 대조하니 공주 국가유산야행(2026-09-04~06)이 9월 5~6일 조회에도 정상 반환됐다. 앱에서는 `행사 시작일 조건과 응답이 달라 표시를 보류했습니다`로 조회 실패했다.

[한국관광공사 공식 명세](https://www.data.go.kr/data/15101578/openapi.do)는 `searchFestival2`의 두 날짜와 행사별 시작·종료 필드를 제공하지만 비교 연산을 상세히 정의하지 않는다. **실제 응답 6개를 대조해 기간 겹침 동작을 확인**했다. 공주 시작 전/시작일/중간일/종료일/종료 후와 논산 3월 27~28일에 각각 확인했다. 이를 모든 데이터의 완전성 보증으로 확대하지 않는다.

## 화면·자료 계약

1. 새 현재 조회는 `기간 겹침`이 기본이다. `기간 안 시작`을 선택하면 동일 API 응답 중 시작일이 기획 기간 안인 행사만 남긴다. 기존 보관 근거의 시작일 검색 방식은 그대로 읽는다.
2. 실제 등록 일정이 `행사 시작≤기획 종료 && 행사 종료≥기획 시작`을 만족하면 응답으로 허용한다. 경계 날짜를 포함하며 잘못된 날짜·역순 일정·비겹침·타지역 응답은 계속 거부한다.
3. API에 기획 기간을 그대로 보낸다. 불필요한 과거 기간 확대나 추가 API 호출을 도입하지 않는다. 최대 366일·지역 1~3곳·지역 600건·캐시·호출 제한은 유지한다.
4. 기획 기간 안의 겹치는 구간을 공통 날짜 축의 막대로 표시한다. 원래 행사 전체 일정과 겹친 구간·일수를 문자로 함께 표시한다. 그림은 결과 순서 최대 20건이며 전체 결과 목록은 유지한다.
5. API 전체 조회 건수와 이름·검색 방식으로 남긴 결과 수를 구분한다. 실제 개최·취소·변경·제공처 미등록은 미확인이다. 취소로 보관한 회차는 겹침 일수 판단을 보류한다.
6. 지역별 실패·600건 초과·중복/페이지 누락은 기존 전체 조회 실패 규칙을 유지한다. 성공한 다른 지역은 남기고 실패 지역을 0건으로 표시하지 않는다.
7. 회차 선택 당시 검색 방식·기획 기간을 복사한다. 이후 다른 조건으로 조회해도 근거 보기·파일 보관/가져오기·기획 후보의 근거 상세에서 당시 일정 그림과 조건을 유지한다. 이전 v1 근거와 과거 회차는 그대로 읽는다.
8. 지역 지도에도 동일 응답 검사를 적용하며 설명을 `이 기간과 겹치는 일정`으로 맞춘다. 방문 통계나 예측 모델의 정의는 바꾸지 않는다.

## 인수 시나리오

- 10월 3~5일 기획: 9월 시작·10월 3일 종료 행사는 포함하고 10월 2일 종료 행사는 제외한다. 10월 5일 시작은 포함하고 6일 시작은 제외한다.
- 검색 방식을 바꾸면 기간 안 시작 결과만 남는다. 결과 수와 제공처 건수를 구분한다.
- 겹침 검색→회차 선택→다른 검색→근거 보관→파일 재조회와 기획 근거 상세에서 원래 기간·일정·출처가 유지된다.
- 366일 경계·윤년·잘못된 날짜·늦은 응답·지역 실패·0건·모바일 390px를 headless로 검사한다. 가상 행사 시험과 실제 공주 표본 조회를 구분한다.

실제 실행·게시 결과는 [29번 검증 기록](../../validation/29-current-festival-overlap.md)에 기록한다. 전국 과거 자료·거리 검색·실무자 인수는 후속이다.
