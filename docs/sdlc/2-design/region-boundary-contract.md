# 행정경계와 관광조회 지역 연결 기준

## 제공할 기능과 현재 상태

담당자는 전국에서 자기 지자체의 영역을 확인하고 그 안팎의 관광자료를 비교해야 한다.
**경계 원본은 확보했지만, 현재 조회 지역과 연결하는 기능은 개발 필요**다.
이번 점검은 원본·연도·좌표계와 코드 충돌을 확인한 결과이며, 경계 표시 기능의 배포 완료가 아니다.
현재 [관광지도](https://kto.damecasol.com/regions)의 지역 선택·자원 조회·근거 보관은 계속 사용 가능하다.

## 확보한 공식 자료

| 항목 | 확인 내용 |
|---|---|
| 원본 | [국가데이터처 SGIS 행정구역 통계 및 경계](https://www.data.go.kr/data/15129688/fileData.do) |
| 경계 기준일 | 2025-06-30. 실제 시도·시군구 DBF 모든 행에 `20250630` 확인 |
| 동봉 통계 | 2024년 통계. 경계 연도와 다르며 이번에 관광 지표로 사용하지 않음 |
| 경계 수 | 시도 17개, 시군구 252개. 관광공사 조회 단위 수와 다름 |
| 좌표계·문자 | PRJ의 UTM-K/GRS80, EPSG:5179. CPG의 UTF-8 확인 |
| 형식 | SHP·SHX·DBF·PRJ·CPG, 코드집·이용안내 포함 ZIP |
| 이용 조건 | 포털 표시: 무료·이용허락범위 제한 없음. 별도 인증키 없이 정상 다운로드 성공 |
| 확인 범위 | ZIP 식별 해시, 구성 파일 해시, DBF 기준일·코드 유일성·명칭 대조. 형상 유효성·좌표 변환·단순화·면적 비교는 미실행 |

[SGIS 자료제공 안내](https://link.mods.go.kr/view/pss/openDataIntrcn)는 기준 연도 6월 30일 경계와 EPSG:5179를 설명한다.
[SGIS 이용 안내](https://sgis.mods.go.kr/view/pss/dataProvdIntrcn)의 통계용 행정구역과 관광공사 법정동 조회 코드를 같은 코드로 취급하지 않는다.
ZIP의 격자 매핑표는 관광공사 코드 연계표가 아니다. ‘코드집’이라는 파일명만으로 연계 검증을 완료 처리하지 않는다.

## 실제 대조 결과

2026-09-08 수집한 관광공사 `ldongCode2` 원문 269개 조회 단위를 보존하고 **같은 시도명 안에서만** 시군구명을 대조했다.
명칭 일치는 검토 후보를 찾는 규칙이며 과거·현재 영역이 같다는 증명이 아니다.

| 분류 | 조회 단위 수 | 의미·다음 조치 |
|---|---:|---|
| 명칭 일치 후보 | 221 | 논산 등. 공식 기준시점별 코드 연계와 구역 변경 여부 확인 필요 |
| 일반시 합성 후보 | 12 | 수원·성남·안양·부천·안산·고양·용인·청주·천안·포항·창원·전주. 하위 행정구 경계를 합칠 수 있는지 확인 필요 |
| 미연결 | 36 | 전남광주통합특별시 27, 인천의 새 구 4, 화성의 행정구 4, 세종 명칭 차이 1 |
| 검증된 지도 연결 | 0 | 위 후보를 공식 연계나 공간 동일성 검증 완료로 표시하지 않음 |

숫자 코드를 그대로 붙이면 잘못 연결된다. 관광공사 시도 `26`은 부산이고 SGIS 시도 `26`은 울산이다.
논산은 관광공사 `(44, 230)`과 SGIS `34060`이 명칭 일치 후보다.
세종의 관광공사 `(36110, 36110)`은 원문 그대로 유지하며, SGIS 시도 `29`·시군구 `29010`·명칭 `세종시`와 별도 대조한다.

인천의 제물포구·영종구·서해구·검단구와 화성의 만세구·효행구·병점구·동탄구는 **현재 보관된 조회 목록의 명칭**이다.
2025년 경계를 분할·이름 변경하는 근거로 이 목록만 사용하지 않는다. 전남광주 조회 영역도 구 광주·전남 경계를 임의 합성하지 않는다.
이 목록은 행정 개편의 법적 효력·시행일 확인을 대신하지 않는다.

## 연결 자료 정의

공식 연계표 확보 뒤 아래 정보를 별도로 보관한다. 관광공사 조회 키와 과거 경계 코드는 서로 덮어쓰지 않는다.

| 정보 | 용도 |
|---|---|
| 관광공사 시도·시군구 코드, 목록 수집일 | 실제 API 조회·자료 보관 식별자 |
| 제공자·경계 기준일·경계 코드 목록 | 화면에 그릴 원본 식별자 |
| 연계 종류 | 일대일 / 여러 경계 합성 / 구역 변경 / 미연결 |
| 연계 근거 URL·기준일·확인일 | 공식 연계표와 개편 근거 추적 |
| 상태·표시 허용 | 미확인 / 코드 확인 / 공간 검증 완료. 코드와 공간 검증이 모두 끝나야 표시 허용 |
| 변환·단순화 버전과 원본 해시 | 같은 지도 재현·다음 원본 갱신 비교 |

지도 자료는 EPSG:4326 경도·위도 순서로 변환한다. 시도/시군구별 필요한 자료만 제공하고 원본 대용량 SHP를 브라우저 번들에 넣지 않는다.
단순화 뒤 섬·구멍·공유 경계·형상 유효성과 면적 오차를 검증한다. 일반시와 행정구를 함께 합산해 이중 계산하지 않는다.
구역 변경 전후 통계의 합산·배분은 별도 지표별 계약이 필요하다.

## 화면 적용안 — 구현 전 기준

1. 전국→시도→시군구 선택 흐름과 목록 대체를 유지한다. 검증된 경계만 클릭 가능한 영역으로 표시한다.
2. 범례에 `경계 기준: 2025-06-30 · SGIS`와 현재 조회 목록의 기준을 따로 표시한다.
3. 미연결 지역은 `현재 조회 지역에 맞는 경계 확인 중`을 표시하고 목록·관광자료 조회를 제공한다. 옛 경계를 현재 영역처럼 강조하지 않는다.
4. 과거 경계를 참고용으로 제공한다면 명시적으로 켠 별도 레이어로 표시하고 현재 지역 선택이나 자원 포함 판정에 사용하지 않는다.
5. 지도 이동·사각 영역 필터·시군구 통계의 기준을 구분한다. 경계 안 관광자원 수가 행사 입장객 수나 지역 방문 통계가 되지 않는다.
6. 경계를 사용한 근거에는 제공자·경계 기준일·연계 버전을 보관한다. 기존 근거에 경계 정보를 소급 삽입하지 않는다.

이는 SCR-FC-001·FR-REG-1~5의 후속 적용 기준이다. 기존 화면의 인수 완료 표시는 이번 경계 기능에 재사용하지 않는다.

## 다음 구현 순서와 완료 기준

1. 공식 기준시점별 통계분류·법정구역 연계표를 확보하고 논산·서울·세종·일반시·구역 변경 사례를 대조한다. 근거가 없는 지역은 미연결로 둔다.
2. 검증된 표본 경계부터 좌표 변환·단순화·공유 경계·섬 보존을 검사하고 크기 제한을 정한다.
3. 시도/시군구 레이어·기준일·미연결 안내·근거 보관을 구현한다.
4. 코드 충돌·이중 집계 방지·미연결 대체·전국 복귀·390px·기존 근거 호환을 headless로 검증한다. 배경 요청은 가상 타일로 대체한다.

재실행 명령과 증거는 [27번 원본 대조 기록](../../validation/27-region-boundary-audit.md)을 따른다.
