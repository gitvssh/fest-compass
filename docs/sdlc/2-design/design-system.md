# 화면의 위계와 공통 표현

## 거르기 칩·쌓은 막대 · 2026-10-04

[설계25](../../design/25-festival-discovery.md)에서 더한 표현이다. 구현·검증은 [검수47](../../validation/47-festival-discovery.md)에 있다.

- **거르기 칩:** 결과를 바로 거르는 단추는 `region-button` 알약(아이콘 + 짧은 이름 + 작은 덧말)이며 `aria-pressed`로 고른 상태를 알린다
  (파랑 테두리·옅은 파랑 바탕). 묶음은 `role="group"`과 보이는 라벨을 가진다. 누르면 바로 적용하고 초점은 칩에 남긴다 — 그래서
  결과가 화면 밖일 수 있는 곳에는 칩 옆에 `N건 보기`(결과 제목으로 초점 이동)를 둔다. 입력 상자와 함께 쓰면 입력 중인 값도 함께 적용한다.
- **분류 표식:** 등록 분류는 회색 바탕 작은 알약(아이콘 13px + 이름). 같은 목록에서 모두 같은 값이면 되풀이하지 않는다.
- **소개 글 표시:** 체험(손·청록)·어린이·가족(아기·주황)·무료(표·파랑) 알약. 거르기 칩은 거르기 칩 규칙에 표시 수(작은 숫자)를 붙인다.
  근거는 `소개 글 근거` 팝업 한 곳에서 보이며 표시만으로 운영을 단정하지 않는다(주최 측 안내 확인 문구).
- **구분 단추(세그먼트):** 화면 전체의 보기 기준(연도·순위 기준)은 테두리 상자 안 단추 묶음, 고른 것은 남색 바탕 흰 글씨.
  639px 이하에서는 같은 너비 칸(연도 6칸 한 줄, 기준 2×2)으로 놓아 감김으로 줄이 들쭉날쭉하지 않게 한다.
- **화면 아래 고정 카드:** 동의 배너·소개 영상 안내처럼 화면 아래에 고정된 카드는 떠 있는 동안 바닥글 아래에 자기 높이만큼 자리를 더한다(`useBottomDock`).
  끝까지 내리면 바닥글의 단추·링크가 카드 위로 올라와 가려지지 않는다. 두 카드는 동시에 뜨지 않는다.
- **쌓은 막대(방문 규모 화면과 함께 ADR-0003으로 제거, 다시 쓸 때의 규칙):** 집단마다 한 색을 고정하고(현지인 청록·외지인 파랑·외국인 주황) 범례를 막대 위에 한 번 둔다. 막대는 꾸밈이며 줄마다 같은 비율을 글자로 적는다.
  표시 배지(외지인 중심·현지인 중심·고르게)는 아이콘(가방·집·저울) + 이름이고, 범례에서 각 배지의 뜻을 한 줄로 붙인다.

## 시각 안내·팝업·초점 · 2026-10-03

사용자가 길잡이 구현(설계24 묶음 1)과 함께 두 방향을 정했다: 문장·설명을 줄이고 아이콘·이미지·시각 도구로 바로 알 수 있게 할 것,
팝업과 초점 상태를 정제할 것. 이 절이 아래 이전 기준보다 우선한다. 구현·검증은 [검수46](../../validation/46-planning-guide.md)에 있다.

- **아이콘:** `lucide-react`(ISC) 한 벌만 쓴다. 뜻 하나에 아이콘 하나로 고정한다 — 방문 흐름=꺾은선, 관광자원=위치 핀,
  개최 시기=달력, 모아 보기=클립보드, 목표=과녁, 알 수 없는 것=가린 눈, 질문=말풍선 물음표, 확인할 일의 법령 근거=관공서·담당 부서=건물·기획 참고=전구,
  준비 단계 일곱 개는 각자 하나([아이콘 대응표](../../../apps/web/components/guide/icons.tsx)). 아이콘은 꾸밈(`aria-hidden`)이고 뜻은 옆 글이 맡는다.
  아이콘만 있는 단추는 `닫기`(이름 있는 둥근 단추) 하나다.
- **안내는 띠 하나·짧은 줄:** 목표 한 줄, 알 수 없는 것 명사구 두 개 이하, 질문 두 개 이하(각 28자 이하). 길이와 금지 표현은 [단위 시험](../../../apps/web/lib/guide/guide.test.ts)이 지킨다.
  순서는 번호 대신 화살표·`이어서` 단추로, 판단 항목·얻는 것·협의할 곳은 아이콘 달린 짧은 항목으로 보인다.
- **모달(`.ui-dialog`):** 흰 표면·모서리20px·옅은 테두리·깊은 그림자, 배경은 남색55% 막(흐림 없음 — 소프트웨어 렌더링에서 한 프레임40~175ms가 걸려 닫힘이 늦어짐을 측정).
  머리글은 색 배지 아이콘·제목·44px 둥근 `닫기`이고 아래에 구분선, 본문만 스크롤한다. Esc·닫기·배경 누름(누름이 배경에서 시작하고 끝날 때만)으로 닫고 여는 단추로 초점을 돌린다.
  열릴 때 짧게 떠오르며(움직임 줄이기 설정 시 없음) 639px 이하에서는 아래에서 올라오는 시트다. 소개 영상 창은 같은 머리글의 넓은 변형(`.ui-dialog-wide`)이다.
- **펼침 메뉴:** 모서리16px·같은 그림자 토큰(`--shadow-pop`)·짧은 등장, 항목은 아이콘+이름, 초점은 항목 안쪽 고리.
- **초점:** 조작 요소는 2px 파랑 고리·2px 간격. 입력칸·선택 상자·글 상자는 고리 대신 파랑 테두리와 안쪽 3px 빛(이웃 라벨을 덮지 않음).
  라벨에 든 확인란·선택지는 라벨(칩) 전체에 고리. 메뉴 항목은 안쪽 고리. 지도 표식은 지도 위 대비를 위해 노랑 고리를 유지한다.
- **선택지 칩(`.choice-chip`):** 대화상자 안 선택지는 테두리 있는 칩으로, 고른 칩은 파랑 바탕·굵은 글씨로 표시한다.
- **늦게 오는 자료가 화면을 밀지 않게:** 두 흐름의 자료 영역은 최소 높이(70vh, 인쇄 제외)로 `이어서` 줄·바닥글을 첫 화면 밖에 둔다.
  늦게 채워지는 자리는 미리 잡는다 — 기존 축제 머리말의 지역 줄(불러오는 중 문구 포함), 월별 방문 차트 자리, 검색 결과 영역.
  모아 보기는 방문 자료가 정해진 뒤 한 번에 보인다. 첫 화면의 가장 큰 글(안내 띠 목표)은 서버에서 그린다.

## PC 조사·비교 중심 · 2026-09-27

사용자가 PC 기반의 기획·설계·조사를 주목적으로 지정했다. [설계21](../../design/21-desktop-research-experience.md)을
최신 입력으로 삼아 본문 최대1760px·홈 최대1440px, 단일 헤더와 접히는 기획 도구, 넓은 화면의 동시 비교 배치를 적용한다.
첫 화면의 큰 목적 이미지2개·핵심 행동이 가장 먼저 읽히며 하단 기록/예측 영역은 중립 표면으로 낮춘다.
남색은 제목·구조, 파랑은 주요 행동/선택에 사용하고 자료/이미지 자체의 구분을 과도한 색 면적으로 덮지 않는다.
이미지는 실제 실적이 없는 장식이며 목적별 주체·구도를 구별한다. 모바일을 주 화면으로 설계하지 않지만
작은 창·200% 확대·키보드·출처·실패 복구는 보존한다. 아래 작은 목적 이미지·모바일 중심 세부 배치보다 이번 요청이 우선한다.

## 2026-09-26 관광자원 화면의 시각 설계 적용

사용자의 시각화·디자인 개선 진행 승인에 따라 [설계20](../../design/20-resource-experience.md)을 적용한다.
두 관광자원 화면과 첫 화면 목적 카드가 대상이다. 기존 남색·파랑 계열, 명확한 선택 표식,
16px 장소명·14px 이상 주소/조작, 44px 조작 영역, 목록과 군집 지도 연결을 기준으로 한다.
밀집·동일 좌표 장소도 군집 목록에서 직접 선택한다. 생성 이미지는 목적 카드에만 쓰며 실제 자료 시각화는 데이터로 그린다.
아래 9월23일의 '최종 시각 디자인은 사용자 작업'은 당시 경계이며 이번 승인 범위는 설계20으로 갱신한다.
전역 메뉴·차트·달력까지 모두 개선됐다는 뜻은 아니다.

## 2026-09-23 디자인 작업의 경계

사용자의 최신 요청에 따라 이번 보완은 [기능 상세](functional-spec.md)와 [화면 목표·기본 배치](screens.md)까지다.
최종 시각 디자인은 사용자가 개선한다. 아래 기존 토큰·타이포·간격·색상은 현행 코드 또는 과거 제안이며
새 화면의 고정 디자인으로 강제하지 않는다. 자료의 의미·필수 단위/기간·행동의 결과·상태와 복구·접근성은 유지한다.
v7의 3개 상태 시안은 기존 정상 상태 v5·v6의 보완이며 검토용 상태 이름을 제품 화면 안에 노출하지 않는다.
이 변경은 앱 UI 구현이 아니다.

### 기능 상세 v7 검수 기록 · 2026-09-23

대상은 기반 `52f2975`에서 보완한 기능 상세·화면/흐름/데이터 문서와 SCR-FC-008/012/014의 v7 편집 소스·SVG다.
기준은 dev-standard `a71fd33`의 `policy/product-experience.md`와 사용자의 기능·기획 우선 요청이다.
정상 상태 v5·v6의 기존 자료 대조 증거는 재사용하고 이번에 수치나 새 공공데이터를 추가하지 않았다.

|---|---|---|
| 기획·흐름 | 충족 · 설계 범위 | 기능 상세 §1~6과 흐름 v7을 대조. 기존 축제는 검색·회차, 새 축제는 지역으로 진입하며 세 탐색에 기록 단계 없음. 관측연월 링크와 일반 메뉴 복귀를 구분 |

| 반응형 | 충족 · 와이어프레임/사본 | 새 6프레임의 내용이 프레임 밖으로 나가지 않음. 사본의 390px 시작·기능 문서·상태 화면은 전체 가로 넘침 없음. 실제 앱 확대·긴 콘텐츠 대응은 미평가 |

독립 읽기 검토에서 검색 식별·다른 지역 복귀·필터 변경 선택·목록/상세 공급의 공백을 확인해 반영했고,
주 담당자가 원문·코드·표시본을 직접 대조했다. 실제 `cursor-agent` Grok 4.6 검토는 250초 내 응답을 받지 못해 종료됐다.
이를 완료된 Grok 검토로 인용하지 않고 직접 검토 결과만 사용했다. 실제 담당자 관찰은 수행하지 않았다.

Excalidraw 3개 스키마와 SVG 반복 렌더 해시3개 일치, UC009/010 전면부·본문 각14개 일치,
문서 추적 산출물51개 누락0·lint error0를 확인했다. 새 UC의 시험 시나리오 미작성 경고28개는 유지한다.
API·실행 명세·Run 미선언은 통과로 환산하지 않는다. 앱 코드는 변경하지 않아 앱 시험·배포·운영 인수는 수행하지 않았다.

## 적용 범위·근거

SCR-FC-008~014의 개발 전 설계다. [기획 기준](../../product/planning-principles.md)과
dev-standard `6e6ce25`의 `policy/product-experience.md`를 읽고 반영했다.
이번에는 새 축제 SCR-FC-011~014에 §5의 실제 문구·첫인상 검수와 §6의 과업 입력을 추가했다.
기존 축제 v5 검수는 당시 기준 `65c4179`의 이력으로 아래에 보존한다.
아래 역할별 배치·타이포 수치는 이번 구현 제안이며 현재 앱에 반영된 값으로 기록하지 않는다.
새 시안은 회색조 배치 검수용이고 최종 색·실행 동작은 구현에서 검증한다.
자료·산식은 [데이터 시각화](data-visualization.md), 화면별 순서·예외는 [화면설계](screens.md)가 정한다.

기획 의도는 사용자에게 필요한 정보의 크기·순서·그룹으로 표현한다.
내부 수집 기준·정규화·검수 절차·시안 상태는 이 문서에 두며 제품 문구·도움말·접근성 이름·고객 응답에 넣지 않는다.
데이터의 대상·기간·단위, 처리 실패와 복구 행동은 사용자가 판단하는 데 필요한 제품 정보다.

## 새 축제 설계·구현에 전달하는 과업 입력

대상은 관광 활성화를 위한 새 축제를 구상하는 지역 공무원이다. 축제 이름·소재·장소·날짜가
아직 없을 수 있으며, 개인 기획안을 작성하지 않고도 자료를 오가며 검토를 마칠 수 있어야 한다.

| SCR-FC-012 | 구상에 쓸 자원의 성격·위치를 확인 → 필요한 상세 또는 두 자원의 사실을 읽음 | 지역 → 세 과업 이동 → 유형·범위 → 지도/목록 → 상세·선택적 함께 보기 |
| SCR-FC-013 | 월·요일별 지역 방문 차이 확인 → 같은 지표·연도의 흐름과 수치를 읽음 | 지역 → 세 과업 이동 → 실제 연도·대상·단위 → 월별/요일별 그래프 → 필요한 표·출처 |

- 참고 패턴: 기존 축제 v5의 과업 이동·현재 맥락·지역 지도와 목록·출처 상세를 재사용한다.
  회차 선택·개최 음영·D0 상대일은 새 축제에 가져오지 않는다.
- devkit `knowledge/product-experience-patterns.md`의 비교 기준 사례는 같은 기준의 정보끼리 묶는
  관점을 참고했다. 과거 방문 연도와 미래 달력 연월을 분리한다. 해당 사례의 개선 효과가 측정됐다고 주장하지 않는다.
- 자료 근거: 2025 논산 일별 보관본, Foundry 자원 세 건과 실제 소개 두 건, 보관된 2026 공휴일이다.
  자원 소개 조회·요일 집계·달력 연결은 사용 가능이고 전국 과거 분석은 후속이다.
- 검수 기준: 이름·기록 없이 세 과업을 오가는 흐름, 서로 다른 시점의 식별, 1280/390px의 읽기 순서와
  실제 고객 문구를 확인한다. 최종 색상·실제 키보드·확대·네트워크 전이는 구현 후 인수한다.

## 새 화면의 시각적 위계 · 구현 제안

본문을 12px 이하로 줄여 밀도를 확보하지 않는다. 법적 지도 귀속 등 외부 컴포넌트는 기존 조건을 유지하고
주요 정보의 폰트 축소 해법으로 복제하지 않는다. 음수/양수·선택/오류를 색 하나로만 구분하지 않는다.
위 표는 신규 화면의 읽기 역할을 정하며 기존 전역 스타일을 일괄 변경하는 지시가 아니다.

| 콘텐츠 너비 | 최대 1200px, 가운데 정렬. 1280px 시안에서 좌우 40px |
| 모바일 바깥 여백 | 16px, 390px 시안에서 콘텐츠 358px |

| 새 축제 비교 | 자원 두 개는 같은 사실 순서, 후보 두 기간은 실제 날짜·요일. 순위·추천 점수 없음 |

큰 빈 영역이나 장식이 정보·조작을 밀어내지 않도록 한다. 차트·지도처럼 공간을 사용하는 요소는 목적 있는 면적을 갖는다.
숫자의 증가·감소에 임의의 성공/실패색을 부여하지 않는다. 이 제품은 판단 근거를 보여주며 성과를 대신 판정하지 않는다.

| 과거 월별 차트 | `2025년 월별 방문 흐름` · `일평균 · 명/일 · 추정` | 미래 예측과 구분되는 실제 관측 연도 |
| 관광자원 조건 | `논산시 전체` · `관광지` · `문화시설` | 탐색 범위와 대상 |
| 관광자원 시점 | `현재 등록 정보` · 실제 조회일 | 과거 회차의 당시 자원과 구분 |
| 지도 거리 | `선택한 위치에서 직선거리 약 …km` | 이동시간과 다른 거리 |
| 차트 보조 행동 | `수치 표` / `출처·산식` | 자세한 근거를 필요할 때 확인 |
| 후보 기간 | `후보 A` / `후보 B` · 시작일·종료일 | 우열 없는 비교 |
| 결과 없음 | `선택한 조건의 등록 결과가 없어요` + `조건 바꾸기` | 검색 범위를 바꾸어 계속 탐색 |
| 불러오기 실패 | `불러오지 못했어요` + `다시 불러오기` | 실패를 인지하고 재시도 |

제목을 설명문과 툴팁에서 반복하지 않는다. 빈 데이터 카드를 전부 만들어 제한 문구를 나열하지 않는다.
추정이라는 지표 성격을 별도 경고 카드나 `검증됨` 배지로 표현하지 않는다.
버튼 `확인`·`다음`만으로 동작을 모호하게 만들지 않고 `회차 바꾸기`, `기간 비교` 등 과업을 쓴다.
기본 조회 화면에 저장 완료를 요구하는 주 행동을 두지 않는다. 선택적 저장은 보조 행동이다.
화면별 주 행동의 개수·형태를 일률적으로 고정하지 않는다.

## 상태와 회복

| 상태 | 화면 행동 | 보조기술·초점 |
|---|---|---|
| 축제 미선택 | 목적 선택 뒤 축제명/지역 검색과 결과. 사업·전략 입력 없음 | 검색 필드 이름과 결과 수, 결과 링크 접근 |
| 방문 자료 없음 | 축제 맥락과 자원·시기 이동 유지. 요청한 방문 영역에 짧은 상태 | 자동 이동하지 않고 복구 링크로 이동 가능 |
| 부분 방문 자료 | 관측 선과 표 유지, 결측 선 단절. 불완전 기간 요약 생략 | 표의 날짜별 `값 없음`, 색만으로 구분하지 않음 |
| 조회 중 | 해당 본문 로딩 상태. 가짜 수치·진행률 없음 | aria-busy와 짧은 상태 전달, 초점 강탈 없음 |
| 성공·조건 변경 | 최신 선택에 해당하는 자료로만 표시 | 결과 갱신 알림, 조작한 필드 초점 유지 |
| 오류 | 해당 영역 짧은 오류·재시도. 다른 정상 정보·입력 보존 | 실제 실패 시 알림, 재시도 뒤 조작 위치 유지 |
| 지도 배경 실패 | 목록 탐색·지역 조건 계속 제공 | 목록 전환과 동일 자원 선택 가능 |
| 선택 상세 닫기 | 원래 자원 목록·스크롤 위치로 복귀 | 열었던 자원으로 초점 반환 |
| 조회 취소·화면 이동 | 뒤늦은 응답 무시. 브라우저 뒤로가기로 조건 복귀 | 새 화면 제목·현재 이동 위치 식별 |
| 개인 저장 선택 시 실패 | 입력·조회 유지, 재시도·기존 파일 복구 경로 | 실제 저장 실패만 알림. 조회 기능 계속 사용 |

공공 조회는 로그인이나 새로운 권한 요구를 추가하지 않는다. 지도 중심 선택은 위치 권한 요청 없이 가능해야 한다.
기간 밖 공휴일 데이터가 없거나 조회 실패한 상태를 `공휴일 없음`으로 표시하지 않는다.
응답이 안 되는 사실은 그 위치의 짧은 상태로 전달하며 내부 정책 설명으로 바꾸지 않는다.

## 접근성·반응형 구현 계약

- 읽기 순서는 축제 또는 지역 맥락→과업 이동→조건→결과→상세다. 시각 순서와 DOM 순서를 맞춘다.
- 지도 마커와 목록을 같은 자원에 연결한다. 키보드로 목록 선택·상세 열기·닫기·복귀를 제공한다.
  지도 중심은 드래그 외에 이름 있는 좌표 입력·적용으로도 고를 수 있게 한다.
- 차트는 제목·단위·기간·수치 표를 가진다. 실제 날짜 입력·표 행 선택으로 점 선택을 대체한다.
  원문·상세는 hover 없이 열 수 있어야 한다. 색과 선 모양·직접 라벨을 함께 사용한다.
- 별도 모달일 때만 초점 가두기·Escape·원위치 복귀를 적용한다. 넓은 화면의 상세열을 불필요한 모달로 만들지 않는다.
- 작은 화면은 두 회차/후보를 세로로 배치한다. 표 내부만 가로 스크롤하며 페이지 전체는 넘치지 않는다.
  구현에서 320px·200% 확대·긴 이름을 확인한다. 항목명·단위·오류를 잘라내지 않는다.
- 본문 대비 4.5:1, 큰 글자·주요 비텍스트 요소 3:1을 구현 검증 목표로 둔다.
  회색조 정지 시안은 최종 색상·키보드·보조기술 실행 검증의 통과 증거가 아니다.
- 지도 제공자 귀속과 기존 적용 고지는 유지한다. 출처·계산 상세를 접더라도 대상·기간·단위는 본문에 남는다.

## 이전 기능에 유지하는 계약

SCR-FC-001~007 구현 문서는 현행 동작을 기록한다. 새 배치가 개발됐다고 역으로 해석하지 않는다.
개인 저장의 성공/실패·충돌, 비용의 원금액·단위·세금·미산정, 인쇄의 선택 자료와 출처 보존은 유지한다.
관측·가정·실측의 구분은 필요한 제목·열·단위·그룹으로 전달하며 일률적인 상태 배지를 강제하지 않는다.
금액 막대는 0축, 파이/도넛은 실제 금액·분모·비율을 함께 제공한다.

추가 수정: 결측이 개최기간 밖에만 있으면 정상 개최기간 평균을 유지하도록 범위를 명료화했다.
개최기간 평균의 누락은 회차 변경으로 복구하며 차트 기간을 줄여 분모를 바꾸지 않는다.
관광자원은 검색을 먼저 강제하는 초기 그림을 실제 지역 목록·선택 상세 그림으로 교체했다.
지표명 `월평균`은 새 계약에서 `월별 일평균`으로 정렬했다.

구조 검증: Excalidraw 스키마 4개, SVG 재렌더 바이트 일치 4개, Mermaid 10개 블록 통과.
추적 빌드의 화면 11개(기존7+신규4)와 표시본 존재를 확인했다. 린트 error 0이며 신규 UC의
TS 미작성 경고 10개는 설계 단계의 남은 개발 검증으로 유지했다. 미선언 API·실행 기록은 통과로 환산하지 않는다.
이번에는 앱·운영 배포나 내부 문서 사이트 재게시를 수행하지 않았다. 공개 API 표본 조회 1회는 HTTP403으로
본문을 받지 못해 운영 정상성을 판정하지 않았고, 관광자원 표본은 승인된 Foundry 읽기 경로로 확인했다.
