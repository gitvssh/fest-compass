# 기획 자료 정의와 확보 상태

## 읽는 기준

기존 확인 근거는 [API 명세](../../design/05_API명세서.md),
[샘플 선정](../../validation/05-festival-selection.md), [과거 기록 검증](../../validation/14-festival-history.md)이다.
아래 신규 계약은 구현 전 설계다. '검증 필요'는 실제 응답·보유 범위를 아직 확인하지 않았다는 뜻이다.
키 값·개인 기록 원문·서버 비밀정보는 문서와 traceboard에 넣지 않는다.

## 자료별 계약

| 자료 | 공간·시간·단위 | 최소 식별·표시 항목 | 확보 상태와 대체 동작 |
|---|---|---|---|
| 지역 선택 | 시도→시군구, 코드 체계 기준일 | 내부 지역 ID, 제공처 코드, 명칭, 매핑 버전 | 기존 시도 코드 매핑 기반 있음. 시군구 전수·개편 이력 검증 필요 |
| 지도 경계 | 확인된 행정구역 경계·좌표계 | 경계 기준일, 출처, 이용 조건, 좌표계 | 검증 필요. 검증 전 영역 채색 제공 안 함. 목록으로 탐색 |
| 관광자원·축제 위치 | 개별 시설/행사 좌표 | 제공처 ID, 이름, 종류, 주소, 좌표·정확도/결측 | 기존 축제 좌표 필드 있음. 자원 전수 조회와 좌표 품질은 검증 필요. 결측은 목록에 남김 |
| 등록 축제 일정 | 축제·개최회차의 시작/종료일 | 제공처 ID, 축제 ID, 회차 ID, 일정 상태, 확인일 | KTO 호출 기반 있음. 현재 등록 정보이며 실시간 운영 확인이 아님 |
| 지역 방문 추세 | 시군구·일별, 제공처 방문자 정의 | 날짜, 지표, 값/결측, 집계 정의, 수집일 | 논산 외지인 이력 검증 자료 있음. 다른 지역·기간은 보유 현황부터 확인 |
| 수요·집중·연관 관광 | 제공 API의 원래 지역/관광지 단위 | 지표명·단위·대상·기간·해석 제한 | 호출 기반과 일부 관측 있음. 전국 동일 가용성·공간 상세도는 검증 필요 |
| 과거 개최회차 | 축제 ID + 회차 ID + 실제 개최기간 | 취소/변경, 출처, 공개일, 집계 방법 | 논산 연구 자료 있음. 타 지역 과거 일정·성과 수집 범위 검증 필요 |
| 과거 예산·성과 | 회차·지표·집계 범위별 | 예산/결산 구분, 지원금/총사업비 범위, 단위·출처 | 현재 축제 API로 확보를 보장하지 않음. 공개 문서 또는 사용자 입력 |
| 장소·운영 제약 | 특정 장소·특정 사용기간 | 접근·사용 가능·시설·수용 기준·담당 확인 | 공공 관광정보만으로 확정 불가. 미확인 상태와 담당자 확인 메모 |
| 예산 항목 | 원, 수량 단위×원/단위 | 항목 ID, 수량, 단가, 출처 유형, 부가세 포함 여부 | 사용자 견적·가정 입력. 근거 없이 자동 최적 예산 제공 안 함 |
| 개인 성과 | 개인 작업의 회차·계획과 같은 지표 | 값, 측정 방법, 단위, 출처, 실제 비용 | 기존 브라우저 기록 기반 있음. 다른 사용자의 기록은 검색하지 않음 |

지도 플랫폼·이용 조건·비용은 특정 공급자를 확정하기 전에 개발 착수 조사에서 검증한다.
현재 수집된 시군구 통계를 행사장·도로의 혼잡 열지도로 세분화하지 않는다.
시각화는 자료 단위에 맞춰 경계 음영 또는 지역 요약 카드, 시설 좌표는 마커로 구분한다.

## 주요 객체와 연결

| 객체 | 키와 필수 속성 | 관계·검증 |
|---|---|---|
| Region | 내부 ID, 이름, 제공처별 코드, 유효 기준일 | 주소 문자열을 코드로 추정해 합치지 않음 |
| TourismResource | 제공처+원천 ID, 유형, 지역 ID, 좌표 상태 | 지도 좌표가 없어도 목록과 상세 유지 |
| Festival / Edition | 축제 ID / 회차 ID, 기간, 지역, 출처 | 같은 이름만으로 합치지 않음. 개최기간 변경은 같은 회차 수정 이력 |
| QueryContext | 지역 목록, 통계 기간, 행사 기간, 유형, 공간 검색 방식 | 지도·목록·차트는 같은 요청 버전 사용 |
| EvidenceItem | 원천 ID, 당시 값, 출처, 조회 조건, 단위·정의, 수집·선택일 | 선택 당시 사본은 불변. 재조회는 새 버전 |
| ConceptOption | 후보 ID, 주제·아이템·대상·장소·기간, 제약 | 항목별 evidence ID와 담당자 판단 연결 |
| BudgetLine | 항목 ID, 수량·단위·단가·세금 기준, 원금액 | 수량/단가 결측은 미산정. 음수·NaN·무한대 거부 |
| ProposalRevision | 선택 후보, 대안, 근거 사본, 비용, 이유, 생성일 | 이후 수정은 새 버전. 시스템 공식 승인이 아님 |
| OutcomeRecord | 회차 ID, 기준 기획안 버전, 지표·값·방법·출처 | 정의 불일치 때 증감 계산 보류 |

## 조회·비교 규칙

- 지역·기간 변경은 하나의 조회 버전으로 묶는다. 늦게 도착한 이전 응답이 최신 선택을 덮지 못한다.
- 로딩·정상·빈 결과·제공 오류·미수집·일부 누락·오래된 자료를 구분한다. 오류를 0으로 바꾸지 않는다.
- 일부 API 실패 때 정상 자료는 남긴다. 각 자료의 기준 기간이 다르면 차이를 명시한다.
- 지도 이동은 표시 위치만 바꾼다. '이 영역 조회' 후 공간 필터가 생겼음을 표시하고 초기화할 수 있다.
- 행사 일정 필터는 조회 기간과 하루 이상 겹치는 회차를 포함한다. 날짜 미확인은 별도 묶음으로 표시한다.
- 과거·현재는 선택한 기획 연도와 별도로 실제 일정·확인일을 표시한다. '검색 결과 없음'은 '행사 없음'의 증명이 아니다.
- 방문/입장·순방문/연인원·예산/결산·보조금/총사업비 등 정의가 다르면 순위·증감·합계를 만들지 않는다.
- 비교표는 가용 지표의 교집합과 누락 항목을 함께 보여준다. 빈 항목을 가진 후보도 제외하지 않는다.
- 같은 원천·조건·시점 자료를 다시 담으면 기존 선택을 안내한다. 다른 시점은 별도 버전으로 선택 가능하다.
- 개인 과거 기록과 공공자료는 저장 위치·출처 배지를 달리한다. 파일 가져오기 전까지 다른 기기의 개인 기록은 없다.

## 예산 산출 예

시안 검증용 가상 입력이며 실제 단가가 아니다.
프로그램 2회×100,000원=200,000원, 시설 1식×300,000원=300,000원이면
확인된 항목 합계는 500,000원이다. 홍보 단가가 비어 있으면 '확인 합계 500,000원 / 미산정 1항목'이고
확정 총액으로 표시하지 않는다. 홍보를 명시적 0원으로 입력하면 미산정이 아니다.
한도 450,000원보다 확인 합계가 50,000원 크면 미산정 여부와 별개로 초과를 표시한다.
단가·수량의 소수 처리와 원 단위 반올림은 항목별 1회, 합계는 표시된 원금액의 합으로 일치시킨다.

## 개발 착수 시 검증할 자료

| 확인 항목 | 책임·완료 증거 | 영향을 받는 요구 |
|---|---|---|
| 지역 코드·경계·지도 공급자 | 개발: 이용 조건·좌표계·샘플 렌더와 코드 매핑 기록 | FR-REG-1~3 |
| 자원 좌표·일정 페이지 범위 | 개발: 정상/빈/오류/페이지별 샘플과 보유 범위 | FR-REG-2~5, FR-CMP-1 |
| 축제·회차 식별 | 개발: 이름 변경·중복·취소·복수 장소 샘플 대조 | FR-CMP-2~3 |
| 견적·현장 제약 | 담당자 입력 또는 공개 출처, 미확인 항목 유지 | FR-PLN-2, FR-BGT-1 |
| 조회 속도·공급 한도 | 개발: 캐시·요청 합치기 실측, 실제 할당량 내 호출 | NFR-PERF-1 |

앞의 자료 확인을 마친 범위부터 구현한다. 확인 실패는 해당 레이어·지표의 미제공 상태로 표시한다.
