# 기획 자료 정의와 확보 상태

## 읽는 기준

기존 확인 근거는 [API 명세](../../design/05_API명세서.md),
[샘플 선정](../../validation/05-festival-selection.md), [과거 기록 검증](../../validation/14-festival-history.md)이다.
아래 계약은 전체 목표다. [M1 첫 구현](../2-design/region-explorer-implementation.md)과 [M2 첫 구현](../2-design/festival-comparison-implementation.md)의 제공 범위를 구분하며, 후속 항목의 '검증 필요'는 실제 응답·보유 범위를 아직 확인하지 않았다는 뜻이다.
키 값·개인 기록 원문·서버 비밀정보는 문서와 traceboard에 넣지 않는다.

## 자료별 계약

| 자료 | 공간·시간·단위 | 최소 식별·표시 항목 | 확보 상태와 대체 동작 |
|---|---|---|---|
| 지역 선택 | 전국→시도→시군구, 코드 체계 기준일 | 내부 지역 ID, 제공처 코드, 명칭, 매핑 버전 | 2026-09-08 KTO 현행 조회 목록 269행/16그룹 확인. 일반시/행정구 혼재, 합산 금지. 개편 이전 이력 대응은 후속 |
| 지도 경계 | 확인된 행정구역 경계·좌표계 | 경계 기준일, 출처, 이용 조건, 좌표계 | 검증 필요. 검증 전 영역 채색 제공 안 함. 목록으로 탐색 |
| 관광자원·축제 위치 | 개별 시설/행사 좌표 | 제공처 ID, 이름, 종류, 주소, 좌표·정확도/결측 | M1 지역별 전체 페이지/좌표 범위 검증·조회 실패 표시. 실제 위치 정밀도·장소 사용 조건은 미확인. 결측은 목록에 남김 |
| 등록 축제 일정 | 축제·개최회차의 시작/종료일 | 제공처 ID, 축제 ID, 회차 ID, 일정 상태, 확인일 | KTO 호출 기반 있음. 현재 등록 정보이며 실시간 운영 확인이 아님 |
| 지역 방문 추세 | 시군구·일별, 제공처 방문자 정의 | 날짜, 지표, 값/결측, 집계 정의, 수집일 | 논산 이력에 공주·임실 2023~2025 각 1,096일을 추가. 다른 지역·기간은 보유 현황부터 확인 |
| 수요·집중·연관 관광 | 제공 API의 원래 지역/관광지 단위 | 지표명·단위·대상·기간·해석 제한 | 호출 기반과 일부 관측 있음. 전국 동일 가용성·공간 상세도는 검증 필요 |
| 과거 개최회차 | 축제 ID + 회차 ID + 실제 개최기간 | 취소/변경, 출처, 공개일, 집계 방법 | M2에서 조사한 논산·임실·공주·원주 8회차 연결. 전국 회차·지속 변경 수집은 후속 |
| 과거 예산·성과 | 회차·지표·집계 범위별 | 예산/결산 구분, 지원금/총사업비 범위, 단위·출처 | 현재 축제 API로 확보를 보장하지 않음. 공개 문서 또는 사용자 입력 |
| 장소·운영 제약 | 특정 장소·특정 사용기간 | 접근·사용 가능·시설·수용 기준·담당 확인 | 공공 관광정보만으로 확정 불가. 미확인 상태와 담당자 확인 메모 |
| 예산 항목 | 원, 명시한 수량·기간 산출 기준 | 항목 ID, 수량, 단가, 출처 유형, 부가세 포함 여부 | 사용자 견적·가정 입력. 근거 없이 자동 최적 예산 제공 안 함 |
| 개인 성과 | 개인 작업의 회차·계획과 같은 지표 | 값, 측정 방법, 단위, 출처, 실제 비용 | 기존 브라우저 기록 기반 있음. 다른 사용자의 기록은 검색하지 않음 |

지도 플랫폼·이용 조건·비용은 특정 공급자를 확정하기 전에 개발 착수 조사에서 검증한다.
현재 수집된 시군구 통계를 행사장·도로의 혼잡 열지도로 세분화하지 않는다.
시각화는 자료 단위에 맞춰 경계 음영 또는 지역 요약 카드, 시설 좌표는 마커로 구분한다.

| 객체 | 키와 필수 속성 | 관계·검증 |
|---|---|---|

| QueryContext | 지역 목록, 통계 기간, 행사 기간, 유형, 공간 검색 방식 | 지도·목록·차트는 같은 요청 버전 사용 |
| EvidenceItem | 원천 ID, 당시 값, 출처, 조회 조건, 단위·정의, 수집·선택일 | 선택 당시 사본은 불변. 재조회는 새 버전 |
| ConceptOption | 후보 ID, 주제·아이템·대상·장소·기간, 제약 | 항목별 evidence ID와 담당자 판단 연결 |
| BudgetLine | 항목 ID, 규격·수량·기간·산출 기준·단가·세금·출처·분류 버전 | 재원과 별도. 기간 포함 견적 중복 계산 금지. 아래 상세 계약 적용 |
| ProposalRevision | 사업 정보·후보·근거·재원/지출·증감·준비 상태의 사본, 기준일, 생성일 | 이후 수정은 새 버전. 시스템 공식 승인이 아님 |
| OutcomeRecord | 회차 ID, 기준 기획안 버전, 지표·값·방법·출처 | 정의 불일치 때 증감 계산 보류 |

## 조회·비교 규칙

- 지역·기간 변경은 하나의 조회 버전으로 묶는다. 늦게 도착한 이전 응답이 최신 선택을 덮지 못한다.
- 로딩·정상·빈 결과·제공 오류·미수집·일부 누락·오래된 자료를 구분한다. 오류를 0으로 바꾸지 않는다.
- 일부 API 실패 때 정상 자료는 남긴다. 각 자료의 기준 기간이 다르면 차이를 명시한다.
- 지도 이동은 표시 위치만 바꾼다. '이 영역 조회' 후 공간 필터가 생겼음을 표시하고 초기화할 수 있다.
- 행사 일정 필터는 조회 기간과 하루 이상 겹치는 회차를 포함한다. 날짜 미확인은 별도 묶음으로 표시한다.
- 과거·현재는 선택한 기획 연도와 별도로 실제 일정·확인일을 표시한다. '검색 결과 없음'은 '행사 없음'의 증명이 아니다.
- 방문/입장·순방문/연인원·예산/결산·보조금/총사업비 등 정의가 다르면 순위·증감·합계를 만들지 않는다.
- 비교표는 가용 지표의 교집합과 누락 항목을 함께 보여준다. 빈 항목을 가진 후보도 제외하지 않는다.
- 같은 원천·조건·시점 자료를 다시 담으면 기존 선택을 안내한다. 다른 시점은 별도 버전으로 선택 가능하다.
- 개인 과거 기록과 공공자료는 저장 위치·출처 배지를 달리한다. 파일 가져오기 전까지 다른 기기의 개인 기록은 없다.

## 예산 산출 예

시안 검증용 가상 입력이며 실제 단가가 아니다.
프로그램 2회×100,000원=200,000원, 시설 1식×300,000원=300,000원이면
확인된 항목 합계는 500,000원이다. 홍보 단가가 비어 있으면 '확인 합계 500,000원 / 미산정 1항목'이고
확정 총액으로 표시하지 않는다. 홍보를 명시적 0원으로 입력하면 미산정이 아니다.
한도 450,000원보다 확인 합계가 50,000원 크면 미산정 여부와 별개로 초과를 표시한다.
단가·수량의 소수 처리와 원 단위 반올림은 항목별 1회, 합계는 표시된 원금액의 합으로 일치시킨다.

## 개발 착수 시 검증할 자료

| 확인 항목 | 책임·완료 증거 | 영향을 받는 요구 |
|---|---|---|
| 지역 코드·경계·지도 공급자 | 개발: 이용 조건·좌표계·샘플 렌더와 코드 매핑 기록 | FR-REG-1~3 |
| 자원 좌표·일정 페이지 범위 | 개발: 정상/빈/오류/페이지별 샘플과 보유 범위 | FR-REG-2~5, FR-CMP-1 |
| 축제·회차 식별 | 개발: 이름 변경·중복·취소·복수 장소 샘플 대조 | FR-CMP-2~3 |
| 견적·현장 제약 | 담당자 입력 또는 공개 출처, 미확인 항목 유지 | FR-PLN-2, FR-BGT-1 |
| 조회 속도·공급 한도 | 개발: 캐시·요청 합치기 실측, 실제 할당량 내 호출 | NFR-PERF-1 |

앞의 자료 확인을 마친 범위부터 구현한다. 확인 실패는 해당 레이어·지표의 미제공 상태로 표시한다.

## v2: 사업·수행 관계와 준비 과제

[공개 사례 보완안](../../research/2026-09-municipal-requirement-proposals.md)의 1·2·6을 반영한다.
M3의 BusinessContext·DeliveryRelation·VenueCondition·ReadinessTask는 개인 기획 파일에 구현했다. 세부 범위·필드·보관 제한은 [구현 계약](../2-design/planning-options-implementation.md)을 따른다. 운영 DB 마이그레이션은 없다.

| 객체 | 최소 필드 | 관계와 상태 규칙 |
|---|---|---|
| BusinessContext | 기획 ID, 담당 지역, 회계연도, 부서, 목적, 신규/계속/미확인, 사업 기간, 작성 기준일 | 지역 탐색의 선행 조건 아님. 초안에서 빈 항목 저장 가능, 보관·출력에서 미확인 표시 |
| DeliveryRelation | 관계 ID, 사업 ID, 기관/역할명, 관계 종류, 업무 범위, 근거, 확인일 | 직접 수행·재단 수행·위탁·용역·보조 관계를 복수 기록. 기관 유형만으로 계약/보조 관계를 결정하지 않음 |
| VenueCondition | 후보·장소 ID, 적용 기간, 설치/행사/철거 구간, 조건 종류, 상태, 확인 조직/담당 역할, 확인일, 참조 | 사용 가능·전력·화장실·접근·교통 등을 독립 확인. 관광시설 등록과 사용 허가를 분리 |
| ReadinessTask | 과제 ID, 후보/사업 ID, 내용, 담당 조직/역할, 기한, 선행 과제 ID, 필요한 자료 종류·참조, 적용 여부·이유, 진행·확인 상태 | 미정 담당/기한을 허용하고 확인 필요 목록에 남김. 자기 참조·순환·다른 사업의 과제 참조 거부 |
| EvidenceReference | 참조 ID, 공개 URL 또는 개인 문서 식별 메모, 자료 종류, 대상 범위, 작성/확인일, 확인 수준 | 계약·견적·수량/위치·참여·사진 등 종류별 관리. 원본 파일 업로드·공유 보관은 MVP 제외 |

- 장소 상태는 미확인/조건부 가능/가능/불가이며 기간과 확인 근거에 결속한다. 행사 기간 확인이 설치·철거 기간을 자동 승인하지 않는다.
- 날짜는 시작≤종료를 검사한다. 설치·운영 구간 일부 중첩은 실무상 가능하므로 일괄 금지하지 않고 장소·시간 충돌의 확인 과제로 남긴다.
- 장소·일정·범위 변경 시 연결된 견적·임차·안전·청소 과제를 재확인 대상으로 표시한다. 이전 기간의 확인 기록은 보존한다.
- 준비 과제의 적용 여부는 미확인/대상/해당 없음이며 해당 없음에는 사유·판단일을 요구한다.
- 진행 상태(미착수/진행/완료)와 외부 확인(미확인/검토 중/보완 요청/확인됨)을 분리한다. 참조 추가만으로 어느 상태도 자동 완료하지 않는다.
- 선행 과제 미완료는 후속 과제에 표시한다. 예외 진행 시 이유를 남기되 공식 절차 충족을 자동 인정하지 않는다.
- 확인 주체는 조직·역할 중심으로 기록한다. 연락처·서명·계좌·증빙 원문 등 불필요한 개인정보를 수집하지 않는다.

## v2: 재원과 금액 단계

보완안 3·4·5의 계약이다. 비용의 관측값과 담당자의 산출값을 구분한다.

|---|---|---|

요구→편성→입찰→계약→지급→정산 검토는 반드시 모두 존재하는 고정 순서가 아니다.
재원 주체(국비/지방비 등)와 전달 관계(보조 등)는 별도 속성이다. 같은 지원금을 두 행으로 중복 합산하지 않는다.
상위 재원 총액과 그 하위 분담액은 상하 관계를 남기고 합계에는 한 수준만 사용한다. 중복 여부 미확인은 합산을 보류한다.
직영·수행기관·보조사업 등 공개된 해당 기록만 연결한다. 여러 지급 기록과 누계 문서는
같은 금액을 중복 계산하지 않도록 개별/누계·포함 기록 ID를 구분한다.
이 MVP에서는 범위 중복 여부가 불명확하면 합산을 보류하고 원문 기록을 나란히 보여준다.

금액 값은 알려진 비음수 유한 수 또는 미확인이다. 0은 명시된 값일 때만 저장한다.
원문 '-', 빈칸, 미공개, 접근 실패는 각각 원문 표기·결측 이유로 보존하며 0으로 변환하지 않는다.
원/천원 환산은 원문 단위를 함께 보존하고, 통화·단위 불명확 시 환산하지 않는다.
실제 계약을 변경하거나 지급을 실행하는 기능은 없다.

### 산출·비교 규칙

1. 프로그램 2회×100000원=200000원, 시설 1식×300000원(2일 포함)=300000원이다. 시설에 2일을 다시 곱하지 않는다.
2. 일별 임차 3대×2일×50000원/대·일=300000원이다. 기간당 단가 여부가 미확인이면 계산을 보류한다.
3. 항목마다 계산 마지막에 원 단위 반올림을 한 번 적용한다. 1.5×1001원=1502원이며 합계는 표시된 항목 금액을 더한다. 합계의 안전한 표현 범위를 넘으면 오류를 표시한다.
4. VAT 포함/별도/면세/미확인을 구분한다. 자동 세율을 가정하지 않는다. 금액이 산정된 항목의 기준이 섞이거나 미확인이면 기준별 소계만 표시하고 최종 총액·한도 차액 계산을 보류한다. 별도 세금액을 입력하면 적용 근거를 함께 남긴다.
5. 미산정이 있으면 알려진 지출 소계와 미산정 수를 표시한다. 같은 세금 기준에서 소계가 한도를 이미 넘으면 최소 초과액을 표시하되 총액 확정은 아니다.
6. 재원 합계와 지출 합계를 더하지 않는다. 확인 재원 300000원·예정 200000원은 확보액 300000원이다. 지출 확인 소계 500000원·미산정 1건이면 부족액은 최소 200000원이며 전체 부족액은 미확정이다. 범위·세금 불일치 시 부족액도 보류한다.
7. 이전 400000원과 현재 500000원이 같은 범위·단계·세금이면 명목 차액 +100000원이다. 기간·수량·관련 부서 범위의 변경 이유를 표시하고 물가 보정이나 효율 개선을 추론하지 않는다.
8. 부분 용역 기초금액과 전체 행사 요구액, 보조금과 총사업비, 누계와 개별 지급은 같은 값으로 순위를 매기지 않는다. 비교 보류해도 출처가 있는 원래 금액은 읽을 수 있다.

견적·분류·준비 과제는 재확인할 초안으로만 가져오며 기한과 확인 상태를 초기화한다. 과거 확정 재원은 새 회차의 확보 재원이 되지 않는다.

파일은 스키마 버전과 관계를 검증한 뒤 교체 미리보기를 거친다. 신규 객체 참조·불변 버전·숫자·상태·과제 의존 순환을 모두 검사한다.
기존 버전 변환은 명시한 변환기와 왕복 검증이 있을 때만 허용하고, 미지원 미래 버전·손상 파일은 기존 자료를 유지한다.
구체적인 파일 형식·한도·이전 버전 변환은 구현 단계에서 확정한다. 문서 v2를 실제 저장 형식 버전으로 사용하지 않는다.

실제 v3 표본은 [자료 점검](../../research/2026-09-historical-comparison-review.md)과 고정 JSON으로 재현한다. 운영 모델·원천 이력 파일은 변경하지 않는다.

수량·단가·기간은 원래 입력 문자열을 보존한다. 음수·쉼표·지수·소수 6자리 초과는 거부한다.
정수 기반 계산으로 항목 전체를 한 번 원 반올림한 뒤 합산하며 안전한 정수 범위를 넘는 값은 보류한다.
기간 포함과 기간당 단가를 구분한다. 별도 세금은 근거가 있는 직접 입력 금액만 더하고 세율을 추정하지 않는다.
원문 금액은 숫자·KRW·원/천원 단위가 확인된 것만 환산하며 미환산 이유·원래 표기를 함께 보존한다.

예산에는 사업연도·지역/부서·후보·아이템·대상·장소·설치/행사/철거 기간의 적용 조건을 남긴다.
조건이 바뀌면 현재 총액 적용·재원 확정·분류 검토·전체/중복 확인을 재검토한다. 재검토 시작 전 기획을 보관한다.
원문 금액 기록은 작성 중에도 초안·파일에 남으며, 출처·기준일 등 필수 정보를 확인한 뒤 기록됨으로 고정한다.
고정 기록의 수정은 새 기록으로 추가한다. 다른 단계·개별/누계·재원/지출 사이를 자동 합산하지 않는다.
같은 재원 식별 메모의 중복·상하위 동시 포함·순환 참조를 검사하고 알려진 상위 금액과 여러 단계 하위 합계를 대조한다.
한 기획의 기존 20개 보관본·5MB 한도와 저장 충돌·손상 파일 방어를 유지한다.
후보별 지출 100개·재원 40개·원문 기록 100개 한도다. 기획안 출력은 아래 M5 계약을 따른다. 결과 연결은 아래 M6 계약을 따른다.

## M5 기획안·출력의 구현 계약

결과 기능까지 사용한 파일은 아래 v4 계약으로 확장한다. v3 보관본 자체는 변경하지 않는다.

개인 파일 v3는 기존 v1/v2를 읽되 기존 일반 보관본을 기획안으로 승격하지 않는다. `Revision.proposal.format=1`이 ProposalRevision이고 해당 `draft`에 사업·후보·자료·예산·준비 상태와 선택적인 `measurementPlan`을 복사한다. 보관 시 후보 두 개 이상과 우선 후보의 선택 이유를 검사하며 미산정·미확인은 허용한다. 이전 보관본의 수정·제거는 저장 시 거부한다.

OutputSelection은 화면에서 고른 기획안 ID·자료 종류·출력 구성 시각이며 개인 저장 필드를 새로 만들지 않는다. PDF에는 세 값을 표시한다. 실제 인쇄 완료·공식 제출 기록은 생성하지 않는다. 출력 형식 1은 그래프와 표를 같은 사본에서 구성하고 선택 범위를 고정한다. 세부와 20개/5MB·호환·복원 규칙은 [기획안 구현](../2-design/proposal-implementation.md)을 따른다.

## M6 결과·다음 회차의 구현 계약

개인 파일 v4의 `outcomes`는 결과 초안 하나와 불변 보관본 최대 20개다. 결과마다 같은 파일의 기획안 `proposalId`가 필요하다. 전체 파일 5MB·기획 보관본 20개 한도는 유지한다.
성과 행은 계획값/참조·계획 정의/단위·실측 정의/단위·비교 대상 기간·실측값/출처/참조/결측 사유를 가진다. 자유문장 측정 계획을 숫자로 자동 변환하지 않는다.
재원 결과는 기획안의 포함 재원 ID·실제 사용 단계(payment/settlement/unknown)·사업 범위 일치 확인·범위 설명·세금 기준과 actual/balance/returned/interest를 각각 가진다.
각 결과 값은 문자열 숫자 또는 빈칸, 출처(unknown/manual/public), 참조, 미확인 사유다. 비용은 원 단위 정수이며 값이 있으면 출처·참조가 필요하다. public은 담당자 전사이며 검증된 API 조회 표시가 아니다.
그래프·합계·비율의 보류 조건과 미확인 처리, 증빙 확인·차기 초기화는 [구현 계약](../2-design/outcome-implementation.md)을 따른다.
차기 기획 `previousOutcomeId`는 같은 파일의 원본 결과 보관본을 가리킨다. 가져오기·출력·복사에서 P/R 보관본을 보존하고 참조 누락·ID 충돌을 거부한다.
