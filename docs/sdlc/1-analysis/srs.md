# 요구사항 정의와 기능목록

2026-09-24 방문 자료 보강은 FR-EXF-2·FR-NEW-3의 별도 집계 영역이다. 임실의 확인된 회차에 한해
개최 행정동 방문 구성을 시군구 일별 자료와 분리해 제공하고, 임실군의 2018~2025년 연간 추세는 월·요일 평균과
별도 단위로 보여준다. 기록·전략 답변은 요구하지 않으며 기간 없는 성·연령·거주지·목적지 순위를 추정하지 않는다.
[기능 상세 §9](../2-design/functional-spec.md#9-방문-구성과-지역-연간-추세),
[추가 인수 기준 TS-FC-012](../3-testing/scenarios/TS-FC-012.md), [실행 기록37](../../validation/37-visitor-context.md)을 따른다.

제품 표시명은 **pickDday**다(2026-09-23 확정, 이전 이름 FEST Compass). 요구 ID(FR-*·NFR-*)와 UC/TS/SCR ID의 `FC` 접두사는 그대로 유지한다.

## 2026-09-23 기능 상세 보완

FR-EXF-1~4·FR-NEW-1~4의 [기능 상세](../2-design/functional-spec.md)를 추가했다. 새 기능군을 늘리지 않고
검색·현재/과거 식별, 조회 조건과 복귀, 월별 관측→실제 연월 일정, 자료 갱신·실패의 결과를 명시한다.
다른 지역 탐색은 선택 축제의 지역·회차를 바꾸지 않는다. 자료 종류별 공급·출처 시점과 실패 분리는
[데이터 계약 v7](../2-design/data-visualization.md)을 따른다. 두 UC의 AC11~14가 해당 동작을 인수한다.
전역 장식·시각 스타일을 확정하지 않으며 화면 목표·와이어프레임·기본 배치는 [화면설계](../2-design/screens.md)에서 전달한다.
기존 축제 화면·조회 연결의 실행 결과는 [검증 기록34](../../validation/34-existing-festival-journey.md)를 따른다. 새 축제 전용 연결은 **사용 가능**이며 문서·렌더 검수나 코드 존재는 기능 동작의 통과가 아니다.

## 2026-09-24 관련 자료 검색 보완

두 핵심 흐름의 선택적 보조 행동으로 관련 자료 검색을 제공한다. 축제명·지역·확인된 회차 연도 또는 지역·관광자원명으로
기본 검색어를 만들고 사용자가 주제·연도·검색어를 조정해 DuckDuckGo 새 탭을 연다. 원래 탐색 조건·자원 선택은 유지한다.
확인되지 않은 대상·연도는 만들지 않고 빈 검색어는 수정하게 한다. 앱에 기사 목록·수치·요약을 수집하거나 검색어를 저장하지 않는다.
상세는 [기능 상세 §8](../2-design/functional-spec.md#8-관련-자료-검색원문-연결),
인수 범위는 [TS-FC-011](../3-testing/scenarios/TS-FC-011.md), 실행 근거는 [검증 기록36](../../validation/36-related-material-search.md)을 따른다.
기존 두 UC의 선택적 흐름에 연결하며 실제 외부 결과·기사 원문 확인과 앱의 검색어·이동 검증을 구분한다.

## 2026-09-22 적용 경계

[확정 기획 기준](../../product/planning-principles.md)에 따라 기존 축제 개선·새 축제 기획의
공공데이터 조회·비교·시각화를 중심에 둔다. 핵심 질문은 정보 설계 기준이며 사용자 답변은 필수가 아니다.
아래 기획·판단 기록·예산 입력·결과 입력·보관·출력 요구는 사용자가 선택한 경우의 지원 기능이다.
두 대안 작성·선택 이유·기획안 저장을 핵심 조회·비교의 선행 조건으로 요구하지 않는다.
기록을 선택해도 전략적 질문 전체의 답변을 강제하지 않는다. 조회·계산의 최소 조건과 파일 무결성 검사는 별도다.
기존 FR·UC·TS의 상세 필수값과 동선 정렬은 후속이다. 기존 축제 탐색의 새 범위는
FR-EXF-1~4와 [UC-FC-009](usecases/UC-FC-009.md), 새 축제 기획의 탐색 범위는
FR-NEW-1~4와 [UC-FC-010](usecases/UC-FC-010.md)이다. FR-EXF는 구현·자동 인수 시험을 마쳤고(아래 참조) 실무자 업무 인수는 남아 있다.
FR-NEW는 두 번째 전용 흐름으로 구현·자동 인수 시험을 통과했으며 실제 담당자 인수는 후속이다.

### 기존 축제 개선의 새 요구와 표시 방식

FR-EXF-1~4는 **active**이며 구현과 자동 시험은 [TS-FC-009](../3-testing/scenarios/TS-FC-009.md)·[검증 기록34](../../validation/34-existing-festival-journey.md)에 연결한다. 실무자 업무 인수는 후속이다. 두 목적 진입에서 기존 축제를 선택한 뒤
과거 방문 흐름·주변 관광자원·다음 개최 시기를 순서와 기록에 구애받지 않고 탐색하는 범위다.
FR-EXF는 기존 축제의 탐색을 다루며 새 축제 기획은 아래 FR-NEW에 별도로 정의한다.
개인 기획·예산·결과 기록 전체의 개편은 이 두 탐색 요구에 포함하지 않는다.
화면은 SCR-FC-008~011, 인수 기준은 UC-FC-009에 연결한다. 기존 UC-FC-008의 개인 저장·복원 계약과 구분한다.

FR-REG-4의 출처·단위·기간·해석 정보와 FR-CMP-3의 비교 가능한 범위 표시 원칙은 새 화면에도 적용한다.
다만 새 화면은 조회 결과를 제목·범례·단위·실제 날짜와 짧은 상태로 먼저 이해하게 하고,
자세한 정의·수집 시각·출처는 직접 열어 확인하게 한다. 기존 자료 확보 행렬이나 내부 계약 설명을
모든 새 화면 상단에 먼저 읽어야 할 영역으로 강제하지 않는다. 비교를 바꾸는 누락·기간 차이는 해당 결과 옆에 표시하고,
실패에는 재시도·조건 변경 등 다음 행동을 붙인다. 내부 검수 상태·규칙 준수 선언은 제품 화면 문구가 아니다.

평균·기간·월별 가공과 반올림·결측 규칙은 [시각화 계약](../2-design/data-visualization.md)을 정본으로 삼는다.
현행 자료와 새 가공을 구분하며 기존 지역·비교 시험의 통과를 FR-EXF 또는 UC-FC-009의 완료로 환산하지 않는다.

### 새 축제 기획의 지역 중심 탐색

FR-NEW-1~4는 모두 **active · 사용 가능**이다. 경로는 `/new` → `/new/{지역코드}/resources·visits·timing`,
새 조회는 `/api/new/visits`·`/api/new/resource-detail`이다. 실행 결과는 [검증 기록35](../../validation/35-pickdday-new-festival.md)를 따른다.
기존 축제 흐름 FR-EXF를 대체하지 않는다. 첫 화면 SCR-FC-011에서 새 축제 기획을 고르면
축제 검색 대신 지역을 선택하고 SCR-FC-012의 현재 관광자원 지도·목록으로 진입한다.
관측 자료가 있는 지역에서는 SCR-FC-013의 월·요일별 방문 흐름을 볼 수 있고,
SCR-FC-014에서는 연월 달력부터 살펴본 뒤 후보 기간을 선택할 수 있다. 이 세 화면은 자유롭게 이동한다.

새 제품의 공통 조건은 지역·관측연도·임시 자원 선택·명시적 위치 기준점·달력 연월·후보 기간이다.
축제명·주제·대상 관광객·이유·기획안 작성은 조회 조건이 아니다. 자원 함께 보기는 최대 두 개의
임시 탐색 선택이며 최종 개최장소 확정·기획안 저장·지역 테마 추천으로 바꾸지 않는다.
후보 기간이 없어도 달력 탐색을 시작하고 하나의 후보만으로도 정보를 볼 수 있다.

월·요일 평균과 기간 완전성·반올림은 [시각화 계약](../2-design/data-visualization.md)이 정본이다.
확보한 자원부터 화면을 구성하고 미확보 통계·상세 필드를 기본 화면에 빈 카드로 나열하지 않는다.
사용자가 방문 흐름을 직접 열었는데 자료가 없으면 짧은 상태와 자원·일정 탐색으로 이어지는 행동을 제공한다.
제목·단위·관측연도·선택 상태로 의미를 전달하며 출처와 상세 계산은 필요할 때 연다.
유사 지역·축제 자동 추천, 합성 테마 점수, 현재 자원에서 방문 동기나 신규 축제 흥행을 추론하는 기능은 포함하지 않는다.
과거 사례를 더 보고 싶을 때만 기존 SCR-FC-002/UC-FC-002로 이동하고, 다른 축제의 회차·설정·기획을 기본값으로 복사하지 않는다.

## 적용 범위·상태

이 문서는 [제품 기획](../0-planning/product-plan.md)의 M1~M6 및 두 목적별 탐색에 필요한 신규·연결 요구사항 정본이다.
**active는 요구사항이 유효하다는 뜻이며 구현 완료가 아니다.** M1 전국·지역 조회와 개인 근거 보관, [M2 주변·과거 축제 비교](../2-design/festival-comparison-implementation.md)의 첫 구현을 추가했다. 각 요구의 전체 완료 판정과 실무 검증은 별도다.
[M3 기획 후보](../2-design/planning-options-implementation.md)에 보관 근거·사업·수행 관계·장소 확인·준비 과제·개인 보관본을 연결했다. [M4 예산·준비 규모](../2-design/budget-implementation.md)에 재원·지출·단계별 원문·이전 보관본 비교를 연결했다. [M5 기획안](../2-design/proposal-implementation.md)에 불변 보관과 사업설명/준비 목록 출력을 연결했다. [M6 결과·다음 회차](../2-design/outcome-implementation.md)도 첫 구현을 제공한다.

2026-09-22 [현행 점검](../../review/2026-09-current-state.md)과 [데이터 현황](../../research/2026-09-data-inventory.md)을 함께 읽는다. 지역·비교는 기록 없이 사용하고 공란 기획 초안도 보관할 수 있다. 기획안으로 보관할 때의 두 후보·우선 후보·선택 이유 조건과 개인 결과의 기준 기획안 조건은 현행 제약이며, 선택적 기록 원칙에 맞춘 후속 재설계 대상이다.

기존 [기능명세서](../../design/04_기능명세서.md)의 FR-EVD-1~4, FR-CAL, FR-SCN,
FR-LGR-1~4, FR-RPT-1 등은 당시 구현의 상세 근거로 유지하고 재번호·재사용하지 않는다.
새 영역도 기존 FR-{영역}-{번호} 관례를 따른다. 기능목록은 아래 표 자체이며 별도 중복 대장을 만들지 않는다.
화면과 인수 시나리오 연결은 각 UC의 covers·screens와 TS의 covers_ac에서 traceboard가 생성한다.

횡단 과제로 검증한다. API 운영 한도·캐시 시간·파일 용량은 [자료 계약](data-contract.md)과 현재 구현을 확인해
개발 시 확정한다. 새 객체 추가로 기존 파일 한도를 묵시적으로 늘리지 않는다.

## 우선순위와 완료 기준

두 목적별 탐색의 설계 범위는 FR-EXF-1~4와 FR-NEW-1~4다. FR-EXF는 [TS-FC-009](../3-testing/scenarios/TS-FC-009.md)와
[검증 기록34](../../validation/34-existing-festival-journey.md)에 구현·자동 시험·공개 반영 근거가 있고 실무 인수는 없다.
FR-NEW는 구현 코드와 인수 시나리오 [TS-FC-010](../3-testing/scenarios/TS-FC-010.md)이 있으나 실행 기록·실무 인수는 아직 없다. 아래 M1~M6 순서는 기존 구현의 이력이며
새 흐름의 개발 순서나 완료 근거로 사용하지 않는다.

M1의 지역·조건·출처·결측과 근거 담기를 먼저 구현한다. 이어 M2 비교, M3 후보를 연결한다.
M4 항목별 비용·재원·기획 사본의 자동 검증을 추가했다. M5는 기획안 출력·파일 복원·당시 값 보존 검증을 추가했다. M6 결과·공개 비용/개인 회차 검색·차기 준비 연결을 구현하고 [검증 기록](../../validation/25-planning-outcomes.md)을 연결했다.
기능 완료는 해당 UC의 인수 기준과 TS 실행 증거, 관련 비기능 검증을 갖췄을 때만 표시한다.
TS-FC-001/003의 M1, TS-FC-002의 M2와 TS-FC-003/004의 M3 해당 범위에 자동 검증을 추가했다. TS-FC-005 AC1~9의 자동 검증은 [M4 결과](../../validation/23-planning-budget.md)를 따른다. TS-FC-006 자동 검증은 [M5 결과](../../validation/24-planning-proposal.md)를 따른다. 전체 실무자 관찰은 미실행이다. 기존 앱 테스트 통과를 신규 기능 검증으로 환산하지 않는다.

## v2 반영 근거와 범위

[공개 사례의 8개 보완안](../../research/2026-09-municipal-requirement-proposals.md)을 기존 요구 ID에 반영했다. 요구 ID를 재번호하지 않았으며 UC·TS v2에서 추가 인수 기준을 연결한다.
사업·예산 입력은 올해 기획 단계부터 펼친다. M1 지역 조회는 사업 정보 없이 사용할 수 있어야 한다.
법정 기한·투자심사 대상·계정 코드·세율을 자동 판정하지 않는다. 연도·기관별 적용 여부와 확인 출처를 기록한다.
기능 범위는 개인 조사·비교·산출·준비 확인·출력이며, 전자결재·입찰 집행·지급·정산 승인·증빙 원본 저장소는 포함하지 않는다.

## 방문자 특성과 관광자원 연결 보강

UC-FC-009의 임실 2025년 회차에서 관측기간을 증명한 성·연령 비율·목적지 검색순위를 읽고 확인된 현재 관광자원으로 이동한다.
원본과 조회 조건을 함께 보존하며 연도·대상·비율·연결 오류는 해당 추가 자료를 제공하지 않는 방식으로 처리한다.
거주지·미확인 장소 연결·실제 방문 경로는 제공 범위로 확대하지 않는다. 기능·배치는 [기능 상세 §10](../2-design/functional-spec.md#10-방문자-특성과-관광자원-연결),
인수는 [TS-FC-013](../3-testing/scenarios/TS-FC-013.md), 구현·공개 결과는 [기록38](../../validation/38-visitor-profile.md)을 따른다.
위 보강은 2025년 한 회차의 기록이며 계속 사용 가능하다.

## 회차별 방문자 특성과 두 회차 비교 보강

상태: **사용 가능 — 원자료·구현·공개 검증 완료.** FR-EXF-2(과거 방문 비교)와 FR-EXF-3(주변 관광자원)의 보강이다.
임실N치즈축제 2023·2024·2025년의 확인된 방문자 특성을 적용 회차에 맞춰 보여준다. 한 회차는 기존 표시, 두 회차는
오래된 해 → 최근 해 순서로 성·연령 비율과 %p 차이, 목적지 두 해 순위와 변화를 제공한다. 기존 방문 구성에는 두 회차의 하루 평균·외지인 비율 차이를 더한다.
세 회차를 적용하면 선택은 유지하고 확인된 최근 두 회차를 비교하며, 방문 구성은 세 회차를 모두 보이고 요약만 최근 두 회차로 계산한다.
선택하지 않은 회차·검증에 실패한 회차의 값은 쓰지 않으며, 없는 순위를 0이나 신규로 만들지 않는다.
기록·저장·선택 이유는 요구하지 않는다. 기능·배치는 [기능 상세 §11](../2-design/functional-spec.md#11-두-회차-방문자-특성-비교),
인수는 [TS-FC-014](../3-testing/scenarios/TS-FC-014.md), 구현·공개 결과는 [기록39](../../validation/39-edition-profile-comparison.md)를 따른다.
