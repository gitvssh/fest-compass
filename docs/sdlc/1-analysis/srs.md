# 요구사항 정의와 기능목록

## 적용 범위·상태

이 문서는 [제품 기획](../0-planning/product-plan.md)의 M1~M6에 필요한 신규·연결 요구사항 정본이다.
**active는 요구사항이 유효하다는 뜻이며 구현 완료가 아니다.** 아래 기능은 개발 필요다.
기존 개인 저장·운영 기록 기반은 재사용하되 신규 근거·후보 객체까지 연결됐다고 간주하지 않는다.

기존 [기능명세서](../../design/04_기능명세서.md)의 FR-EVD-1~4, FR-CAL, FR-SCN,
FR-LGR-1~4, FR-RPT-1 등은 당시 구현의 상세 근거로 유지하고 재번호·재사용하지 않는다.
새 영역도 기존 FR-{영역}-{번호} 관례를 따른다. 기능목록은 아래 표 자체이며 별도 중복 대장을 만들지 않는다.
화면과 인수 시나리오 연결은 각 UC의 covers·screens와 TS의 covers_ac에서 traceboard가 생성한다.

## 비기능 요구사항

| ID | 항목 | 검증 가능한 기준 | 상태 |
|---|---|---|---|
| NFR-DATA-1 | 의미와 출처 | 관측·가정·계산·실측, 지역 방문자/입장 건수를 구분. 결측을 0으로 표시하지 않음 | active |
| NFR-ACCESS-1 | 접근성 | 주요 흐름 키보드 완주, 지도 대신 같은 자료 목록 제공, 색 이외의 상태 표기와 보이는 초점 | active |
| NFR-VIEW-1 | 작은 화면 | 390px에서 페이지 전체 가로 넘침 없음. 비교표 내부 스크롤은 제목·단위 접근 유지 | active |
| NFR-PERF-1 | 응답과 최신 선택 | 실험 조건을 기록한 캐시 조회에서 3초 내 결과 또는 로딩/지연 안내. 늦은 응답으로 최신 선택 변경 0건 | active |
| NFR-PRIVACY-1 | 개인 기록 보호 | 분석 이벤트·공개 서버에 개인 입력 자동 전송 0건. API 키는 브라우저·문서·로그에 노출 0건 | active |
| NFR-RECOVERY-1 | 저장 복구 | 손상 파일·참조 오류·탭 충돌·저장 거부 시 기존 보관본 손실 0건과 복구 경로 제공 | active |

속도와 사용성 기준은 목표 초안이며 달성 실적이 아니다. 비기능 요구는 [인수 전략](../3-testing/acceptance-plan.md)의
횡단 과제로 검증한다. API 운영 한도·캐시 시간·파일 용량은 [자료 계약](data-contract.md)과 현재 구현을 확인해
개발 시 확정한다. 새 객체 추가로 기존 파일 한도를 묵시적으로 늘리지 않는다.

## 우선순위와 완료 기준

M1의 지역·조건·출처·결측과 근거 담기를 먼저 구현한다. 이어 M2 비교, M3 후보를 연결한다.
M4~M6는 기존 개인 작업을 재사용하되 항목별 비용·기획 사본·근거 재검색의 연결 검증을 추가한다.
기능 완료는 해당 UC의 인수 기준과 TS 실행 증거, 관련 비기능 검증을 갖췄을 때만 표시한다.
현재는 모든 신규 TS가 미실행이다. 기존 앱 테스트 통과를 신규 기능 검증으로 환산하지 않는다.
