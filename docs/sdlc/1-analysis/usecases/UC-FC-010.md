# UC-FC-010 · 지역의 자원·방문 흐름·시기를 살펴 새 축제를 구상한다

| 항목 | 내용 |
|---|---|
| ID | UC-FC-010 |
| 액터 | 지역 관광 활성화를 위한 새 축제를 구상하는 지역 공무원 |
| 목적 | 지역 자원에서 구상의 단서를 찾고 지역 방문 패턴·공개 일정 여건을 살펴 장소와 시기의 선택 근거를 얻는다. |
| 버전 | v2 (2026-09-23) |
| 구현 상태 | 사용 가능 — `/new` 지역 선택과 `/new/{지역코드}/resources·visits·timing` 화면·조회 코드가 있다. 단위·타입·빌드·전용 브라우저 인수는 통과했고 공개 운영 확인을 마쳤다. 공개 서비스의 새 축제 선택은 `/new`로 연결된다. 기존 축제 흐름 UC-FC-009는 그대로 유지한다. |
| 관련 화면 | SCR-FC-011 두 목적·지역 선택, SCR-FC-012 관광자원, SCR-FC-013 지역 방문, SCR-FC-014 시기 |
| 관련 API | 읽기 전용 `GET /api/new/visits`(월별·일별 방문 + 요일 블록), `GET /api/new/resource-detail`(자원 소개)을 추가했고 기존 `GET /api/existing/resources`·`GET /api/existing/schedule`을 재사용한다. OpenAPI 정형 계약은 선언하지 않았으며 `apis: []`는 API 검증 통과가 아니다. |

## 사전 조건

- 축제명·주제·대상 관광객·기획 이유·과거 회차·기획안·개인 기록이 없어도 시작할 수 있다.
- 첫 조회에 필요한 조건은 시군구다. 위치 권한이나 사용자 거주지로 임의 지역을 고르지 않는다.
- 관광지·문화시설은 선택 지역의 현재 등록 자료를 사용한다. 일별 방문은 보관된 지역·기간에서만 가공한다.
  자세한 범위는 [데이터 현황](../../../research/2026-09-data-inventory.md)을 따른다.
- 지역에 과거 방문 이력이 없어도 관광자원·일정 탐색을 시작할 수 있다. 논산의 예시를 다른 지역에 대신 표시하지 않는다.

## v2 기능 상세 연결

[기능 상세](../../2-design/functional-spec.md)는 검색·조건 유지·월별 상세와 실제 연월 일정 연결·자료 갱신·복구의 정본이다.
AC11~14를 추가했다. 14개 기준은 새 축제 전용 headless 시험 37개 항목으로 통과했다. 기존 회차/지역·지표 정의와 기록 선택 경계는 유지한다.
최종 시각 디자인은 사용자가 진행한다. 설계 산출물은 화면 목표·기본 배치·상태 와이어프레임까지다.

## 기본 흐름

1. SCR-FC-011에서 **새 축제 기획**을 선택하고 시도·시군구를 고른다. 축제 검색이나 신규 축제 등록을 요구하지 않는다.
   SCR-FC-012로 진입해 해당 지역의 현재 관광지·문화시설 지도와 목록을 본다.
2. 자원 이름·유형·주소·위치를 살펴보고 관심 있는 자원을 상세에서 확인한다. 지도 핀과 목록은 같은 원천 ID로 연결한다.
   원하면 **함께 보기**에 최대 두 개를 추가해 나란히 본다. 한 개 또는 선택 없이도 탐색을 계속한다.
3. 거리 관점이 필요할 때 장소 또는 지도 위치를 **위치 기준점**으로 명시한다. 함께 보기 선택만으로 기준점이 자동 지정되지는 않는다.
   선택 지역에서 조회한 자원과 기준점 사이의 직선거리를 살펴보고 기준점을 해제할 수 있다.
   자원·기준점은 임시 탐색 상태이며 개최장소 확정이나 개인 기획안의 장소 필드로 자동 변환되지 않는다.
4. SCR-FC-013에서 지역 방문 흐름을 연다. 최근 완전연도를 기본으로 월별 일평균과 요일별 일평균을 확인한다.
   관측연도를 바꾸고 실제 수치 표·출처·계산 상세를 열 수 있다. 각 평균의 산식·분모·누락·반올림은
   [시각화 계약](../../2-design/data-visualization.md)을 따른다. 제목과 단위는 선택 지역의 관측임을 보여준다.
5. SCR-FC-014에서 연월 달력을 넘기며 요일·공휴일·선택 지역의 등록 행사를 본다. 후보 기간이 아직 없어도 이 탐색을 제공한다.
   필요하면 시작·종료일로 후보 하나를 선택하고, 비교하려는 경우에만 두 번째 후보를 추가한다.
   두 후보의 실제 날짜·일수·휴일·등록 일정 겹침을 나란히 볼 수 있다. 기간 선택 이유나 기획명은 입력받지 않는다.
6. 자원·방문·시기 화면을 원하는 순서로 오가며 탐색을 마친다. 관측연도와 미래 후보 날짜는 서로 바꾸지 않는다.
   어느 단계에서도 기록·저장·확정 버튼을 눌러야 다음 탐색을 할 수 있는 절차를 두지 않는다.
7. 사용자가 과거 사례를 더 보고 싶을 때만 기존 [UC-FC-002](UC-FC-002.md)의 SCR-FC-002로 이동한다.
   자동으로 유사 축제를 선정하거나 사례의 회차·기획·설정을 새 축제의 기본값으로 복사하지 않는다.

## 대안·예외 흐름

- **A1. 처음 방문·지역 미선택:** 전국의 지역 선택을 보여준다. 다른 사용자의 담당 지역이나 논산을 기본값으로 넣지 않는다.
  지역명을 찾지 못하면 목록·검색 조건을 바꿀 수 있다. 이 상태에서 축제 이름을 대신 입력하도록 요구하지 않는다.
- **A2. 등록 자원 없음:** 조회 완료한 해당 종류·지역의 결과가 없음을 짧게 알리고 지역·자료 종류를 바꿀 수 있다.
  원천 목록에 없는 자원을 생성하지 않는다. 미연결 음식점·숙박·테마·상세 정보는 실제 필드처럼 채우지 않는다.
- **A3. 함께 보기 세 번째 선택:** 현재 두 항목을 유지하고 기존 항목을 해제해 교체할 수 있게 한다.
  세 항목을 조용히 추가하거나 사용자의 기존 선택을 임의로 교체하지 않는다. 최적 장소 점수나 순위를 붙이지 않는다.
- **A4. 자원 좌표 없음:** 목록과 실제 주소는 유지하고 핀·거리만 생략한다. 해당 자원을 위치 기준점으로 사용할 수 없으면
  좌표가 있는 다른 장소나 지도 위치를 고를 수 있다. 주소 추정 좌표를 원천 좌표처럼 만들지 않는다.
- **A5. 방문 이력 없음·불완전한 연도:** 자원 기본 화면에 빈 평균 카드를 여러 개 놓지 않는다.
  방문 흐름을 직접 연 경우에는 짧은 상태와 다른 연도·자원·달력 탐색 행동을 제공한다.
  완전연도가 없으면 부분연도를 완전연도로 자동 선택하지 않는다. 사용자가 불완전 기간을 골랐을 때 평균 생성 여부와
  유효한 월·일별 값의 표시는 시각화 계약을 따른다. 실제 0과 누락을 같은 막대로 표현하지 않는다.
- **A6. 후보 기간 없음·하나만 있음:** 선택한 연월의 달력 탐색은 계속된다. 후보 하나도 날짜·휴일·행사 정보를 조회할 수 있다.
  두 개를 채워야 ‘완료’하는 비교 절차를 만들지 않는다. 후보 삭제 뒤에도 달력과 정상 자료를 유지한다.
- **A7. 공휴일 범위 밖·등록 행사 0건:** 공휴일 정보가 없는 날짜를 평일이나 휴일 없음으로 확정하지 않는다.
  등록 행사 0건은 조회 완료한 지역·기간의 결과이며 실제 모든 행사 부재를 뜻하지 않는다. 연월·지역·후보 기간 변경을 제공한다.
- **E1. 날짜 오류:** 시작일이 종료일보다 늦지 않은지 확인하며 같은 날 시작·종료하는 후보도 허용한다. 잘못된 후보의 입력은 유지하고 해당 필드에서 수정하게 한다.
  다른 후보와 기존의 정상 달력 결과를 지우지 않으며 날짜를 자동으로 다른 날로 바꾸지 않는다.
- **E2. 제공처·지도 실패:** 실패한 자료 영역에 재시도를 제공한다. 정상 방문·자원·일정은 유지한다.
  지도 배경 실패는 이름·주소 목록으로 계속 탐색한다. 같은 조건 재시도는 임시 자원 선택과 위치 기준점을 임의로 해제하지 않는다.
- **E3. 지역 변경·늦은 응답:** 이전 지역의 함께 보기와 위치 기준점은 해제하고 새 지역 자료를 조회한다.
  달력 연월·후보 날짜 등 지역과 독립인 조건은 유지하되 조회 결과는 새 지역으로 바꾼다.
  선택한 관측연도는 유지한다. 해당 연도 자료가 없거나 불완전하면 유효 자료와 해당 영역의 상태·연도 변경을 제공하며 다른 연도로 자동 대체하지 않는다.
  이전 지역의 늦은 성공·오류가 새 제목·지도·목록·차트를 덮지 않도록 요청 조건에 결속한다.
- **E4. 개인 저장 불가:** 임시 선택·함께 보기·달력 탐색은 기록을 저장하지 않아도 가능하다.
  별도로 선택한 개인 기록의 실패는 [UC-FC-008](UC-FC-008.md)의 계약이며 이 흐름을 중단시키지 않는다.

## 조회·임시 선택 상태

업무 승인·개최 확정 상태를 만들지 않는다. 아래 상태는 이 탐색 화면 안에서만 사용한다.

| 상태·변화 | 결과·회복 경로 |
|---|---|
| 지역 미선택 → 선택 → 조회 중 | 지역 자원을 요청하고 해당 지역의 가용 방문 기간을 확인한다. 지역 선택을 되돌릴 수 있다. |
| 조회 중 → 정상·빈 결과·실패 | 결과의 종류를 구분한다. 실패는 재시도하고 빈 결과는 조건을 바꾼다. 독립된 정상 자료는 유지한다. |
| 함께 보기 0개 ↔ 1개 ↔ 2개 | 추가·해제가 가능하다. 두 개에서 추가하려면 기존 선택을 해제한다. 기획안·개최장소를 생성하지 않는다. |
| 위치 기준점 없음 ↔ 명시적 위치 선택 | 기준점이 있을 때만 거리 정보를 계산한다. 해제하면 지역 탐색으로 돌아간다. |
| 후보 없음 ↔ 후보 1개 ↔ 후보 2개 | 어느 상태에서도 달력을 볼 수 있다. 후보를 삭제해도 다른 후보와 달력 탐색은 유지한다. |
| 같은 지역의 화면 이동 | 임시 선택·유효 조건을 유지하고 해당 화면의 정보만 새로 보여준다. 저장은 전제 조건이 아니다. |
| 다른 지역 선택 → 새 조회 | 지역 종속 선택·중심은 초기화한다. 선택한 관측연도는 유지하고 해당 자료가 없으면 연도 변경을 제공하며 달력 연월·후보 날짜는 유지한다. 이전 응답은 폐기한다. |

## 사후 상태와 검증

사용자가 선택한 지역·조회 조건과 그에 맞는 자료가 화면에 남는다. 자원과 기간은 임시 탐색 상태이며,
기획안·개최장소·최적일·목표 관광객을 시스템이 확정하지 않는다. 기록이나 후보 선택 없이 지역 정보를 살펴본 상태도 정상 완료다.

FR-NEW-1~4는 **구현·자동 인수 시험 통과**다. 인수 시나리오 [TS-FC-010](../../3-testing/scenarios/TS-FC-010.md)은
Node 24.20.0·Next production·격리 DB에서 실행했으며 AC1~14는 자동 시험을 통과했다. 실행 결과는 [검증 기록35](../../../validation/35-pickdday-new-festival.md)에 남긴다.
기존 지역 조회·기존 축제 UC-FC-009·저장 UC-FC-008의 시험을 이 흐름의 인수 증거로 환산하지 않는다.
정형 API 참조가 없으므로 API 계약 검증도 미평가다.

문서 수준의 흐름·문구·데이터 경계를 먼저 검수한다. 실제 화면의 키보드 동작·반응형·복구 검증은 통합 검증에서
수행하며 코드가 있다는 사실이나 이 UC 작성만으로 통과 처리하지 않는다. 최종 시각 디자인과 실제 담당자 업무 관찰은 사용자 후속이다.
