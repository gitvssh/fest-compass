# UC-FC-009 · 기존 축제의 방문 흐름·주변 자원·다음 시기를 살펴본다

2026-09-26 보강: 어떤 등록 축제를 고르든 주변 관광자원에서 음식점·숙박을 함께 살펴보고 공통 소개를 연다.
목록·지도·직선거리의 기존 조작과 기록 없는 탐색을 유지한다. [설계19](../../../design/19-tourism-resources.md)와
[TS-FC-016](../../3-testing/scenarios/TS-FC-016.md)이 추가 인수 기준이며 구현·검증 진행 중이다.

2026-09-26 사용자 정정(사용 가능): 검토된 과거 회차가 없는 축제도 방문 화면에서 그 시군구의 외지인 방문 흐름을 본다.
아래 [고른 모든 등록 축제의 공통 흐름](#고른-모든-등록-축제의-공통-흐름)과 [TS-FC-015](../../3-testing/scenarios/TS-FC-015.md)를 기존 AC와 함께 적용한다.

2026-09-24 보강: 임실N치즈축제의 회차를 적용하면 지역 전체 일별 차트 아래 별도 개최 행정동 방문 구성을 읽는다.
구분별 일평균·외지인 비율을 비교하고 필요할 때 기간 합계 표나 모든 개최연도를 연다. 기존 차트 기간 조정은
회차의 원래 집계기간을 바꾸지 않는다. 미확인 자료 입력이나 기획안 저장은 필요 없다.
[상세 계약](../../2-design/functional-spec.md#9-방문-구성과-지역-연간-추세)과
[추가 시나리오 TS-FC-012](../../3-testing/scenarios/TS-FC-012.md)를 기존 AC와 함께 적용한다.

## 사전 조건

- 사용자는 개인 기록·기획안·메모가 없는 상태로 시작할 수 있다. 가입·위치 권한·업무 목적 서술을 선행 조건으로 두지 않는다.
- 최소 조회 조건은 선택할 축제와 그 지역이다. 후보 기간·지도 중심은 해당 정보가 필요한 탐색에서 선택한다.
- 축제 목록과 회차는 확인된 원천으로 식별한다. 같은 이름만으로 현재 콘텐츠와 과거 회차를 합치지 않는다.
- 자료별 사용 가능 범위와 미연결 항목은 [데이터 현황](../../../research/2026-09-data-inventory.md)을 따른다.
  자료가 없는 지역을 논산 표본으로 자동 대체하지 않는다.

## v2 기능 상세 연결

[기능 상세](../../2-design/functional-spec.md)는 검색·조건 유지·월별 상세와 실제 연월 일정 연결·자료 갱신·복구의 정본이다.
전체 14개 기준의 실행 시나리오는 [TS-FC-009](../../3-testing/scenarios/TS-FC-009.md), 자동 시험과 운영 확인은 [검증 기록](../../../validation/34-existing-festival-journey.md)을 따른다. 기존 회차/지역·지표 정의와 기록 선택 경계는 유지한다.
최종 시각 디자인은 사용자가 진행하며 이번 산출물은 화면 목표·기본 배치·상태 와이어프레임까지다.

## 기본 흐름

1. 첫 화면에서 **기존 축제 개선**을 선택하고 축제를 찾는다. 검색 결과는 지역과 이름으로 구분한다.
   축제를 선택하면 지역과 가용 회차를 연결하고 최신 비교 가능한 두 회차를 기본 선택한다.
   현재 논산 보관본의 기본 회차는 2025·2024다. 첫 화면의 다른 선택지인 새 축제 기획은 [UC-FC-010](UC-FC-010.md)의 별도 전용 흐름이며 이 흐름을 대체하지 않는다.
2. **과거 방문 흐름**에서 회차별 일별 차트와 행사기간 요약을 본다. 기본 표시 구간은 행사 시작 7일 전부터 종료 7일 후다.
   작은 차트를 회차별로 나누고 같은 Y축을 쓴다. 각 차트에는 실제 날짜·요일과 그 회차의 행사기간을 표시한다.
   평균·일최대·결측·반올림은 [시각화 계약](../../2-design/data-visualization.md)을 따른다.
3. 비교 회차를 바꾸거나 실제 수치 표·출처를 연다. 2023의 5일과 2024·2025의 4일, 평일·주말 구성 차이를 확인할 수 있다.
   행사기간이 다른 회차를 공통 기간의 총방문객으로 합치거나 일별 합계를 고유 방문객으로 표시하지 않는다.
4. **주변 관광자원**으로 이동하면 축제의 지역을 기본 범위로 현재 등록 관광지·문화시설을 지도와 목록에서 본다.
   확인된 행사장 좌표가 없으면 지역 목록부터 탐색한다. 장소 또는 지도 중심을 선택하면 그 중심과 조회된 자원 사이의 직선거리를 볼 수 있다.
   중심 선택은 검색 조건이며 기획안 작성이나 저장을 요구하지 않는다.
5. **다음 개최 시기**에서 과거 연도별 월간 일평균과 실제 연월 달력을 살펴보고 원할 때 미래 후보 기간을 선택한다.
   후보가 없어도 달력·일정 탐색을 제공하고 후보 하나도 요일·공휴일·주변 등록 행사를 확인할 수 있다.
   과거 월별 일평균을 미래 날짜의 방문 전망으로 투영하거나 일정 겹침에 경쟁 점수를 붙이지 않는다.
6. 사용자는 세 탐색 화면을 원하는 순서로 오가며 조건을 바꾸고 비교를 마친다. 답변·선택 이유·메모·기획안을 남길 필요가 없다.
   자료 담기·개인 기록은 원할 때 선택할 수 있으나 누르지 않아도 이 유스케이스의 목적을 달성한다.

## 대안·예외 흐름

- **관련 자료 찾기 · 2026-09-24 추가:** 확인된 축제 머리에서 `관련 자료 검색`을 열고 프로그램·운영 결과·보도자료를 찾는다.
  방문 화면의 적용 회차가 하나면 해당 연도, 비교 중이면 연도 전체로 시작한다. 검색어를 조정해 DuckDuckGo 새 탭을 열며
  돌아오면 기존 조회 조건을 유지한다. 외부 결과를 공공 통계로 가져오지 않는다. 상세·독립 검증은
  [기능 상세 §8](../../2-design/functional-spec.md#8-관련-자료-검색원문-연결)·[TS-FC-011](../../3-testing/scenarios/TS-FC-011.md)을 따른다.
- **A1. 초기 검색 또는 결과 없음:** 축제 미선택 상태에서는 선택할 대상을 찾는 행동을 제공한다. 검색 결과가 없으면
  검색어·지역을 바꿀 수 있고 개인 축제 등록이나 설명 작성을 요구하지 않는다. 확인한 목록의 결과 없음과 실제 축제 부재를 구분한다.
- **A2. 가용 회차가 한 개 또는 없음:** 있는 회차는 단독으로 볼 수 있다. 방문 자료가 없으면 짧은 상태와 회차 변경·다른 탐색 이동을 제공한다.
  다른 지역 값이나 가상 곡선을 대신 채우지 않는다. 기본 두 회차 선택은 실제 비교 가능한 회차가 있을 때만 적용한다.
- **A3. 일부 방문값 누락·정의 차이:** 누락 지점에서 선을 끊는다. 평균·일최대의 표시 또는 보류와 분모는 시각화 계약을 따른다.
  서로 다른 지역·지표를 동일 기준의 증감이나 순위로 계산하지 않는다. 정상 자료·출처 열기·화면 이동은 유지한다.
- **A4. 좌표 없음·지도 배경 실패:** 좌표 없는 자원은 이름·주소 목록에 남긴다. 중심점이 없으면 거리순·반경 결과를 만들지 않는다.
  지도 배경을 못 불러와도 같은 자원을 목록으로 탐색한다. 음식점·숙박 등 아직 연결하지 않은 종류를 있는 자료로 채우지 않는다.
- **A5. 공휴일 범위 밖·행사 빈 결과:** 공휴일 자료 미확보는 공휴일 없음과 다르다. ‘조회한 등록 행사 0건’은 실제 행사 부재를 뜻하지 않는다.
  달력·후보 기간 변경 또는 SCR-FC-001에서 다른 지역을 살펴보는 행동을 제공한다. 원래 축제의 지역·회차·방문 조건은 유지해 복귀한다.
- **E1. 한 제공처·지역 조회 실패:** 실패한 결과 영역에 어떤 정보를 못 불러왔는지와 재시도 행동을 표시한다.
  정상 보관 방문이나 성공한 지역 결과를 함께 지우지 않는다. 다시 조회해도 조회 조건을 임의로 바꾸지 않는다.
- **E2. 로딩 중 조건 변경:** 화면마다 해당 조회에 영향을 주는 축제·지역·회차·기간·중심 조건을 같은 요청 버전에 묶는다.
  조건을 바꾸면 새 로딩 상태를 표시하고 이전 조건의 지연 응답을 적용하지 않는다. 이전 결과를 남길 때에는 이전 조건임을 구분한다.
- **E3. 개인 저장 사용 불가:** 개인 기록을 선택하지 않은 탐색은 계속된다. 선택적 기록의 실패·복원은
  [UC-FC-008](UC-FC-008.md)의 별도 계약이며 이 유스케이스의 완주를 막지 않는다.

## 조회 상태와 결과 유지

이 유스케이스는 승인·결재 등 업무 엔티티의 상태를 전이시키지 않는다. 아래는 화면의 조회 상태 계약이다.

| 상태·변화 | 표시와 허용되는 행동 |
|---|---|
| 초기 → 조회 중 | 필요한 조회 조건을 선택한다. 요청 중임을 실제 상태로 알리고 조건 변경·다른 탐색 이동을 유지한다. |
| 조회 중 → 결과 있음 | 현재 요청 조건의 결과만 함께 반영한다. 단위·실제 기간·선택 상태를 결과와 일치시킨다. |
| 조회 중 → 결과 없음·자료 미확보 | 두 상태를 구분한다. 검색 조건 변경이나 다른 탐색을 제공하며 값 0으로 대체하지 않는다. |
| 조회 중 → 일부 실패·전체 실패 | 실패 영역에 재시도를 제공한다. 다른 자료의 정상 결과·선택 조건은 유지한다. |
| 실패 → 재조회 → 결과 있음 | 재시도가 성공한 현재 조건의 영역을 갱신한다. 이전 요청의 늦은 성공·실패를 새 결과에 적용하지 않는다. |
| 임의 상태 → 조건 변경 → 조회 중 | 최신 조건의 요청으로 전환한다. 이전 조건 값이 새 제목·축·지도·목록 아래에 섞이지 않게 한다. |

## 사후 상태와 검증

선택한 축제와 조회 조건에 맞는 정보·비교 결과가 화면에 남는다. 개인 기록을 선택하지 않았다면 기획안·메모·근거를
저장하지 않은 상태도 정상 완료다. 제공한 정보로 어떤 관광객을 유치할지, 무엇을 바꿀지는 사용자가 판단한다.

이 문서는 [요구사항](../srs.md)의 FR-EXF-1~4를 실현하는 유스케이스다. 체크한 AC1~14는
[TS-FC-009](../../3-testing/scenarios/TS-FC-009.md)의 자동 인수 시험(실제 논산 보관값과 통제한 실패·응답 경합)으로 확인했으며
결과는 [검증 기록34](../../../validation/34-existing-festival-journey.md)를 따른다. 정형 Spec/Run 식별자는 아직 없고 실무자 업무 인수는 미실시다.
기존 UC-FC-001/002의 조회 시험이나 UC-FC-008의 저장 시험으로 이 기준을 통과 처리하지 않는다.
`apis: []`는 OpenAPI 정형 연결을 선언하지 않았다는 뜻이며 API 검증 통과가 아니다.

화면 구성·이동은 [화면 목록](../../2-design/screens.md), [흐름](../../2-design/flows.md)을 따른다.
자료 산식과 표시 조건은 [시각화 계약](../../2-design/data-visualization.md),
공통 표현은 [디자인 기준](../../2-design/design-system.md)을 따른다.
기존 비교 화면(`/compare`)의 시작일 ±7일 15점과 달리 이 흐름의 회차 차트는 행사 전 7일~종료 후 7일을 사용하며,
회차별 전체 일수(18·19일 등)는 검증 기록34에서 원자료와 대조했다.

## 임실 2025년 방문자 특성 보강

2025년 회차가 적용된 사용자는 개최기간 성·연령 비율과 목적지 검색순위를 살펴본다.
목적지 구분을 바꾸고 확인된 장소를 누르면 현재 관광자원 화면의 해당 상세로 이동한다. 기록은 필요하지 않다.
대상 유형 조회가 실패하면 재시도하고, 성공한 목록에 장소가 없으면 결과 안내와 기존 목록을 유지한다.
다른 회차·지역에 이전 특성을 남기지 않으며 뒤로가기에서 회차·표시 조건을 보존한다.
[TS-FC-013](../../3-testing/scenarios/TS-FC-013.md)의 VP1~8로 검증하고 [기록38](../../../validation/38-visitor-profile.md)에 결과를 남긴다.
이 절은 2025년 한 회차의 기록이며 해당 표시는 계속 사용 가능하다. 적용 회차에 따른 표시 조건은 아래 절이 대체한다.

## 임실 두 회차 방문자 특성 비교 · 사용 가능

상태: **사용 가능 — 원자료·구현·공개 검증 완료.**

1. 사용자가 기존 회차 선택에서 임실N치즈축제의 두 회차(예: 2024·2025)를 적용한다.
2. 방문 구성 아래에서 두 회차의 하루 평균·외지인 비율 차이를 읽는다.
3. `방문자 특성 · 2024년과 2025년`에서 두 회차의 날짜·일수와 같은 성수면·내국인 기준을 확인하고, 연령대별 두 해 막대와 값을 비교한다.
   필요하면 수치 표에서 %p 차이를 본다.
4. 목적지 검색순위에서 구분을 고르고 장소별 두 해 순위와 `2위 상승`·`1위 하락`·`같음`·`—`을 읽는다.
   확인된 장소는 현재 관광자원 상세로 이동하고 돌아와 비교를 이어간다.
5. 판단은 사용자가 한다. 기록·저장·선택 이유 없이 끝낼 수 있다.

- **한 회차만 적용:** 그 연도의 기존 한 회차 표시를 그대로 본다.
- **세 회차 적용:** 선택은 그대로 두고 확인된 최근 두 회차를 비교한다. 제목은 비교하는 두 연도다. 방문 구성은 세 회차를 모두 보이고 요약만 최근 두 회차다.
  다른 두 회차를 비교하려면 회차 선택에서 그 두 회차를 고른다.
- **적용 회차에 확인 자료 없음:** 방문자 특성 영역 없이 다른 방문 정보와 세 메뉴를 계속 쓴다.
- **한 회차 자료만 검증 실패:** 그 회차만 빠지며 남은 회차 수에 따라 위 규칙을 따른다. 고객 화면에 사유 배너를 두지 않는다.
- **한 해에만 있는 장소:** 없는 해는 `—`로 두고 0이나 신규로 표시하지 않는다.

기존 AC1~14는 바꾸지 않는다. 인수 기준은 [TS-FC-014](../../3-testing/scenarios/TS-FC-014.md), 기능 상세는
[§11](../../2-design/functional-spec.md#11-두-회차-방문자-특성-비교), 결과는 [기록39](../../../validation/39-edition-profile-comparison.md)를 따른다.

## 고른 모든 등록 축제의 공통 흐름

상태: **사용 가능.** 구현·시험·공개 확인을 마쳤다. [검증 기록40](../../../validation/40-unified-festival-analysis.md)을 따른다.
기존 AC1~14와 그 검증(기록34)은 유지한다. 이전 판에서 과거 회차가 없는 현재 등록 축제가 방문 화면에 짧은 기록 없음 상태만 보이던 동작은 이 절이 대체한다.

1. 사용자가 검색에서 어떤 등록 축제든 고른다. 같은 축제로 검토된 과거 회차가 있으면 결과는 현재 카드 하나이며 과거 개최연도가 함께 보인다.
2. **과거 방문 흐름**에서 축제가 등록된 시군구의 `<시군구> 외지인 방문 흐름`을 본다. 연도를 고르고 월별 하루 평균을 읽은 뒤,
   월을 고르면 그 달의 일별 선과 수치 표가 열린다.
3. 제공처에 실제 등록된 일정이 있으면 `등록된 일정`에서 그 연월로 바로 이동한다. 등록 일정은 개최 확정이나 회차로 표시하지 않는다.
4. 검토된 과거 회차가 연결된 축제는 같은 화면에서 기존 회차 비교(기본 흐름 2~3)를 본다. 축제 이름·경로는 고른 현재 축제 그대로다.
5. 관광자원·개최 시기는 기존 흐름(4~6)과 같다. 기록·저장 없이 끝낼 수 있다.

- **축제 확인 중:** 확인 중 상태만 보이고 기록 없음 문구를 먼저 띄우지 않는다.
- **시군구 자료 없음 또는 조회 실패:** 방문 자리만 짧은 상태·재시도를 두고 관광자원·개최 시기로 계속 이동한다.
- **등록 일정 없는 연도:** 바로가기 없이 연도·월을 직접 고른다. 올해 날짜로 과거 기간을 만들지 않는다.
- **이름만 같은 축제:** AC11대로 별도 대상이며 과거 회차를 붙이지 않는다. 시군구 방문 흐름은 각자 자기 지역으로 제공한다.
- **특정 축제 보조 자료:** 임실 방문 구성·방문자 특성·회차 비교는 그 축제에서만 보인다. 다른 축제에 빈 영역을 두지 않는다.

인수 기준은 [TS-FC-015](../../3-testing/scenarios/TS-FC-015.md), 기능 상세는
[§12](../../2-design/functional-spec.md#12-고른-축제-모두의-공통-분석-흐름), 설계는 [통합 설계 18](../../../design/18-unified-festival-analysis.md)을 따른다.
