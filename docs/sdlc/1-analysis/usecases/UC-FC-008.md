# UC-FC-008 · 개인 기획을 저장하고 다른 기기로 옮긴다

| 항목 | 내용 |
|---|---|
| 액터 | 지자체 축제 담당자 |
| 목적 | 기획 자료를 잃지 않고 저장 위치를 이해한다. |
| 구현 상태 | 개발 필요. active는 유효한 요구이며 구현 완료가 아님 |

## 사전 조건

개인 브라우저 저장을 사용할 수 있거나 파일 보관 경로가 제공된다.

## 기본 흐름

1. 기획을 수정하고 저장 상태와 위치를 확인한다.
2. 파일로 내보낸 후 다른 빈 브라우저에서 가져온다.
3. 교체될 목록과 데이터 범위를 확인한 뒤 복원한다.
4. 저장 실패나 탭 충돌이 발생하면 입력 보관 또는 다시 읽기를 선택한다.

## 대안·예외 흐름

손상된 파일·중복 ID·끊긴 근거 참조·크기 초과는 기존 자료를 교체하지 않는다. 저장소 접근 거부는 파일 보관으로 복구한다. 다른 탭 변경은 자동 덮어쓰기를 중단한다.

## 수용 기준

- [ ] AC1: Given 개인 기획을 편집할 때 When 저장하면 Then 위치와 결과를 표시하고 공개 서버에 개인 기록 쓰기를 보내지 않는다.
- [ ] AC2: Given 파일 복원 요청이 있을 때 When 구조·ID·참조 검증에 실패하거나 교체를 취소하면 Then 기존 자료를 그대로 유지한다.
- [ ] AC3: Given 저장 실패나 다른 탭의 변경이 있을 때 When 입력을 계속하면 Then 충돌·실패를 알리고 파일 보관 또는 다시 읽기로 복구할 수 있다.

## 사후 상태와 검증

사용자가 선택한 기록이 개인 저장 경계 안에 남고 이전 보관본은 유지된다.
검증: [TS-FC-008](../../3-testing/scenarios/TS-FC-008.md). 미실행이며 실행 API·명세는 구현 단계에서 연결한다.
