# TS-FC-011 · 관련 자료 검색·원문 연결

[기능 명세 §8](../../2-design/functional-spec.md#8-관련-자료-검색원문-연결)의 관련 자료 검색을 확인한다.
별도 유스케이스가 없어 기준 번호 `RS1`~`RS12`는 이 문서 안에서만 쓴다. **상태: 관련 검색 25항목 자동 검증 통과.**
자동 시험 `apps/web/scripts/related-search-e2e.mjs`(headless)는 저장소 실행기에 등록했다. 실행 대상·결과는
[검증 기록36](../../../validation/36-related-material-search.md)에 남기며, 이 문서만으로 통과를 주장하지 않는다.
요소는 합의된 화면 문구와 접근 가능한 이름으로만 찾고 구현 내부 구조나 요소 개수에 기대지 않는다.

## 자료와 실행 경계

| 구분 | 대상 | 시험에서의 성격 |
|---|---|---|
| 실제 보관본 | 지난 회차 축제 조회(`/api/existing/festivals`의 archive id), 방문·월별·일정, `/api/new/visits` | 서버 응답을 그대로 통과시킨다. 논산딸기축제 회차 연도(2025·2024·2023)와 지역 이름은 `apps/web/data`에서 독립으로 읽는다. |
| 검증용 응답 | 현재 등록 축제 식별 조회(일정 확인 1건·미확인 1건·없음 1건), 관광자원 목록·소개, 지도 타일 | 이름·주소에 `검증용`/`(가상)`을 붙인다. 화면 의미만 증명하며 공개 제공처의 실제 결과로 표시하지 않는다. |
| 검증용 DuckDuckGo 도착지 | `duckduckgo.com`으로 가는 모든 요청 | 시험이 가로채 `검증용 DuckDuckGo 도착지 (가로챈 시험 응답 · 실제 검색 결과 아님)` 문서로 응답한다. 링크의 이동 의미(주소·referrer·opener)만 증명하고 검색 결과를 증명하지 않는다. |
| 운영 확인 | 실제 DuckDuckGo 검색 화면 | 주 담당자가 별도로 확인한다. 봇 확인 화면이 관찰됐으며 우회하지 않는다. |

- 실행 서버는 공개 읽기 전용 모드이며 공공데이터 키가 없다. 같은 출처 비GET 요청은 0건이어야 한다.
- 응답 순서는 요청 보류·해제로 정한다(시간 대기로 순서를 정하지 않음). 한글 조합 중 Enter는 조합 표시가 있는 keydown을
  직접 보낸 뒤 확정 Enter를 눌러, 새 탭이 정확히 하나만 열렸다는 순서로 판정한다.
- 증거: `apps/web/output/playwright/related-search-e2e.json`(통과 항목, 새 탭마다 실제 주소·`document.referrer`·`window.opener`·Referer 헤더),
  `related-search-festival-{320,390,1440}.png`, `related-search-resource-{320,390,1440}.png`.

## 기준별 시나리오

| 기준 | 자료 | 사용자 행동·확인할 결과 | 시험 위치 · 상태 |
|---|---|---|---|
| RS1 | 실제 보관본 | 첫 축제 조회를 보류한 동안(`축제 정보`)과 조회 실패 뒤에는 `관련 자료 검색` 버튼이 없다. `다시 불러오기`로 확인되면 버튼이 보인다. 보관본에 없는 축제와 현재 등록에서 찾지 못한 축제(`선택한 축제를 찾지 못했어요`)도 버튼이 없다. 페이지를 여는 것만으로 DuckDuckGo 요청·미리 연결이 없다. | `verifiedOnly`, `notFound` · 통과 |
| RS2 | 실제 보관본 | 버튼의 보이는 글자는 `관련 자료 검색`, 이름과 창 제목은 `논산딸기축제 관련 자료 검색`. 키보드 Enter로 연다. 찾을 내용 `전체`/`프로그램`/`운영 결과`/`보도자료`, 연도 `연도 전체`/`2025년`/`2024년`/`2023년`, 기본은 `전체`·`연도 전체`(주소 없는 기본 비교 두 회차). `검색어`에 축제명 → `충청남도 논산시`(한 번) 순서, 연도·주제 없음, `새 탭에서 검색 결과가 열려요.` | `existingDialog` · 통과 |
| RS3 | 실제 보관본 | 주제·연도를 바꿀 때마다 검색어가 다시 만들어진다(연도는 선택한 한 해만). 직접 고친 뒤 주제를 바꾸면 새 검색어로 덮인다. 연도·주제를 바꾸고 고친 채 Esc로 닫고 다시 열면 기본 상태로 돌아온다. 닫기 버튼·Esc 모두 초점이 실행 버튼으로 돌아간다. | `existingDialog` · 통과 |
| RS4 | 실제 보관본 | 주소의 적용 회차가 하나(`editions=…2023`, `…2025`)이면 그 연도가 기본. 세 회차 비교, 없는 회차(`…2019`), 일부만 유효, 같은 매개변수 두 번(같은 값·다른 값)은 `연도 전체`이며 2019를 만들지 않는다. 회차 선택 `적용`으로 하나가 되면 다음 열 때 그 연도. | `editionAddress` · 통과 |
| RS5 | 실제 보관본·실제 일정 | 방문 화면 2023 → `개최 시기`에서 관측연도 2024, 2025 회차 기간 안의 후보 추가 → `연도 전체`, 검색어에 연도 없음, 연도 선택지는 회차 연도뿐. 관측연도·후보는 그대로다. `주변 관광자원`도 `연도 전체`, 방문 화면으로 돌아오면 다시 2023. | `otherViews` · 통과 |
| RS6 | 실제 보관본 | `논산 & 딸기 #2025 + 체험 후기`처럼 고친 검색어는 `%26`·`%23`·`%2B`로 인코딩되고 링크의 `q`를 되읽으면 입력과 같다. 링크는 `https://duckduckgo.com/`의 `q` 하나뿐, `target=_blank`, `rel`에 `noopener`·`noreferrer`, `referrerpolicy=no-referrer`, `ping` 없음. 빈 값·공백만이면 링크 대신 `검색어를 입력해 주세요.`이고 Enter도 아무것도 열지 않는다. `기본 검색어로`는 고쳤을 때만 보이고 기본으로 되돌린다. | `editableAndExternal` · 통과 |
| RS7 | 검증용 도착지 | 링크 클릭과 검색어 칸 Enter만 새 탭을 하나 연다. 조합 중 Enter는 열지 않는다. 새 탭의 주소는 표시된 검색어를 담고, `document.referrer`가 비어 있으며 `window.opener`가 null이고 Referer 헤더가 없다. 원래 탭의 주소·회차 선택·창 속 검색어는 그대로다. | `editableAndExternal` · 통과 |
| RS8 | 검증용 현재 등록 | 일정이 확인된 현재 등록 축제는 연도 선택지 `2026년`(시작 연도)만 있고 기본 `연도 전체`. 일정 미확인은 연도 선택지가 없다. 검색어에 등록 번호·주소가 없다. | `currentFestivals` · 통과 |
| RS9 | 검증용 자원 | 새 축제 머리 `충청남도 논산시 관련 자료 검색`: 찾을 내용 `전체`/`관광사업`/`축제 사례`, 연도 입력 없음, 지역 이름 한 번. 자원 상세의 `검증용 관광지 가 (가상) 관련 자료 검색`: `전체`/`행사`/`축제`, 자원명 → 지역 순, 주소·ID 없음. 자원 검색 새 탭 뒤에도 상세·목록 선택이 그대로다. | `newRegionAndResources` · 통과 |
| RS10 | 검증용 자원·실제 지역 | 다른 자원을 열면 이전 자원의 버튼·입력이 사라지고 새 자원 이름으로 `전체`부터 시작한다. `지역 바꾸기`로 공주시에 가면 논산 지역·자원 검색이 사라지고 `충청남도 공주시`로 시작한다. 이름이 여러 시도에 있는 `서울특별시 중구`도 전체 이름을 한 번 쓴다. | `newRegionAndResources` · 통과 |
| RS11 | 혼합 | 320·390·1440px에서 축제 창과 자원 창(긴 검색어·빈 검색어 포함)이 화면 안에 있고 창 안 요소가 창 밖으로 나가거나 가로 스크롤이 생기지 않으며 문서 가로 넘침이 없다. Tab으로 검색어·주제·링크·닫기에 모두 닿고 초점이 창 밖으로 나가지 않는다. 방향키로 주제를 바꾸면 검색어가 바뀐다. | `layouts` · 통과 |
| RS12 | 전체 | 창 안 조작(주제·연도·입력·지우기·기본 복구)은 앱 API·다른 호스트 요청을 만들지 않는다. 입력한 검색어는 앱 주소·브라우저 저장소·앱/분석 요청 어디에도 없고 DuckDuckGo 새 탭에만 전달된다. DuckDuckGo 이동 수는 명시적 사용자 행동 수와 같다. 같은 출처 비GET 0건, 브라우저 오류 0. | 실행 마지막 공통 단언 · 통과 |

공통으로 확인할 것: 검색어에 축제·회차·등록·자원 ID, 지역 코드, 주소, 좌표, `undefined`·`null`·`NaN`, `새 축제` 같은 화면 이름이 들어가지 않는다.
연도를 선택하지 않은 조건에는 회차 연도를 자동으로 덧붙이지 않는다. 원래 공개 이름에 포함된 숫자는 유지한다.
검색 입력칸의 긴 문자열을 커서로 좌우 이동하는 기본 동작은 허용한다. 입력칸 자체·창·문서가 화면 밖으로 넘치는 것과 구분한다.

## 자동 시험 실행 연결

- 실행: 저장소 실행기(`npm run test:e2e` → `scripts/run-demo-e2e.mjs`)가 공개 읽기 전용 서버에서 `new-festival-e2e.mjs` 다음에 부른다.
  성공하면 통과 항목과 새 탭 증거 개수를 JSON 한 줄로 출력하고 위 증거 파일을 쓴다. 실패는 해당 단언 메시지로 멈춘다.
- 스크립트는 시작 시 보관본에서 논산 회차 연도와 `중구`가 여러 시도에 있다는 사실을 먼저 확인한다.
- 시험이 확인하지 않는 것: 실제 DuckDuckGo 결과·순위·원문 제공 여부, 실제 IME 입력기의 조합 이벤트(합성 keydown으로 대체),
  같은 축제의 이전 정보가 남은 채 갱신만 실패한 상태의 검색 가능 여부, 창이 열린 동안 대상이 사라지는 경우, 실무 담당자 사용성.

## 운영 확인과 미평가 구분

1. 공개 주소에서 기존 축제·새 축제 지역·자원 상세의 버튼과 창이 같은 문구로 보이는지, 320/390px·키보드 동작.
2. 실제 DuckDuckGo 새 탭이 표시된 검색어로 열리는지. 봇 확인 화면이 나오면 그대로 기록하고 우회하지 않는다.
3. 공개 서버 CSP·분석 연결에서 검색어가 전송되지 않는지.

최종 시각 디자인과 실무 담당자 관찰은 별도 작업이다. 정형 Spec/Run 식별자는 선언하지 않는다.
