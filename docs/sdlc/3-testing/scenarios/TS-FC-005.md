# TS-FC-005 · 준비 내역과 항목별 예산을 비교한다

| 항목 | 내용 |
|---|---|
| 근거 | [UC-FC-005@v1](../../1-analysis/usecases/UC-FC-005.md) |
| 대상 환경 | 구현 후 격리된 로컬 브라우저 + 고정 자료 응답 |
| 실행 상태 | 미실행. 신규 기능과 실행 명세 개발 필요 |

## 데이터와 사전 조건

프로그램 2×100000원, 시설 1×300000원, 홍보 단가 null, 한도 450000원을 둔다. 홍보를 0으로 바꾸고 다시 null로 바꾼다. 수량 1.5와 단가 1001원으로 반올림 사례도 둔다.
가상 데이터만 사용한다. 실제 API 자격·외부 기관 연락·공유 운영 자료 변경은 필요하지 않다.

## 실행할 과제와 기대 결과

확인 합계 500000원, 초과 50000원, 미산정 1건을 확인한다. 명시적 0원 입력 후만 미산정이 사라져야 한다. 1.5×1001원은 1502원이며 음수는 거부한다.

| 순서 | 사용자 과제 | 판정할 인수 기준 |
|---|---|---|
| 1 | 후보별 항목·수량·단가·세금 기준·출처를 입력한다. | AC1 |
| 2 | 확인 합계와 미산정 항목 수를 확인한다. | AC2 |
| 3 | 예산 한도를 입력하고 후보별 초과액과 다른 비용 항목을 비교한다. | AC3 |
| 4 | 운영 제약을 확인해 선택 이유와 함께 기획안으로 넘긴다. | AC3 |

## 실패·복구 확인

음수·유효하지 않은 숫자는 저장을 거부하며 입력을 유지한다. 수량/단가 결측은 총액 미확정이다. 세금 기준 혼재는 확정 총액 표시를 막고 기준 통일을 안내한다. 인력·셔틀 증가만으로 안전 효과를 산출하지 않는다.
실패 입력을 한 뒤 기존 보관본과 다른 회차가 유지되는지 확인한다.

## 실행 증거와 정리

현재 Run은 없다. 개발 후 실행 파일과 결과를 specs·보고서 경로로 연결한다.
새 인수 기준은 기존 운영 E2E 결과로 통과 처리하지 않는다.
독립 브라우저 저장·고정 응답만 사용하고 종료 시 테스트 컨텍스트를 닫는다.
