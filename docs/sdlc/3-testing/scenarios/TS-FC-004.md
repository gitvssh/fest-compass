# TS-FC-004 · 아이템·장소·시기가 다른 기획 대안을 구성한다

| 항목 | 내용 |
|---|---|
| 근거 | [UC-FC-004@v2](../../1-analysis/usecases/UC-FC-004.md) |
| 대상 환경 | 구현 후 격리된 로컬 브라우저 + 고정 자료 응답 |
| 실행 상태 | 미실행. 신규 기능과 실행 명세 개발 필요 |

## 데이터와 사전 조건

같은 가상 지역에 '봄꽃 산책'과 '지역 먹거리 체험' 후보를 만든다. 장소 A의 사용 가능 여부는 미확인, 장소 B는 담당자 확인 메모만 있다.
가상 데이터만 사용한다. 실제 API 자격·외부 기관 연락·공유 운영 자료 변경은 필요하지 않다.

## 실행할 과제와 기대 결과

미확인 장소가 승인 완료로 표시되지 않아야 한다. 두 후보의 근거 ID와 담당자 메모가 뒤섞이지 않고 선택된 탐색 지역을 바꿔도 기획 담당 지역은 유지한다.

| 순서 | 사용자 과제 | 판정할 인수 기준 |
|---|---|---|
| 1 | 봄꽃 산책과 먹거리 체험 두 후보를 같은 항목으로 비교한다. | AC1 |
| 2 | 자료 출처·담당자 가정·장소 미확인을 구분해 연결한다. | AC2 |
| 3 | 다른 지역을 탐색하고 새 버전을 작성해도 담당 지역·이전 보관본이 유지되는지 확인한다. | AC3 |

## 공개 사례 반영 추가 과제

| 인수 기준 | 고정 입력·행동·기대 결과 |
|---|---|
| AC4 | 2027년 관광부서 계속사업에 재단 수행 관계와 무대 업체 용역 관계를 각각 추가한다. 재원 확인 전에도 초안을 저장하며 보조사업 분류가 자동 생성되지 않는지 확인한다. |
| AC5 | 설치 4/9, 행사 4/10~11, 철거 4/12를 입력하고 행사 기간만 사용 가능으로 확인한다. 설치·철거는 미확인으로 유지한다. 종료일이 시작일보다 이르면 입력 오류를 표시한다. 행사 기간을 하루 늘리면 연결된 임차·안전·청소 과제가 재확인으로 나타나며 단가·효과를 자동 추정하지 않는다. |
| AC6 | 장소 확인→계약 자료 준비의 의존 관계를 둔다. 견적 참조 추가만으로 외부 검토 완료가 되지 않아야 한다. 해당 없음에는 사유가 필요하고, 자기 참조·순환 의존은 거부한다. |

추가 과제의 수치는 시험용 고정 입력이다. 실제 사례의 해석 범위는 [조사 출처](../../../research/2026-09-municipal-festival-sources.md)를 따른다. 현재 모두 미실행이다.

## 실패·복구 확인

자료가 없으면 담당자 가정으로 기록할 수 있으나 실측 근거로 표시하지 않는다. 다른 지역 사례 선택이 담당 지역을 바꾸지 않는다. 장소 사용 가능 여부가 없으면 미확인으로 남긴다.
실패 입력을 한 뒤 기존 보관본과 다른 회차가 유지되는지 확인한다.

## 실행 증거와 정리

현재 Run은 없다. 개발 후 실행 파일과 결과를 specs·보고서 경로로 연결한다.
새 인수 기준은 기존 운영 E2E 결과로 통과 처리하지 않는다.
독립 브라우저 저장·고정 응답만 사용하고 종료 시 테스트 컨텍스트를 닫는다.
