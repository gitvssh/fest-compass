# TS-FC-008 · 개인 기획을 저장하고 다른 기기로 옮긴다

| 항목 | 내용 |
|---|---|
| 근거 | [UC-FC-008@v3](../../1-analysis/usecases/UC-FC-008.md) |
| 대상 환경 | 격리된 로컬 브라우저 + 고정 자료 응답 |
| 실행 상태 | 기존 구현·자동 검증 근거 있음. 아래 전체 인수의 통합 판정·정형 Spec/Run 연결은 미완료 |

## 데이터와 사전 조건

정상 파일, 손상 JSON, 중복 후보 ID, 존재하지 않는 evidence ID, 허용 크기 초과 파일을 준비한다. 별도 브라우저 컨텍스트와 같은 출처의 두 탭을 사용한다.
가상 데이터만 사용한다. 실제 API 자격·외부 기관 연락·공유 운영 자료 변경은 필요하지 않다.

## 실행할 과제와 기대 결과

정상 복원 전 목록 확인을 거치며 취소/실패 때 기존 작업 해시가 유지된다. 쓰기 요청을 관찰해 개인 자료 전송이 없는지 확인한다. 저장소 거부 상태에서 성공 저장 배지가 나오지 않아야 한다.

| 순서 | 사용자 과제 | 판정할 인수 기준 |
|---|---|---|
| 1 | 개인 입력 저장 결과와 위치를 확인하고 네트워크에서 개인 기록 쓰기 요청 부재를 확인한다. | AC1 |
| 2 | 손상·중복 ID·끊긴 참조·과대 파일 및 복원 취소 시 기존 자료 해시를 비교한다. | AC2 |
| 3 | 두 탭 충돌·저장소 거부 후 실패 표시와 파일 보관/다시 읽기로 복구한다. | AC3 |

## 공개 사례 반영 추가 과제

| 인수 기준 | 고정 입력·행동·기대 결과 |
|---|---|
| AC4 | 정상 파일을 왕복해 단계별 금액과 '-'의 미확인 상태를 유지한다. 각각 끊긴 재원/기준 버전 참조, 과제 순환, 음수/무한대 금액, 알 수 없는 단계 값을 넣은 파일은 교체 전에 거부한다. 기존 형식은 명시한 변환 규칙이 있는 경우에만 미리보기 후 복원하며 미지원 미래 버전은 거부한다. |

추가 과제의 수치는 시험용 고정 입력이다. 실제 사례의 해석 범위는 [조사 출처](../../../research/2026-09-municipal-festival-sources.md)를 따른다. 아래 기존 실행 근거와 전체 AC 판정을 구분하며 이번 문서 정정에서 재실행하지 않았다.

## 실패·복구 확인

손상된 파일·중복 ID·끊긴 근거 참조·크기 초과는 기존 자료를 교체하지 않는다. 저장소 접근 거부는 파일 보관으로 복구한다. 다른 탭 변경은 자동 덮어쓰기를 중단한다.
실패 입력을 한 뒤 기존 보관본과 다른 회차가 유지되는지 확인한다.

## 실행 증거와 정리

정형 Run과 specs 연결은 아직 없다. 다만 실행 코드·검증 기록 자체가 없는 것은 아니다.

| 확인할 범위 | 기존 구현·검증 근거 |
|---|---|
| 구조 검증·파일 가져오기·기존 값 보존·저장량·다른 탭 변경 감지 | [기획 모델](../../../../apps/web/lib/planning/model.ts), [단위 시험](../../../../apps/web/lib/planning/planning.test.ts) |
| 파일 왕복·손상 파일 거부·저장 공간 부족·탭 변경 대응 | [headless 실행 코드](../../../../apps/web/scripts/planning-e2e.mjs), [M3 당시 결과](../../../validation/22-planning-options.md) |
| 재원·예산·결과가 추가된 버전 | [M4 검증](../../../validation/23-planning-budget.md), [M6 검증](../../../validation/25-planning-outcomes.md). 각 보고서의 실제 범위만 적용 |

전체 AC와 실행 증거의 정형 대응·실무자 인수는 후속이다. 상단 specs를 가짜 실행 식별자로 채우지 않는다.
새 인수 기준은 기존 운영 E2E 결과로 통과 처리하지 않는다.
독립 브라우저 저장·고정 응답만 사용하고 종료 시 테스트 컨텍스트를 닫는다.
