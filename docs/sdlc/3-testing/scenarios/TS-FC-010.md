# TS-FC-010 · pickDday 새 축제 기획 탐색

[UC-FC-010](../../1-analysis/usecases/UC-FC-010.md)의 14개 기준을 확인한다. **상태: 작성/미실행 — 14개 모두 미평가.**
자동 시험 `apps/web/scripts/new-festival-e2e.mjs`(headless)는 작성했지만 브라우저 실행 결과가 아직 없으므로 이 문서와 스크립트는
통과 근거가 아니다. 실행 대상·결과는 [검증 기록35](../../../validation/35-pickdday-new-festival.md)에 남긴다.
스크립트의 요소 식별은 작성 시점의 실제 화면 코드(접근 가능한 이름·제목·버튼 이름)를 따른다.

## 자료와 실행 경계

| 구분 | 대상 | 시험에서의 성격 |
|---|---|---|
| 실제 보관본 | `/api/new/visits`(일별 외지인 방문·월/요일 평균), `/api/regions`, `/api/existing/schedule`의 날짜·공휴일 | 서버 응답을 그대로 통과시킨다. 기대값은 앱 코드가 아닌 `apps/web/data`의 원자료에서 독립 계산한다. |
| 검증용 응답 | `/api/existing/resources`, `/api/new/resource-detail`, 일정 응답의 등록 행사 블록, 지도 타일, 값 0·결측 변형, 같은 날짜 공휴일 중복 | 이름에 `검증용`/`(가상)`을 붙인다. 화면 의미만 증명하며 공개 제공처의 실제 결과로 표시하지 않는다. |
| 운영 확인 | 실제 관광자원·소개·행사 조회 | 아래 [운영 확인](#운영-확인과-미평가-구분)에서 별도로 대조한다. |

- 검증용 응답은 서버의 정규 키를 그대로 쓴다: 방문 `["new-visits", province, district, year|null]`,
  소개 `["new-resource-detail", province, district, kind, id]`, 자원 `["resources", province, district, types]`,
  일정 `["schedule", province, district, start, end]`. 가장자리 조건만 바꿀 때는 실제 응답을 받아 `key`·`request`를 보존한다.
  연도 없는 첫 방문 요청(`year:null` 키)과 화면이 주소에 기본 연도를 쓴 뒤의 요청(`year:2025` 키)은 서로 다른 키다.
- 지역 경로: 논산 `/new/44230` → API `province=44&district=230`. 세종은 `/new/36110` → API `36110/36110`이며
  `/new/3611036110`이나 `36/110`을 만들지 않는다.
- 응답 순서는 요청 보류·해제로 정한다(시간 대기로 순서를 정하지 않음). 격리 데이터베이스·임시 브라우저·headless만 사용한다.
  격리 DB에 논산 실행환경 수집 행이 있으면 보관본보다 최신 행이 우선하므로 실행 전에 비어 있음을 확인한다.

## 값 있음·0·결측의 판정

- **값 0:** 관측값이다. 관측일과 `값 0인 날`에 세고 합계에 0으로 더하며 표에 `0`으로 보인다. 결측을 만들지 않는다.
- **결측:** 보관본의 명시적 `missing` 행과 행 자체가 없는 날짜를 모두 포함한다. 표 `—`, 범례 `값 없음`이며
  0이나 다른 지역·연도 값으로 채우지 않는다. 최신 수집 행이 결측이면 이전 수집값을 되살리지 않는다.
- **월 평균:** 해당 달 모든 날짜의 합 ÷ 달력 일수. 한 날이라도 결측이면 그 달 평균 없음, 일별 값은 유지.
- **요일 평균:** 선택한 달력 연도 전체가 값 있음일 때만 7개 모두 생성(합 ÷ 그 연도의 해당 요일 날짜 수 N(w)).
  하루라도 결측이면 7개 모두 생성하지 않고 날짜 수·관측·결측·0 개수만 유지한다. 항상 52로 나누지 않는다.
- **연도 자료 없음:** 요청 연도를 그대로 두고 자료 없음과 연도 바꾸기를 제공한다. 다른 연도로 자동 대체하지 않는다.
- **공휴일 0일:** 후보 전체가 공휴일 확인 범위 안일 때만. **등록 행사 0건:** 후보 전체 기간 조회가 정상 완료된 때만.
  실패·조회 중·일부 달 조회는 0이 아니다.

## 자동 시험 실행 연결

- 실행: 저장소 실행기(`npm run test:e2e` → `scripts/run-demo-e2e.mjs`)가 격리 DB·빌드 서버에서 이 스크립트를 부른다.
  성공하면 통과 항목 목록을 JSON 한 줄로 출력하며, 실패는 해당 단언 메시지로 멈춘다.
- 스크립트는 시작 시 보관본 JSON에서 대조값을 다시 계산해 위 표의 숫자와 먼저 일치시킨 뒤 브라우저를 연다.
- 실제 `/api/new/visits` 응답은 바꾸지 않고 전달하면서 요일·월 값을 독립 계산과 비교한다. 검증용 변형은 임실 2023 한 조건과
  후보 2026-10-02~10-09 한 조건뿐이며 서버가 준 `key`·`request`를 그대로 둔다.
- 세종 경로 확인은 마지막에 실행한다. 이 단계만 실패하면 다른 기준의 결과와 분리해 읽는다.
- 시험이 확인하지 않는 것: 실제 제공처의 관광자원·소개·행사 결과, 지도 실제 배경, 실무 담당자 사용성.

## 운영 확인과 미평가 구분

브라우저 시험과 별도로 실제 공개 조회를 대조하며, 결과를 위 대조값에 맞춰 다시 정하지 않는다.

1. 논산 관광지·문화시설 실제 목록의 건수·좌표 없는 항목·전체 페이지 완료.
2. 소개: 130896 백제군사박물관(소개 있음 기대), 2650372 강경근대거리, 2633947 김홍신 문학관(보관 조회에 소개 행 없음 → 생략 기대),
   유형·지역 불일치 요청. 응답이 평문이고 출처가 공식 https 주소인지, 목록과 별개의 수집 시각인지.
3. 소개 조회 실패 직후 재시도: 서버 조회 도구가 실패를 30초 보관하므로 그 안의 재시도는 같은 실패가 나올 수 있다.
4. 월·연 경계 후보의 실제 행사 전체 기간 조회, 취소·일정 미확인 제외.
5. 운영 방문 값이 위 2025 대조값과 같은지(실행환경 수집 행이 덮는지), `/api/new/*`의 GET 전용·`no-store`.
6. 공개 주소의 390px·키보드 동작과 새 경로의 검색 노출·분석 연결(프로젝트 정책 범위).

실무 담당자 관찰과 최종 시각 디자인은 별도 작업이다. 정형 Spec/Run 식별자는 선언하지 않는다.
