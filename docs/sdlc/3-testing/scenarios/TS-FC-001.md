# TS-FC-001 · 우리 지역의 관광자원과 방문 추세를 조회한다

| 항목 | 내용 |
|---|---|
| 근거 | [UC-FC-001@v3](../../1-analysis/usecases/UC-FC-001.md) |
| 대상 환경 | 구현 후 격리된 로컬 브라우저 + 고정 자료 응답 |
| 실행 상태 | M1 해당 범위 자동 검증 완료. 아래 전체 과제·정형 Run 연결은 후속 |

## 데이터와 사전 조건

가상 지역 R-A에는 좌표 있음 2건·없음 1건, 방문값 100·0·null의 3일 자료를 둔다. R-B는 미수집이다. 첫 요청 응답을 두 번째보다 늦게 반환한다.
가상 데이터만 사용한다. 실제 API 자격·외부 기관 연락·공유 운영 자료 변경은 필요하지 않다.

## 실행할 과제와 기대 결과

R-A→R-B 전환 후 100 표시가 남지 않는지, 좌표 결측 1건이 목록에 있는지, 실제 0과 null 문구가 다른지 검증한다. 지도 이동 전후 QueryContext는 같고 '이 영역 조회' 뒤에만 공간 범위가 생겨야 한다.

| 순서 | 사용자 과제 | 판정할 인수 기준 |
|---|---|---|
| 1 | R-A→R-B로 지역을 바꾸고 모든 패널에서 R-A 값이 제거됐는지 확인한다. | AC1 |
| 2 | 기간·유형 변경 후 요청을 역순 응답시켜 최신 조건만 유지되는지 확인한다. | AC2 |
| 3 | 좌표 없는 자원과 일부 API 오류를 조회해 목록 유지·0/null/오류 구분을 확인한다. | AC3 |
| 4 | 자원과 지역 통계 상세에서 공간·기간·단위·출처를 확인하고 행사장 혼잡 표시가 없는지 확인한다. | AC4 |

## 공개 사례 반영 추가 과제

| 인수 기준 | 고정 입력·행동·기대 결과 |
|---|---|
| AC5 | 사업 정보가 빈 신규 작업에서 지도 목록의 장소 A를 선택한다. 관광시설 등록만 있고 대관 확인은 없는 고정 자료를 사용한다. 탐색·담기를 완료하고 사용 가능 여부가 미확인인지 확인한다. |

추가 과제의 수치는 시험용 고정 입력이다. 실제 사례의 해석 범위는 [조사 출처](../../../research/2026-09-municipal-festival-sources.md)를 따른다. 아래 전체 조합 중 M1 해당 검증 범위는 20번 기록을 따른다.

## 실패·복구 확인

좌표 없음은 목록에 유지한다. 미수집 지역에서는 이전 지역 숫자를 제거하고 자료 부족을 표시한다. 일부 API 오류는 해당 자료만 재시도하며 늦은 이전 응답은 무시한다.
실패 입력을 한 뒤 기존 보관본과 다른 회차가 유지되는지 확인한다.

## 실행 증거와 정리

현재 Run은 없다. 개발 후 실행 파일과 결과를 specs·보고서 경로로 연결한다.
새 인수 기준은 기존 운영 E2E 결과로 통과 처리하지 않는다.
독립 브라우저 저장·고정 응답만 사용하고 종료 시 테스트 컨텍스트를 닫는다.
