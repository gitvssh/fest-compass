# TS-FC-009 · 기존 축제 개선 탐색

[UC-FC-009](../../1-analysis/usecases/UC-FC-009.md)의 14개 기준을 확인한다.
시나리오 선언 자체는 시험 통과가 아니다. 실행 대상과 결과는 [검증 기록](../../../validation/34-existing-festival-journey.md)에 남긴다.

## 자료와 실행 경계

논산의 회차·일별 방문은 실제 보관 자료를 사용한다. 현재 등록 축제·자원·행사 실패와 응답 경합은
명시적인 시험 응답으로 재현하고 공개 운영의 실제 조회와 구분한다. 원천에 없는 0·결측·중복 휴일은
계산 단위 시험의 입력이며 실제 축제 관측으로 표시하지 않는다. 임시 브라우저·격리 데이터베이스를 사용한다.

| 기준 | 사용자 행동·확인할 결과 |
|---|---|
| AC1 | 첫 화면에서 기존 축제 개선 → 논산딸기축제 선택 → 2025·2024 회차. 개인 기록 없이 진입한다. |
| AC2 | 세 탐색 화면을 오가고 뒤로 간다. 적용한 조건·임시 선택이 유지되고 개인 기록 쓰기가 발생하지 않는다. |
| AC3 | 논산 2025·2024·2023의 실제 개최기간 일평균 85,212.75·90,412.875·68,590.9, 최대일·표를 대조한다. 전후 차트는 각각 18·18·19일이다. |
| AC4 | 누락·다른 지표·기간 없음은 0이나 허구 평균으로 표시하지 않는다. 유효한 일별 값·출처와 다른 탐색 이동을 유지한다. |
| AC5 | 관광자원은 지역 목록에서 시작한다. 사용자가 중심을 적용한 뒤만 직선거리를 계산하고 좌표 없는 항목은 목록에 남긴다. |
| AC6 | 관광자원 한 유형 또는 행사 조회만 실패시킨다. 정상 자료·조건을 유지하며 실패한 영역을 다시 불러온다. |
| AC7 | 실제 관측연도의 월간 일평균과 달력·후보 날짜를 별도로 본다. 월별 관측일수·결측을 대조하고 미래 방문값·추천 점수가 없는지 확인한다. |
| AC8 | 2027-02-01 이후 공휴일 자료 없음과 전체 조회한 행사 0건을 구분한다. 날짜·지역을 바꿔 탐색을 계속한다. |
| AC9 | 앞 조건의 성공·실패 응답을 나중에 도착시킨다. 마지막 적용 조건의 제목·차트·목록이 유지된다. |
| AC10 | 키보드와 390px에서 선택·이동·표·자원·출처·복구를 이용한다. 문서 전체 가로 넘침과 닫은 뒤 초점 복원을 확인한다. |
| AC11 | 동명 현재 축제와 보관 축제를 별도 ID로 선택한다. 확인하지 않은 과거 회차를 붙이지 않고 과거 기록 없이도 자원·시기를 연다. |
| AC12 | 과거 월의 실제 연월 일정 링크를 열고 뒤로 간다. 관측연도·후보 날짜를 바꾸지 않고 이전 선택·초점을 복원한다. |
| AC13 | 같은 조건 성공 후 갱신만 실패시킨다. 기존 결과·당시 시각·재시도를 유지하고 다른 조건의 결과를 대신 쓰지 않는다. |
| AC14 | 1~3회차·차트 날짜 변경·후보 하나·월/연 경계 후보를 시험한다. 평균은 원 개최기간을 사용하며 전체 후보 기간이 확인된 경우만 일정 수와 겹침을 집계한다. |

## 운영 확인과 미평가 구분

실제 공개 검색·자료 조회·출처·모바일 화면을 별도로 대조한다. 시군구 일별 외지인 방문과
기존 `/compare/annual`의 개최 행정동 지표를 섞지 않는다. 실무자 관찰과 최종 시각 디자인은 별도 작업이다.
정형 Spec/Run 식별자는 아직 선언하지 않으며 실행 파일·근거가 있는 범위만 검증 기록에서 판정한다.
