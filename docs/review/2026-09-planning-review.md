# FEST Compass 기획 검수 v3

**전국 조회·축제 비교의 근거에서 기획 후보와 예산·준비 규모 비교까지 연결했습니다. 다음은 완성 기획안 출력입니다.**
먼저 [M4 실제 화면·검수 과제](../sdlc/2-design/budget-implementation.md), [M4 검증 기록](../validation/23-planning-budget.md)을 확인하세요.
이전 단계는 [M3 실제 기능과 검수 과제](../sdlc/2-design/planning-options-implementation.md), [M3 검증 기록](../validation/22-planning-options.md)을 확인하세요.
이전 단계는 [축제 비교 구현·검수 범위](../sdlc/2-design/festival-comparison-implementation.md)와 [M2 검증 기록](../validation/21-festival-comparison.md)을 확인하세요.
이전 단계는 [실제 화면과 제공 범위](../sdlc/2-design/region-explorer-implementation.md), [검증·공개 반영 상태](../validation/20-region-explorer.md)를 확인하세요.
이미 사용 가능한 논산 자료·예측 연구와 개인 운영 기록 기능을 전체 제품 MVP 완료로 보지 않습니다.
이번 검수에서는 지자체 담당자가 자료를 살펴보고 아이템·장소·시기·예산·준비 규모를 결정할 수 있는지 확인합니다.

## 검수 주소와 읽는 순서

2026-09-08 추가 조사: [지자체 축제 준비·예산 사례](../research/2026-09-municipal-festival-cases.md),
[출처·확인 범위](../research/2026-09-municipal-festival-sources.md),
[요구사항·화면 보완안 8개](../research/2026-09-municipal-requirement-proposals.md)를 먼저 읽을 수 있습니다.
8개 보완 방향을 요구사항·자료 정의·인수 기준과 7개 와이어프레임에 반영했고, v3에서 전국 진입·실자료 그래프를 추가했습니다.
기존 화면 번호와 지도 중심 순서를 유지하고, 기획·예산·결과 단계의 업무 정보를 구체화했습니다.

내부 검수 사이트: [FEST Compass 문서](https://traceboard.homelab.damecasol.com/portfolio/fest-compass/site/index.html).
이 주소는 기존 내부 접근 환경에서 사용합니다. 외부 공개 사이트 등록은 이번 범위가 아닙니다.
traceboard의 화면 카탈로그와 화면 흐름에서 7개 시안을 열 수 있습니다.
사이트의 '문서 존재' 표시는 개발 완료·사용자 검수 완료가 아닙니다.

1. [제품 기획](../sdlc/0-planning/product-plan.md): 누구의 어떤 업무를 해결하고 무엇을 기획안으로 남기는가.
2. [요구사항·기능목록](../sdlc/1-analysis/srs.md): 전체 기능과 완료 조건이 목표를 빠짐없이 다루는가.
3. [자료 정의](../sdlc/1-analysis/data-contract.md): 실제 확보 자료·검증 필요·사용자 입력의 구분이 타당한가.
4. [정보구조](../sdlc/2-design/ia.md)와 [화면 흐름](../sdlc/2-design/flows.md): 첫 탐색부터 기획안까지 순서가 자연스러운가.
5. [화면설계·와이어프레임](../sdlc/2-design/screens.md): 필요한 정보·행동·오류 상태를 화면에서 찾을 수 있는가.
6. [인수 검증 계획](../sdlc/3-testing/acceptance-plan.md): 어떤 과제를 실제로 통과해야 완료라고 할 것인가.

## 먼저 확인할 다섯 가지

| 검수 관점 | 확인할 질문 |
|---|---|
| 첫 화면 | 전국에서 지역을 좁혀 지도·관광자원·방문 추세를 보는 흐름이 담당자의 첫 정보 수요를 충족하는가? |
| 비교 | 주변 행사·과거 회차의 어떤 조건과 지표가 실제 기획 판단에 필요한가? |
| 근거 연결 | 자료를 담고 후보의 아이템·장소·시기에 연결하는 과정이 이해되는가? |
| 예산·준비 | 프로그램·시설·인력·교통·홍보 항목과 수량·단가·미산정 표기가 충분한가? |
| 최종 기획안 | 두 후보 중 하나를 선택한 이유와 미확인 사항을 검토자에게 설명할 수 있는가? |

표의 질문은 검수용이며 문서 작성을 중단시키는 승인 대기가 아닙니다.
이미 정한 주 타겟·지도 중심 방향·모델 연구 후순위를 다시 결정할 필요는 없습니다.

## 시안에서 제안한 기본값

전국지도에서 시도→시군구로 좁혀 갑니다. 우리 지역·이전 탐색 바로가기는 별도로 제공합니다. 비교는 2~3개 회차의 그래프와 수치 표를 함께 봅니다.
지도를 움직이면 화면 위치만 바뀌고 '이 영역 조회'로 검색 범위를 바꿉니다.
아이템은 자동 선정하지 않고 담당자가 두 후보를 만들어 근거와 제약을 연결합니다.
미입력 예산은 0원이 아니며, 확인 합계와 미산정 항목을 함께 표시합니다.
이 기본값들은 검수 의견에 따라 바꿀 수 있는 초안입니다.

## 검수 의견 기록 방식

화면 번호나 요구사항 ID와 함께 '현재 시안 / 원하는 행동 / 이유'를 적으면 수정 위치를 찾기 쉽습니다.
예: 'SCR-FC-002: 회차 비교에 예산 출처를 항상 보고 싶다. 총사업비와 지원금을 혼동할 수 있다.'
상태는 미검토 → 의견 반영 중 → 재검토 → 검토 완료로 구분합니다.
현재는 **사용자 전국 진입·실자료·시각화 의견을 반영한 v3 재검토** 단계입니다.
실제 담당자 인터뷰·시안 검수 완료는 기록하지 않았습니다.

## 개발 착수 조건

핵심 흐름과 기획안 항목을 검토한 뒤 M1의 지역·기간·지도/목록/차트·출처·근거 담기를 구현합니다.
지도 공급자·행정경계·좌표·지역별 자료 가용성은 개발 착수 시 확인할 항목입니다.
M1~M4 첫 기능 다음에는 M5 기획안 출력, M6 결과를 연결합니다. 전국 자료 완비나 추가 예측 정확도 연구를 먼저 요구하지 않습니다.

## v2에서 집중해 볼 화면

| 화면 | 이번에 구체화한 내용 |
|---|---|
| SCR-FC-001~003 | 지도 자원의 장소 확인 상태, 비용의 문서 단계·전체/부분 범위, 선택 당시 출처와 담당자 해석 |
| SCR-FC-004 | 사업연도·부서·복수 수행 관계, 설치/행사/철거 일정, 담당·기한·선행 과제·확인 상태 |
| SCR-FC-005 | 재원과 지출 분리, 기간 포함 산출, 단계별 금액, 전년 증감 이유·연도별 분류 |
| SCR-FC-006 | 같은 보관 버전에서 사업설명 자료·준비 목록 출력, 미확인·증감·출처 유지 |
| SCR-FC-007 | 재원별 실제 사용, 잔액/반납/이자 미확인, 증빙 확인과 차기 개선 연결·결과 출력 |

v3의 논산 방문 추세와 원주 지원사업 계획·집행액은 확인한 실제 표본입니다. 올해 기획 후보·견적 입력은 가상 예시입니다. 실제 사례 금액과 확인 범위는 조사 문서를 기준으로 읽습니다.
예산·사업 정보를 작성하지 않아도 지역 지도를 탐색하도록 설계했습니다.
공식 결재·입찰·지급·정산 승인이나 증빙 원본 저장 기능을 추가한 것은 아닙니다.

## v3에서 먼저 볼 변경

1. [과거 자료 점검](../research/2026-09-historical-comparison-review.md): 실제 조회·보관 자료와 현재 API의 과거 회차 누락을 구분합니다.
2. [전국·시각화 설계](../sdlc/2-design/data-visualization.md): 전국→시도→시군구, 차트 종류·구성비 조건·출처·근거 담기를 확인합니다.
3. [7개 화면 v3](../sdlc/2-design/screens.md): 001 전국 시작, 002 실제 논산 선그래프, 005 미산정 파이 보류, 007 실제 원주 지원사업 그래프를 봅니다.

과거 자료를 실제 사용 가능한 것으로 표시하려면 회차·지표마다 출처·보유 기간·누락·확인일이 있어야 합니다.
첫 20건을 전국 축제 총수로 표시하지 않으며 지역 방문자를 축제 입장객으로 표현하지 않습니다.
화면 표시 검증은 headless로 수행합니다. 실제 공무원 관찰과 제품 기능 시험은 별도입니다.
