# FEST Compass 실데이터 기반 고도화 계획

승인일: 2026-09-07. 사용자는 공모전 완성도와 실무 활용성을 같은 비중으로 추진하고,
관광데이터를 이용해 축제의 현재·과거 현황과 향후 전망, 운영 결정, 기록과 장기 운영을
연결하는 플랫폼 및 실제 축제 한 곳의 샘플 구현을 승인했다.

## 단계와 완료 기준

| 단계 | 작업 | 산출물 | 다음 단계 기준 |
|---|---|---|---|
| 1 | 기획·코드·데이터·화면 현재 점검, 실무 판단 질문 정의 | 현재 상태·가설·우선순위 | 핵심 기능에 사용자·문제·데이터·성공 기준 연결 |
| 2 | API 실값·기간·지역·갱신·결측 검증, 후보 2~3곳 비교 | 데이터 품질 보고서·샘플 선정 근거 | 핵심 데이터 또는 명시적 대체 방법 확보 |
| 3 | 예측 대상·단위·시점 확정, 과거 시점 재현, 운영 계산 검증 | 단순 기준 대비 예측 평가·계산 근거 | 기능별 제공 범위와 확보할 자료 확정 |
| 4 | 실무 의견과 증거로 기획·기능 우선순위 확정 | 개정 기획·기능·인수 기준 | 샘플의 핵심 가치와 구현 범위 확정 |
| 5 | 실제 값·결측을 사용한 화면 설계와 과제 수행 관찰 | 화면 시안·데이터 연결·사용성 결과 | 수치의 의미와 다음 행동 이해 |
| 6 | 실제 축제 한 곳의 전체 흐름 구현 | 샘플·수집 절차·회귀 검증 | 과거→현재→향후 계획→결과 추적 가능 |
| 7 | 공모전·실무 평가, 다음 개발 정리 | 검증 보고서·시연·후속 목록 | 검증 성과와 남은 가설 구분 |

## 일정 가정

4주 집중안: 1주 현재 점검·데이터·후보, 2주 예측·기획, 3주 화면·핵심 구현,
4주 전체 흐름·검증·발표. 정확한 제출일과 팀 가용시간은 별도 확인 대상이다.
외부 자료·인터뷰 대기는 독립적인 데이터 조사와 구현을 막지 않는다.
자료가 없다는 이유로 실측이나 예측 성능을 만들어내지 않는다.

## 데이터 검증 기준

- API 인가, 정상 응답, 비어 있지 않은 표본, 전체 수집, 제품에 쓸 수 있음은 각각 구분한다.
- 데이터마다 출처, 지표 정의, 집계 단위, 지역코드, 조회기간, 수집 시점, 갱신 지연,
  누락·중복, 이용 조건, 호출 예산과 해석 한계를 기록한다.
- 최신 공개 통계를 실시간 현황으로 표현하지 않는다. 지역 방문자와 축제 입장객을 분리한다.
- 공식 공급자 예측, 자체 모델 예측, 사용자 가정, 실측을 구분한다.
- 과거 재현은 당시 공개되어 있던 데이터만 사용한다. 현재 API의 미래 집중률을 과거 정답으로 쓰지 않는다.
- 후보는 반복 개최·과거 자료·KTO 연결·운영 문제·실무 접근 가능성으로 비교한다.
  조회 표본이 확보됐다는 이유만으로 최종 샘플로 선정하지 않는다.

## 예측·운영 기능 기준

- 예측 목표는 유지한다. 지역 방문 규모·축제 입장객·시간대별 혼잡을 별개 문제로 정의한다.
- 전년·요일·계절 기준과 시간 순서 평가로 비교하고 오차와 불확실성, 과소·과대 추정 영향을 기록한다.
- 단일 축제의 연간 총계 몇 개는 학습자료 충분성의 증거가 아니다. 필요하면 비교 가능한 유사축제 자료를 검토한다.
- 셔틀·인력·회차 변경과 비용·처리량·대기·수용량 사이의 관계는 필요한 운영자료와 계산식으로 검증한다.
- 축제와 개최회차, 자료·예측 버전, 결정 당시 입력, 실측 정의를 장기적으로 보존한다.

## 사용자 검증과 운영

팀이 확보한 실무자 3~5명을 대상으로 판단 과제, 입력 부담, 완료시간, 지표 이해도를 관찰한다.
자료 확보와 인터뷰 미실시는 미검증으로 남긴다. 공개 자료 재현은 현장 검증을 대체하지 않는다.
공개 편집에는 인증·권한 검증이 필요하며, 운영 ADR을 후속 결정 없이 변경하지 않는다.

단계 종료마다 확인 사실, 남은 불확실성, 유지·변경·보류할 기능과 다음 작업을 기록한다.
세션을 넘는 현재 상태는 `.ai/projects/fest-compass-evolution/STATE.md`에서 확인한다.

## 2026-09-07 후보 선정 진행

후보 3곳의 2023~2025년 공개 자료를 비교해 [논산딸기축제를 개발 샘플로 선정](05-festival-selection.md)했다.
1차 예측 지표는 [논산시 일별 외지인 방문 추세](06-forecast-contract.md)로 정의했다.
시군구 API의 14개 선택일 조회는 성공 10·empty 4이며, 연속 다년 자료와 당시 공개본은 미확보다.
다음 작업은 연속 수집·갱신 지연 검증과 단순 기준 모델 비교다. 2·3단계 전체 완료는 아니다.

## 2026-09-07 첫 예측 모델 진행

후속 구현으로 논산시 2023~2025년 1,096일을 모두 수집하고, 과거 이력으로 계수를 학습하는
회귀 모델과 기준 2개를 시간 순서대로 비교했다. [실험 설계](08-model-experiment.md)와
[실제 오차·검증 결과](09-model-validation.md), `/forecast`의 2025년 사례 화면을 제공한다.
기본 공개 지연 가정에서 2025년 선택된 208일의 평균 절대오차는 선정 기준보다 12.4~18.2% 작았다.
그러나 축제 4일의 방문 증가를 과소예측했고 구간 포함률도 목표에 못 미쳤다.
현재 개정자료 실험이며 당시 공개본 재현·향후 발행 예측·실무자 검증·전체 흐름 구현은 남아 있다.
