# 샘플 축제 선정: 논산딸기축제

선정일: 2026-09-07. 기준 제품 `fbe50f0`. 사용자가 요청한 후보 비교·선정 범위에서
**논산딸기축제를 첫 개발 샘플로 선정한다.** 2025년 회차를 설명용 사례로 삼고
2023~2024년 자료를 과거 비교에 연결한다. 예측 모델과 화면 연결은 개발 필요 상태다.

이유는 방문객 규모가 아니라, 같은 지역에서 반복 개최되고 사후 발표와 주차·셔틀의
구체적인 운영 문제가 함께 공개되어 있기 때문이다. 실무자 연결·비공개 자료 제공은 세 후보
모두 미확인이다. 이번 비교는 공개 자료만 사용했으며 기관 연락·자료 제공 승인을 뜻하지 않는다.

현재 메타데이터이며, 과거 회차 일정을 대신하지 않는다. 논산의 2026년 회차 전체 분석은 후속 대상이다.

이 표는 공개 근거에 따른 개발 판단이다. 자료가 있는 것처럼 보이게 점수를 부여하거나
인터뷰·현장 접근 가능성을 추정하지 않았다. 임실·백제의 예측 성능이 낮다는 의미도 아니다.

논산시의 2025년 3월 25일 안내는 전용주차장 5곳·4,600면과 셔틀 83→119대 계획을
명시하고, 전년의 긴 대기 문제를 설명한다 [N4]. 다만 119대가 동시 보유대수인지 기간 누계인지,
시간대별 배차·운행 횟수·실제 탑승·회차시간·대기가 얼마였는지는 확인되지 않았다.
따라서 이 수치만으로 시간당 수송능력이나 대기 감소율을 계산하지 않는다.

2023년 주차 안내에도 장소별 면수와 일부 주말 한정 개방 조건이 있다 [N5].
그러나 게시일이 3월 13일로 행사 종료 뒤이므로, 이 재게시본을 2023년 사전계획 당시 공개 자료로
간주하지 않는다. 2025년 SKT 혼잡도 서비스 도입 발표 [N6] 역시 데이터 보유 가능성의 근거이며,
공개 API·일별 원자료·FEST Compass 연결이 확보됐다는 증거는 아니다.

## 3. KTO 과거 제공 범위 확인

[12회 구조화 조회 증거][E1]와 [추가 2회 확인][E2]는 전국 기초지자체의 하루 응답을 각각 최대 1,000행
조회한 후 네 지역을 지역코드·이름으로 검증했다. 서버 필터로 지원되지 않는 시군구 파라미터는
보내지 않았다. 이번 도구는 조사용이며 앱 화면의 기존 광역 방문자 조회는 그대로다.

| 조회일 묶음 | 전국 응답 | 후보 지역 확인 | 의미 |
|---|---|---|---|
| 2023-03-08, 09-23, 10-06 | 각 783/783행 | 매일 4지역 × 3종 | 이 3일만 완전 수집 |
| 2024-03-21, 09-28, 10-03 | 각 792/792행 | 동일 | 이 3일만 완전 수집 |
| 2025-03-27, 10-03, 10-08 | 각 792/792행 | 동일 | 이 3일만 완전 수집 |
| 2026-08-01 | 807/807행 | 동일 | 확인한 선택일 중 가장 최근 비어 있지 않은 날짜 |
| 2026-08-15, 08-31, 09-01, 09-03 | 각 0/0행, 정상 empty | 자료 없음 | 0명으로 치환 금지. 전체 제공 종료일·원인은 아직 모름 |

보고서의 14회 중 비어 있지 않은 10회·empty 4회·오류 0회. 공개 지역 관측값 120개를 보존했다.
도구 작성 전 2025-03-27을 한 번 사전 확인했으므로 이번 시군구 실호출은 총 15회다.
예를 들어 2025-03-27 논산시는 외지인 `52,671.5`, 현지인 `63,528.5`, 외국인
`642.2899999999998`로 반환된다. 소수점은 API 원값을 보존하며, 세 종류를 합산하거나
이 날짜를 축제의 실제 일별 입장객으로 이름 붙이지 않는다.

공식 API 명세는 내국인 KT·외국인 SKT 기반의 지역 방문 추정 통계로 설명한다 [K1].
데이터랩의 일별 갱신 안내(4일 전) [K2]와 위 API 실응답은 일치하지 않는 구간이 있다.
포털 안내를 API의 확정 지연 또는 과거 공개일로 옮기지 않는다. **연속 다년 자료·제공일 이력은 미확보**다.

관광 소비 강도·자원 수요는 기존 2026-09-07 후보별 202604 조회가 모두 empty이며,
8월 30일에는 충남 7개 월을 확인했다고 [기존 API 점검](../design/05_API명세서.md)에 기록돼 있다.
이번에는 그 호출을 반복하지 않고 공식 명세 [K3, K4]를 재확인했다. 월별 복합 지표로서 개별 축제
입장객의 정답이 아니며, 명세의 시간범위가 비어 있어 empty 원인은 확정하지 못했다.
첫 모델의 필수 입력에서 제외하고, 제공 범위 확인을 별도 과제로 남긴다.

## 4. 선정 결과와 다음 작업

- **사용 가능:** 후보 비교, 공개 일정·발표 총계의 출처 확인, 읽기 전용 시군구 과거 선택일 조사.
- **개발 필요:** [예측 지표 계약](06-forecast-contract.md)의 논산시 일별 외지인 추세 모델,
  연속 수집·자료 버전·시점별 가용성·단순 기준 비교, 샘플 화면 연결.
- **준비됐지만 연결 필요로 표시할 수 없음:** 현장 입장객·시간대별 혼잡·셔틀 실적은 아직
  확보되지 않았다. 예측과 운영 효과 검증에 필요한 자료부터 확인해야 한다.
- **다음 구현:** 논산시의 2023~2025 연속 일별 자료 수집과 누락 지도를 만들고,
  실제 갱신 지연을 확인한다. 시점 증거가 부족한 실험은 당시 상황 재현 성능으로 발표하지 않는다.

2단계의 후보 비교·선정과 3단계의 지표 정의를 완료했다. 2단계 전체 자료 확보,
3단계 예측 성능·운영 계산 검증, 4단계 실무 의견 반영은 완료하지 않았다.
검증 명령·결과는 [이번 변경 검증](07-selection-validation.md)에 기록한다.
