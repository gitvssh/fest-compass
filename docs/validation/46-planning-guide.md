# 축제 기획 길잡이(묶음 1)와 팝업·초점 정제

상태: **사용 가능 — 공개 반영(두 번)·공개 화면 검증. 첫 반영 뒤 측정한 화면 밀림을 고쳐 다시 반영했다(아래 '공개 배포').** [설계24](../design/24-planning-guide.md) 19절과
[인수 기준 TS-FC-021](../sdlc/3-testing/scenarios/TS-FC-021.md)에 따른 변경이다.

## 사용자에게 달라지는 점

- 홈 카드마다 끝에 얻는 것이 한 줄로 보이고, 카드 아래 `축제 준비 전체 과정 보기`로 처음 맡은 담당자용 안내에 간다.
- 두 흐름의 시작 화면에 목표·네 할 일(화살표로 순서, 순서는 자유)·담당자가 판단할 것·끝에 얻는 것이 한 덩어리로 보인다.
- 탭이 할 일 이름이 됐다: `방문 흐름 돌아보기 · 연계 관광 찾기 · 개최 시기 검토하기 · 모아 보기`(새 축제는 `지역 자원 살펴보기 · 방문 흐름 읽기 · 개최 시기 검토하기 · 모아 보기`).
- 자료 화면마다 아이콘 세 칸(목표·이 자료로 알 수 없어요·살펴볼 질문 두 개)과 아래 `이어서` 줄이 있다.
- 기존 축제 회차 카드에 개최 전·개최기간·종료 후 일평균 막대가 생겼다(논산딸기축제 2025: 50,823 · 85,213 · 43,485명/일).
- `모아 보기`는 고른 회차·장소·후보 기간, 판단 메모, 다음에 확인할 일(할 일·협의할 곳·구분)을 한 장으로 모아 인쇄한다. 저장·전송하지 않는다.
- `/guide`는 일곱 단계의 하는 일·확인할 질문·협의할 곳·공식 원문을 보여 준다. 금액·기한 숫자는 없다.
- 모든 팝업이 같은 모양(아이콘 머리글·둥근 닫기·배경 누름으로 닫기)이 되고 휴대폰에서는 아래에서 올라온다.
  초점 표시는 2px 고리로 가늘어졌고, 입력칸은 테두리 안쪽이 빛나며, 확인란·선택지는 칩 전체가 표시된다.

- 전체 headless 묶음(run-demo-e2e와 같은 순서, 편집/공개 두 모드, 시험 실행 29회 — 새 시험 포함)이 최종 코드에서 통과했다.
  이 세션의 에이전트 실행에서는 Prisma가 시험 DB `--force-reset`을 차단해 같은 절차를 새 시험 DB 파일 생성(`db push`)으로 실행했다. 저장소 스크립트는 바꾸지 않았다.
- 검수 중 발견해 고친 결함:
  - 휴대폰에서 탭 줄의 숨은 구분 글자(화면 낭독용)가 스크롤 영역 밖으로 빠져 페이지가 644px로 넓어지던 문제(탭 줄을 위치 기준 상자로 만듦).
  - 대화상자 배경 흐림이 소프트웨어 렌더링에서 프레임마다 40~175ms 걸려 닫힘 처리가 늦던 문제. 흐림을 빼고 단색 막으로 바꿨다(흐림 없음 2~7ms).
    소개 영상은 Esc를 누른 순간(`cancel`)과 닫기 단추에서 바로 멈추도록 고쳤다. 소개 영상 시험은 초점 복귀를 기다린 뒤 확인한다. 6회 연속 통과.
  - 모아 보기를 주소로 바로 열 때 축제 이름이 오기 전 머리말에 ‘축제’가 잠깐 보이던 문제(이름이 올 때까지 생략).

## 첫 화면 성능과 화면 밀림

첫 반영(`ac9f196`) 뒤 공개 화면을 headless로 3~5회 재 보니 기존 축제 방문 화면의 화면 밀림(CLS)이 0.042에서 0.43~0.46으로 커졌다.
자료가 오기 전 첫 화면 안에 있던 `이어서` 줄과 바닥글이 차트가 들어오며 화면 밖으로 밀린 것이 주원인이고, 머리말의 지역 줄이 늦게 생기며 탭·안내 띠를 24px 미는 것(이전부터 있던 밀림)이 더해졌다.
두 시작 화면은 흐름 지도 그림이 지연 불러오기라 첫 화면 최대 요소(LCP)가 200ms가량 늦어졌다. 다음을 고쳐 다시 반영했다.

- 자료 영역 최소 높이(70vh, 인쇄 제외)로 `이어서` 줄·바닥글을 첫 화면 밖에 둠. 검색 결과 영역 자리 확보.
- 기존 축제 머리말: 기록이 오기 전 지역 줄 자리를 같은 높이의 불러오는 중 문구로 잡고, 따로 뜨던 불러오는 중 줄은 첫 불러오기에 쓰지 않음.
- 월별 방문 차트 자리를 불러오는 동안 같은 크기의 옅은 자리로 잡음(개최 시기·등록 축제 방문 화면).
- 모아 보기는 방문 자료가 정해진 뒤 한 번에 보임(다시 불러오기 중에는 그대로 유지). 관광자원 출처 줄은 목록이 정해진 뒤.
- 흐름 지도 그림은 바로 불러오고(우선순위 높음), 안내 띠 목표를 16px로 키워 서버에서 그린 글이 첫 화면 최대 요소가 되게 함.

같은 컴퓨터·같은 자료로 반영 전 판(`3e62419`)과 최종 판을 각 5회 측정한 중앙값(1440×900, 매번 새 브라우저 상태, 로컬 서버라 절대값은 공개 서버보다 작다):

| 화면 | LCP(ms) 전→후 | CLS 전→후 | 전송량(KB) 전→후 |
|---|---|---|---|
| 홈 | 88→92 | 0→0 | 304→315 |
| 기존 축제 찾기 | 112→256 | 0→0 | 199→224 |
| 기존 축제 방문 흐름 | 104→184 | 0.240→0.001 | 222→236 |
| 기존 축제 관광자원 | 640→484 | 0.143→0.018 | 1445→1446 |
| 기존 축제 개최 시기 | 168→180 | 0.451→0.001 | 231→245 |
| 새 축제 지역 고르기 | 80→116 | 0→0 | 176→207 |
| 새 축제 관광자원 | 560→544 | 0.119→0.082 | 1170→1165 |
| 새 축제 방문 흐름 | 64→76 | 0.047→0.019 | 248→263 |
| 새 축제 개최 시기 | 124→80 | 0.144→0.083 | 202→217 |

화면 밀림은 모든 화면에서 같거나 줄었다. 전송량은 새 그림·아이콘만큼(화면당 약 10~30KB) 늘었다. 시작 화면의 LCP는 흐름 지도 그림이 최대 요소가 되어 로컬에서 30~150ms 늘었고(좋음 기준 2.5초보다 훨씬 짧음),
방문 흐름 화면의 측정 차이는 반복마다 흔들리는 범위다(같은 조건 단독 측정에서 첫 화면 그리기 180ms 대 이전 276ms). 새 축제 관광자원·개최 시기에 남은 0.08 안팎의 밀림은 이전부터 있던 목록·달력 늦은 표시 때문이며 후속 개선 대상이다.
