# 축제 기획 길잡이(묶음 1)와 팝업·초점 정제

상태: **구현·로컬 검증 완료 — 공개 반영은 아래 '공개 배포'.** [설계24](../design/24-planning-guide.md) 19절과
[인수 기준 TS-FC-021](../sdlc/3-testing/scenarios/TS-FC-021.md)에 따른 변경이다.

## 사용자에게 달라지는 점

- 홈 카드마다 끝에 얻는 것이 한 줄로 보이고, 카드 아래 `축제 준비 전체 과정 보기`로 처음 맡은 담당자용 안내에 간다.
- 두 흐름의 시작 화면에 목표·네 할 일(화살표로 순서, 순서는 자유)·담당자가 판단할 것·끝에 얻는 것이 한 덩어리로 보인다.
- 탭이 할 일 이름이 됐다: `방문 흐름 돌아보기 · 연계 관광 찾기 · 개최 시기 검토하기 · 모아 보기`(새 축제는 `지역 자원 살펴보기 · 방문 흐름 읽기 · 개최 시기 검토하기 · 모아 보기`).
- 자료 화면마다 아이콘 세 칸(목표·이 자료로 알 수 없어요·살펴볼 질문 두 개)과 아래 `이어서` 줄이 있다.
- 기존 축제 회차 카드에 개최 전·개최기간·종료 후 일평균 막대가 생겼다(논산딸기축제 2025: 50,823 · 85,213 · 43,485명/일).
- `모아 보기`는 고른 회차·장소·후보 기간, 판단 메모, 다음에 확인할 일(할 일·협의할 곳·구분)을 한 장으로 모아 인쇄한다. 저장·전송하지 않는다.
- `/guide`는 일곱 단계의 하는 일·확인할 질문·협의할 곳·공식 원문을 보여 준다. 금액·기한 숫자는 없다.
- 모든 팝업이 같은 모양(아이콘 머리글·둥근 닫기·배경 누름으로 닫기)이 되고 휴대폰에서는 아래에서 올라온다.
  초점 표시는 2px 고리로 가늘어졌고, 입력칸은 테두리 안쪽이 빛나며, 확인란·선택지는 칩 전체가 표시된다.

## 구현·검증

- `npm test`: 414개 통과(42+342+30). 새 단위 시험 8개(`lib/guide/guide.test.ts`): 두 흐름의 권장 순서·다음 할 일, 문구 길이(목표30·질문28자 등),
  확인할 일의 구분·협의할 곳, 결론·평가·내부 용어 금지, 금액·기한·인원 기준 숫자 없음과 일곱 단계 구조, 출처 대장의 공식 https 주소·확인일,
  자료 범위 문장, 개최 전·후 일평균(값 없는 날은 평균 없음).
- `npm run typecheck`, `next build` 통과. 아이콘 의존성 `lucide-react@1.51.0`(ISC, 하위 의존성 없음)을 고정 버전으로 더했고 운영 의존성 감사는 0건이다.
  개발 의존성(Tailwind 3 경로)의 `braces` 고위험 공지(GHSA-vfj7-8cjw-p6xm)가 새로 떠 있지만 배포 점검 범위(운영 의존성) 밖이며 이번 변경과 무관하다.
- 새 headless 시험 `scripts/planning-guide-e2e.mjs` 15항목: G1 홈·시작 화면(목록 첫 줄 1440×900 첫 화면 안), G2 탭 이름·`aria-current`·이어서 순서·제목 초점,
  G3 안내 띠·질문2·부제 중복 없음·회차 막대 값(묶음 자료에서 다시 계산한 값과 일치), DS1 대화상자 Esc·배경 누름·닫기와 초점 복귀, DS2 초점 고리·입력칸 빛·칩 고리,
  G5 모아 보기 내용·출처 줄·메모 유지·인쇄(탭·안내·단추 제외, 메모 글·출력일), 새로 고침·주소 직접 진입, G4 방문 자료 실패의 부분 경고·다시 불러오기,
  새 축제 시작·탭·모아 보기, G6 `/guide` 일곱 단계·공식 링크·숫자 기준 없음, G9 390·720px 가로 넘침 없음, 브라우저 오류0.
- 기존 시험 정비: 탭 이름(`할 일 · 자료 이름`)과 하단 교차 연결이 `이어서` 줄로 바뀐 곳, 부제에서 입장객 경고를 안내 띠로 옮긴 곳, 관련 자료 검색 단추 이름을 고쳤다. 확인하는 내용은 그대로다.
- 전체 headless 묶음(run-demo-e2e와 같은 순서, 편집/공개 두 모드, 시험 실행 29회 — 새 시험 포함)이 최종 코드에서 통과했다.
  이 세션의 에이전트 실행에서는 Prisma가 시험 DB `--force-reset`을 차단해 같은 절차를 새 시험 DB 파일 생성(`db push`)으로 실행했다. 저장소 스크립트는 바꾸지 않았다.
- 검수 중 발견해 고친 결함:
  - 휴대폰에서 탭 줄의 숨은 구분 글자(화면 낭독용)가 스크롤 영역 밖으로 빠져 페이지가 644px로 넓어지던 문제(탭 줄을 위치 기준 상자로 만듦).
  - 대화상자 배경 흐림이 소프트웨어 렌더링에서 프레임마다 40~175ms 걸려 닫힘 처리가 늦던 문제. 흐림을 빼고 단색 막으로 바꿨다(흐림 없음 2~7ms).
    소개 영상은 Esc를 누른 순간(`cancel`)과 닫기 단추에서 바로 멈추도록 고쳤다. 소개 영상 시험은 초점 복귀를 기다린 뒤 확인한다. 6회 연속 통과.
  - 모아 보기를 주소로 바로 열 때 축제 이름이 오기 전 머리말에 ‘축제’가 잠깐 보이던 문제(이름이 올 때까지 생략).

## 제품 경험 판정

| 항목 | 결과 | 확인 범위 |
|---|---|---|
| 목표·흐름 | 충족 | 시작 화면 목표·네 할 일·판단·끝, 탭=할 일, 이어서로 다음 할 일, 마지막은 전체 과정으로. 어느 탭으로든 이동 |
| 시각적 위계 | 충족 | 자료(차트·지도)가 주, 안내는 아이콘 세 칸 한 띠. 회차 값은 막대와 숫자, 모아 보기는 영역별 아이콘 카드 |
| 문구 경계 | 충족 | 짧은 명사구·질문, 결론·평가·내부 절차 없음(단위·headless 금지 표현 시험). 같은 경고를 부제와 띠에 되풀이하지 않음 |
| 상태·복구 | 충족 | 고른 것 없음·새로 고침·주소 직접 진입·방문 자료 실패의 부분 경고와 다시 불러오기, 저장되지 않는 메모를 화면에 밝힘 |
| 접근성·반응형 | 충족(자동 범위) | 링크 탭·`aria-current`·제목 초점, 대화상자 초점 복귀, 초점 표시, 390·720px 넘침 없음, 꾸밈 아이콘·그림은 읽지 않음 |
| 출처·고지 | 충족 | 모아 보기 수치마다 지역·단위·기준·출처·수집 시각, 개인 검토 자료·공식 문서 아님, 원문은 기관 게시 페이지 새 탭 |

화면 낭독기 실제 사용, 첫 화면 성능(LCP)·전송량의 배포 전후 측정, 실제 초기 사용자 재확인(설계24 14절)은 미평가다.
