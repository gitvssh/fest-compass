# 첫 예측 모델 결과와 검증

검증일: 2026-09-07. **논산시 3년 이력 수집·학습 모델·시간순 비교 실험·화면은 사용 가능하다.**
지역 추세의 전체 오차는 단순 기준보다 작았지만, 축제 주말의 급증을 크게 과소예측했다.
축제 입장객·시간별 혼잡·운영 자원 결정을 위한 검증은 남아 있다.

마지막 페이지의 `numOfRows`는 요청 크기 대신 실제 잔여 행 수를 반환했다. 이를 전체 페이지 크기로
오인한 첫 최종 검사가 중단됐고, 전체 건수·고유 식별자·정확한 잔여 행 수를 확인하도록 고쳤다.
수정 후 **추가 API 호출 0회**로 저장된 108페이지를 재사용해 완전한 자료를 만들었다.
후속 수집기는 월별 검사를 통과한 뒤 다음 달로 진행한다. 부분 응답을 학습 자료에 섞지 않는다.

정본 자료: [일별 수집본](evidence/2026-09-07-nonsan-history.json).
자료 버전은 `de14d21e2ba9580d74de60160fd4a3b34b7a343cfa49d1ce626dedd4e4ea6170`.
전국 원문을 제품 DB에 넣지 않으며, 이 CLI의 호출 이력은 전용 캐시의 `attempts.jsonl`와
최종 자료의 페이지 메타데이터에 남긴다. 제품의 `ApiCallLog`를 쓰는 온라인 수집과 별도다.

## 2. 모델과 평가 결과

[사전에 고정한 실험 설계](08-model-experiment.md)를 사용했다. 모든 시나리오에서 규제 강도 100의
회귀가 2024년 선택 자료에서 골라졌다. 계수·표준화 값·학습 날짜·관측 ID 목록을 저장했고,
발행일마다 그 시점의 가정상 이용 가능한 과거만 사용해 다시 학습했다.
2025년 결과를 본 뒤 후보나 규제 강도를 바꾸지 않았다.

개최일은 평가 대상 날짜와 발행일을 정하는 데만 사용하고, 행사 여부나 프로그램은 모델 입력으로 넣지 않았다.
2025년 3월 27~30일 일정은 D-28보다 앞선 [2025-01-22 보도](https://www.newsis.com/view/NISX20250122_0003042722)에서도 확인했다.
2024년 일정의 당시 공지·변경 이력 전체는 아직 확보하지 못했으므로, 그 회차의 실제 의사결정 상황까지 재현했다고 주장하지 않는다.

기본 공개 지연 **35일 가정**의 결과다. MAE는 일별 추정 인원의 평균 절대오차이며 WAPE는
관측값 합 대비 절대오차 합이다. 표의 수치는 반올림했고 원본 소수는 평가 자료에 보존했다.

| 발행 | 2024년에서 선정한 단순 기준 | 기준 MAE / WAPE | 모델 MAE / WAPE | 기준 대비 MAE 감소 |
|---|---|---|---|---|
| 개막 28일 전 | B2 전년 같은 요일 | 7,162 / 15.0% | 6,274 / 13.2% | 12.4% |
| 개막 7일 전 | B1 최근 같은 요일 4회 | 7,434 / 15.6% | 6,083 / 12.8% | 18.2% |

각 선행기간에서 선택용 104일, 구간 보정용 36일(9개 창), 2025년 시험용 208일(52개 창)을 사용했다.
208일은 축제 4일·주변 비축제 8일·다른 비축제 196일이며, 예측 실패·누락 제외는 모두 0이다.
2025년 365일 전체를 평가한 것은 아니다. 겹치는 대상 날짜는 같은 선행기간 내에서 없으며,
여러 시점·지연 시나리오의 동일 날짜를 독립 관측처럼 합하지 않는다.

| 평가 묶음 | D-28 모델 MAE / WAPE | D-7 모델 MAE / WAPE |
|---|---|---|
| 축제 4일 | 30,754 / 36.1% | 31,628 / 37.1% |
| 주변 비축제 8일 | 4,662 / 9.3% | 4,545 / 9.1% |
| 다른 비축제 196일 | 5,840 / 12.5% | 5,624 / 12.0% |

전년 같은 요일 기준 B2의 축제 4일 WAPE는 31.5%로, 두 선행기간 모두 자체 모델보다 작았다.
따라서 전체 지역 추세의 개선을 축제 특유 수요의 개선으로 주장할 수 없다.
2025-03-29~30 실제 지역 추정치는 약 11.3만·11.2만이었으나 모델은 약 5.5만~6.5만을 예상했다.
모델은 날짜별 요일·계절·최근 이력을 학습했고, 축제 효과·공휴일·행사장 유입은 별도 학습하지 않았다.

## 3. 불확실성과 자료 공개 지연

| 기본 지연 가정 | 명목 구간 | 시험에서 구간을 낼 수 있었던 날짜 | 실제 포함률 | 평균 폭(추정 인원) | 축제 4일 포함률 |
|---|---|---|---|---|---|
| D-28 | 80% | 188일 | 73.4% | 12,167 | 0% |
| D-7 | 80% | 200일 | 64.0% | 10,581 | 25% |

보정 정답이 도착했다고 가정한 2025-01-03 이전 발행분에는 구간을 붙이지 않았다.
두 경우 모두 목표 포함률에 미달한다. 구간은 **보정 실험값**이며 운영의 안전 여유나 보장 범위가 아니다.
가을 36일·9개 창의 오차로 만든 구간이 다른 계절·축제 급증을 충분히 담지 못했다.

| 가정한 공개 지연 | D-28 모델 WAPE / 포함률 | D-7 모델 WAPE / 포함률 |
|---|---|---|
| 7일 | 13.0% / 58.3% | 12.7% / 57.2% |
| 35일(기본) | 13.2% / 73.4% | 12.8% / 64.0% |
| 60일 | 12.6% / 69.3% | 13.1% / 75.5% |

이는 지연 가정에 대한 민감도이며 실제 API 지연을 추정한 결과가 아니다. 60일 자료가 더 낫게 나온
일부 수치만 보고 60일 지연을 최적 설정으로 채택하지 않았다. 모든 경우 2024년에서 선택한 단순 기준보다
전체 MAE·WAPE가 낮았지만 축제 급증과 포함률 문제는 남았다.
당시 공개본만 허용하는 모드에서 2025 축제 D-7에 사용 가능한 관측은 **0개**다.
현재 개정자료 실험을 과거 실제 운영에서 달성한 성능으로 소개하지 않는다.

## 5. 재현과 검증

Node 24.20.0 / npm 11.19.0, Ubuntu WSL. `apps/web`에서 실행한다.
수집·평가 출력은 기존 파일을 덮어쓰지 않으므로 새 경로를 사용한다.

```bash
# TOUR_API_KEY는 기존 비공개 환경 설정으로 전달한다. 값은 인수나 로그에 쓰지 않는다.
npm run data:collect-history -- --start 2023-01-01 --end 2025-12-31 \
  --cache output/nonsan-history-new --max-calls 150 --output output/nonsan-history-new.json

# 저장된 공개 수집본만으로 재평가: 외부 API나 키 불필요
npm run forecast:evaluate -- --input ../../docs/validation/evidence/2026-09-07-nonsan-history.json \
  --output output/nonsan-forecast-reproduction.json.gz --summary output/nonsan-summary-reproduction.json

# 저장된 산출물의 계수로 예측을 다시 계산하고 자료·시점·오차를 대조
npm run forecast:verify -- --input ../../docs/validation/evidence/2026-09-07-nonsan-history.json \
  --report ../../docs/validation/evidence/2026-09-07-nonsan-forecast.json.gz \
  --summary data/nonsan-forecast-summary.json
```

수집기는 캐시 설정·페이지 체크섬·실행 점유 파일을 확인하고, 실제 요청 시도마다 전체 예산을 차감한다.
중단 시 자동 재시도하지 않으며, 같은 인수로 실행하면 완료된 페이지를 재사용한다.
다른 실행의 점유 파일을 임의로 제거하지 않는다. 전체 상한은 최대 200회·36개월이다.

검증 대상은 `fb0d4cb`에서 분기한 `feat/nonsan-forecast-model`의 이 보고서와 함께 게시된 변경이다.

|---|---|

## 6. 다음 개발

1. 2026년 자료와 지속 수집본으로 실제 공개 지연·개정 차이를 관찰하고 향후 회차 전에 예측을 저장한다.
