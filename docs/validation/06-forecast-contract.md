# 논산 샘플의 예측 지표·평가 계약

결정일: 2026-09-07. [후보 비교·선정 근거](05-festival-selection.md).
사용자의 지표 선정 요청에 따라 개발의 기준을 정한다. **첫 모델·현재 개정자료 실험·비교 화면은 구현됐다.**
[실험 설계](08-model-experiment.md)와 [결과·검증](09-model-validation.md)을 함께 읽는다.
당시 공개본으로 하는 재현과 현장 적용 검증은 개발 필요다.
현재 제품의 광역 배경선·사용자 가정 계산을 자체 예측이 완성된 것으로 표시하지 않는다.

## 1. 예측 질문과 지표

“행사일 중 논산시로 들어오는 외지인 방문 추세가 평소보다 커질 날은 언제인가?”를 첫 질문으로 삼는다.
주차·교통 안내를 더 준비할 날짜를 검토하는 보조자료이며, 행사장 실제 인원이나 차량 필요량을 직접 뜻하지 않는다.

| 항목 | 선정한 정의 |
|---|---|
| 샘플 | 논산딸기축제, KTO `525292`; 사례 회차 `2025-03-27~03-30` |
| 1차 정답 지표 `y(d)` | KTO 기초지자체 방문자 API의 `signguCode=44230`, `touDivCd=2`(외지인(b)), 해당 일자의 `touNum` |
| 공간·시간 | 논산시 전체 / 한국 날짜 기준 1일. 행사장 경계·시간별 혼잡과 분리 |
| 단위·원값 | 통신 기반 추정 인원(소수 보존). 화면에는 일별 추세·기준 대비 변화를 중심으로 설명 |
| 예측 대상일 | 선택된 개최회차의 각 행사일. 행사 전체의 순방문객 합계는 만들지 않음 |
| 예측 발행 시점 | 개막 28일 전 및 7일 전, 각각 09:00 Asia/Seoul. 입력 마감도 같은 시각 |
| 예측값 | 자체 모델의 `ŷ(d)` 및 단순 기준 대비 지수 `100 × ŷ(d) / b(d)` |
| 보조 지표 | 기준 대비 변화율 `100 × (ŷ(d) / b(d) - 1)`, 상대적으로 유입이 클 것으로 예상하는 날짜 |
| 정답의 성격 | 공급자가 추정한 지역 관측 통계. 현장 실측과 구별하고 `fetchedAt`·출처·자료 버전 보존 |
| 누락·0 | 누락은 null, 관측 0은 0. 기준 `b(d)=0`이면 지수·증감률은 계산 불가 |
| 현재 제공 상태 | 2023~2026-08-08의 1,316일 확보. 첫 회귀 모델·시간순 실험·`/forecast`, 일반 날짜 사전 예측 보존·`/forecast/records` 사용 가능([후속 규칙](10-prospective-records.md)). 다음 축제 회차 발행·운영 적용은 검증 필요 |

`b(d)`는 발행 시점에 이용 가능한 최근 4개 같은 요일 값의 중앙값으로 고정한다.
어떤 날을 선택했는지 함께 저장한다. 최근 자료가 늦으면 기준 날짜도 오래되었다고 표시하고,
4개를 확보하지 못하면 지수를 출력하지 않는다. 이를 객관적인 무축제 반사실로 해석하지 않는다.

지역 방문자의 정의와 합산 제한은 [한국관광공사 공식 명세](https://www.data.go.kr/data/15101972/openapi.do)를 따른다.
`touDivCd=1` 현지인, `3` 외국인은 따로 보존하며 1차 정답에 더하지 않는다.
API가 반환하는 소수는 추정 과정의 결과로 다루고 실제 측정 정확도를 의미하지 않는다.

## 2. 다른 예측·운영 지표의 범위

| 지표 | 이번 결정 | 사용하기 위한 최소 자료 |
|---|---|---|
| 축제 일별 입장객 | 후속 예측 목표로 유지, 현재 미제공 | 행사장 경계·계수 방식·재입장/중복 처리·일별 총계·집계 변경 이력 |
| 행사장 시간별 혼잡 | 후속 예측 목표로 유지, 현재 미제공 | 구역별 유입/유출 또는 동시 체류 관측, 시간 간격·시계·구역 경계·센서 누락 정의 |
| 셔틀·주차 수요 | 원자료 확보 후 운영 시나리오 계산 | 시간대별 도착 차량·승차 수요·좌석·실제 배차·회차시간·점유·대기·비용 |
| 관광지 집중률 | 공급자 향후 30일 상대 예측 보조신호 | 같은 장소의 확인된 식별자·좌표/경계·예측 발행시각과 대상기간 |
| 소비 강도·자원 수요 | 필수 입력에서 제외, empty 상태 유지 | 비어 있지 않은 월별 실값·제공 범위·갱신일 검증 |
| 사후 발표 방문객·딸기 판매량 | 회차 설명·성과 기록 | 출처와 발표일, 보고 범위; 일별 값으로 균등 분할하거나 학습용 복제 금지 |

주차 안내의 “셔틀 119대”를 동시에 운행하는 버스 수로 간주하지 않는다.
지역 방문자에서 축제 참여율·승용차 비율·셔틀 이용률을 가정하는 경우에는 사용자 가정과
검증된 관측을 분리하고, 이번 지역 예측의 정확도를 운영 대기시간 정확도로 옮기지 않는다.

## 3. 과거 비교와 미래 정보 유입 방지

자료마다 `eventDate`, `sourcePublishedAt`(알 수 없으면 null), `fetchedAt`,
`sourceVersion/hash`, 지역코드·지표 정의·품질 상태를 보존한다. 예측에는 별도로
`issuedAt`, 입력 관측 ID 목록, 입력의 마지막 날짜, 모델·기준 모델 버전을 기록한다.

당시 공개된 자료만 쓰는 과거 재현은 `sourcePublishedAt <= issuedAt` 또는 그 시점 이전의
수집본으로 가용성을 증명해야 한다. **오늘 조회한 과거 통계를 당시 공개본으로 간주하지 않는다.**
현재 확보한 2023~2025 자료에는 당시 공개시각·개정 전 버전이 없으므로 엄격한 과거 재현은 아직 불가하다.

[공식 갱신 안내](https://datalab.visitkorea.or.kr/datalab/portal/getMetaInfoList.do)의 4일 지연을
일괄 적용해 `sourcePublishedAt`을 만들어내지 않는다. [선택일 조사](05-festival-selection.md#3-kto-과거-제공-범위-확인)에서
2026-08-15 이후의 일부 조회일이 empty였기 때문이다. 자료가 제공되는 날을 지속 관찰하고
실제 공개 지연을 기록한 뒤 발행 시점별 입력 가능 범위를 검증한다.

현재 개정본만 확보되면 **현재 개정자료를 이용한 시간순 탐색 실험**은 진행할 수 있다.
가정한 지연과 관측 날짜 제한을 명시하고, 이를 당시 운영에서 달성한 성능이나 계획 3단계의
과거 재현 완료로 발표하지 않는다. 필요한 시점 증거를 확보하거나 향후 회차에 사전 예측을
저장한 뒤 사후 검증하는 방식으로 부족한 증거를 보완한다.

실험에 사용하는 일정·공휴일·프로그램도 발행 시점에 알려진 버전을 쓴다.
행사 당일 실제 날씨, 사후 방문객 총계, 발표 전 운영 실적, 현재 API의 미래 집중률을
과거 예측 입력으로 넣지 않는다. 날씨 예보를 쓰려면 해당 발행시점의 예보 원본이 필요하다.

## 4. 데이터 확보·평가 기준

1. **연속 자료 확보:** 우선 2023-01-01~2025-12-31 논산시 일별 외지인 자료를 수집한다.
   2024년 윤일을 포함한 1,096일의 기대 날짜와 실제 관측·누락을 대조하고, 지역코드·중복·
   지표 종류·숫자·공급자 정의 변경을 검사한다. 선택일 9개의 성공을 전체 기간 확보로 취급하지 않는다.
2. **호출 계획:** 전국 응답만 지원하므로 기간·페이지를 나눠 모두 받은 후 논산시를 필터한다.
   이번 하루 조사 도구는 최대 16회이며, 향후 전체 수집기는 공용 키의 다른 사용량을 고려해
   별도 상한·재개·중복 방지·실패 시 부분 결과 격리를 구현한다. 포털 개발계정 1,000회 표기를
   현재 키의 가용 호출 잔액으로 간주하지 않는다.
3. **시간 순서 분리:** 2023년을 초기 학습 구간으로 하고 2024년을 확장 창 검증·모델 선택에 쓴다.
   2025년은 선택 후 고정 평가 구간으로 남긴다. 2025-03-27의 표본 숫자는 이미 품질 조사에서
   열람했으므로 완전한 미열람 시험이라고 부르지 않는다. 후보 모델이나 기준은 그 수치에 맞추지 않는다.
4. **비교 기준:** B1은 `b(d)`(가용한 최근 4개 같은 요일 중앙값), B2는 `y(d-364일)`
   (전년 같은 요일)이다. 2023~2025 축제 날짜가 이동하므로 B2가 전년 행사일과 같다고 표현하지 않는다.
   해당 값이 없으면 기준도 계산 불가로 기록한다. 동일 발행시점·동일 평가일에서 비교한다.
5. **평가 수치:** 주 지표는 MAE `mean(abs(ŷ-y))`와 WAPE `sum(abs(ŷ-y))/sum(y)`.
   편향 `mean(ŷ-y)`로 과소·과대를 함께 보고한다. WAPE 분모 0이면 계산 불가다.
   오차식의 합은 평가 연산이며 행사 순방문객·공식 월간 합계를 뜻하지 않는다.
6. **평가 묶음:** 개막 28일 전과 7일 전을 분리한다. 축제기간·주변 비축제기간을 각각 보고하고,
   실제 평가일 수·누락 제외일·예측 실패를 함께 공개한다. 2025 행사 4일로 일반적인 축제 예측력을
   입증하지 않는다. 여러 발행일의 겹치는 대상일도 독립 표본처럼 부풀리지 않는다.
7. **불확실성:** 검증 구간 잔차로 80% 예측구간을 만들고 시험 구간에서 포함률·폭을 보고한다.
   표본이 부족하면 구간 보정을 검증하지 못했다고 명시한다. 상대 피크일과 실제 피크일의 차이는
   보조 평가로만 보고하며 임의의 혼잡 경보 기준을 만들지 않는다.
8. **채택 판단:** 2024년 검증에서 고른 단순 기준을 2025년 고정 구간에서 MAE·WAPE로 비교한다.
   개선하지 못하면 단순 기준을 유지한다. 유의미한 개선·현장 효용의 수치 기준은 현재 미검증이며,
   오차를 감당할 운영 범위는 실무 판단 과제를 통해 검증한다.

## 5. 다음 구현의 완료 조건

- 지역 일별 전체 수집·자료 버전 보존과 누락 보고서가 실제 데이터로 동작한다.
- 발행시점별 입력 가용성과 평가 모드(엄격 재현/현재 개정자료 실험)를 기계적으로 구분한다.
- 기준 모델 둘과 첫 자체 모델을 같은 날짜·시점에서 비교하고 결과와 예측 실패를 저장한다.
- 화면에 출처·자료의 마지막 날짜·예측 발행일·단위·불확실성·제공 불가 사유를 연결한다.
- 발표 총계와 지역 추세를 구별하는지, 주차·셔틀 판단에 무엇이 더 필요한지 실무자 과제로 확인한다.

첫 모델의 실제 오차는 [검증 보고서](09-model-validation.md)에 기록했다. 운영 비용 절감률·대기 감소율은 미검증이다.
