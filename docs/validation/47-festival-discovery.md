# 축제 유형으로 찾기와 문화관광축제 방문 규모

상태: **사용 가능 — 공개 반영·공개 화면 검증 완료(아래 '공개 배포').** [설계25](../design/25-festival-discovery.md) 1단계와
[인수 기준 TS-FC-022](../sdlc/3-testing/scenarios/TS-FC-022.md)에 따른 변경이다.

## 사용자에게 달라지는 점

- 기존 축제 찾기에 `축제 유형` 칩 일곱 개가 생겼다(전체·문화관광·문화예술·지역특산물·전통역사·생태자연·기타). 먹거리 축제는 `지역특산물 · 먹거리`.
  누르면 바로 거르고, 이름·지역과 함께 쓸 수 있다. 유형만 고르면 올해 그 유형의 전국 등록 축제를 날짜순으로 40건씩 본다.
- 칩 옆 `○○축제 N건 보기`로 결과로 바로 간다(휴대폰에서 결과가 화면 아래에 있어도). 결과 카드와 축제 머리에 등록 분류 표식이 붙는다.
- 새 화면 `문화관광축제 방문 규모`(`/compare/scale`): 데이터랩 문화관광축제 26곳을 연도별로 일평균·기간 합계·외지인 비율·현지인 비율 순으로 본다.
  막대 하나에 현지인·외지인·외국인을 쌓아 규모와 구성을 함께 보이고, 한쪽이 60% 이상이면 `외지인 중심`(관광 연계·숙박이 중요)·
  `현지인 중심`(교통편·프로그램이 중요)으로 표시한다. 2025년 하루 방문 최다는 부평풍물대축제(하루 88,369명), 외지인 비율 최고는 임실N치즈축제(88%),
  현지인 비율 최고는 목포항구축제(83%)다.
- 입구: 홈 `자료 조사·비교`의 `축제 방문 규모 →`, 축제 비교·연도별 방문 흐름 머리의 단추, 축제 검색 유형 줄의 `문화관광축제 방문 규모`.

## 검수(제품 경험)

| 항목 | 결과 | 근거 |
|---|---|---|
| 목표·흐름 | 충족 | 칩 한 번으로 유형 목록, 이름·지역과 결합, 결과로 가기. 방문 규모는 요약 → 기준 → 목록 순 |
| 시각적 위계 | 충족 | 칩 한 줄(1440px), 분류 표식은 작은 회색 알약, 순위 1~3 파랑 숫자, 막대 색 셋 고정 |
| 문구 경계 | 충족 | 분류 코드·내부 용어 없음(시험), 60% 표시가 이 서비스 기준임을 `기준`에 밝힘 |
| 상태·복구 | 충족 | 0건 안내, 공급처 실패 시 목록 전체 실패와 다시 불러오기(기존), 주소 값 되돌림 |
| 접근성·반응형 | 충족(자동) / 미평가(화면 낭독기 실사용) | `aria-pressed` 묶음·초점 유지·결과로 초점 이동·팝업 초점 복귀, 390px 가로 넘침 없음 |
| 필요한 고지 | 충족 | 방문자 정의(입장객 아님)·일평균 주의·외국인 0·26곳 한정·원문 링크, 분류 출처 |

검수 중 발견해 고친 결함:

- 방문 규모 목록의 순위 숫자가 넓은 화면에서 셋째 줄로 밀렸다. 반응형 칸 지정(`md:col-span`·`md:row-span`)이 시작 칸을 지워서였다 — 시작 칸을 다시 지정했다.
- 유형 줄이 두 줄이라 기존 축제 목록 첫 줄이 1440×1000에서 892px(기준 900px)까지 내려갔다. 라벨·칩·연결을 한 줄로 모아 852px로 되돌렸다.
- 휴대폰에서 칩을 눌러도 결과가 화면 아래라 바뀐 것이 보이지 않았다. 칩 옆 `N건 보기`(0건이면 `0건` 글자)를 더했다.
- 결과 제목으로 초점을 옮기면 고정 머리글에 가렸다. 제목에 위 여백(`scroll-mt-24`)을 주었다(검색 단추의 기존 이동에도 적용).
- 유형을 고른 목록에서 모든 카드가 같은 표식을 되풀이했다. 고른 유형과 같으면 생략한다.

## 남은 것·한계

- 2단계(체험·어린이·무료 표시)와 3단계(데이터랩 수동 보강)는 [설계25](../design/25-festival-discovery.md) 5절. 이동 시간 원은 사용자 결정으로 보류.
- 분류는 공급처가 붙인 값이다. 실제 축제 성격과의 일치는 검증하지 않았다(미평가).
- 방문 규모는 내려받은 26곳 한정이며 등록 분류 `문화관광축제`(64건)와 같은 목록이 아니다.

## 2단계 — 등록 소개 글 표시와 전국 모든 축제

상태: **사용 가능 — 공개 반영·공개 화면 검증 완료.** [설계25](../design/25-festival-discovery.md) 6절, [TS-FC-022](../sdlc/3-testing/scenarios/TS-FC-022.md) v2 M1~M6.
표시는 수집기가 소개 글을 읽은 축제에만 붙으며 첫날 200건, 이후 하루 40건씩 늘어난다(확인 전 축제는 거르기 줄에 수를 밝힌다).

사용자에게 달라지는 점:

- 결과 위 `소개 글로 거르기`: 체험·어린이·가족·무료 칩에 지금 목록에서 그 표시를 가진 축제 수가 붙는다. 여러 개를 고르면 모두 가진 축제만 남는다.
  아직 소개 글을 읽지 않은 축제는 수를 밝히고 거를 때 뺀다. 고른 표시는 주소에 남아 공유된다.
- 결과 카드와 축제 머리에 표시 알약, 축제 머리의 `소개 글 근거`에서 근거가 된 글 조각과 확인 시각을 본다(“실제 운영 여부는 주최 측 안내를 확인해 주세요”).
- `전체` 칩을 이름·지역 없이 누르면 올해 모든 축제(여섯 분류) 전국 목록이 열린다(로컬 실제 조회 486건). 처음 화면에서는 어느 칩도 눌려 있지 않고, 눌린 칩을 다시 누르면 풀린다.

구현·검증:

- 실제 표본 30건(2026-10~12 축제, 키 원문 미출력)으로 규칙을 맞췄다. 근거 조각은 모두 해당 낱말을 담았고(예: 금산세계인삼축제 — 체험 `인삼캐기체험여행`,
  어린이·가족 `가족전통놀이 체험 등`, `무료·일부 유료`), 숫자 안 쉼표로 잘리던 조각(`000원 (만 6세 이상 어린이`)을 화면 검수에서 찾아 고쳤다.
- 로컬 수집 시험: 등록 일정 조회 886건(17회), 소개 글 40건(40회). 40건 저장 파일 35.6KB. 운영 원천 저장소는 3.7MB(상한 128MiB)라 최대 4,000건도 여유가 있다.
- 단위 시험: 표시 규칙 4개(`festival-marks.test.ts`), 수집 5개(`intro.test.ts` — 분류 보존, 처음 200·이후 40회와 하루 한 번, 별도 시도 기록, 순서, 한도·접근 오류
  즉시 멈춤·같은 오류 세 번 멈춤·저장 유지·파일에 키 없음, 저장 검증), 서버 3개(모든 축제 목록 조건·공연 행 거부, 저장 표시 붙이기와 저장소 실패 시 표시 없음,
  축제 조회의 그때 읽은 표시·날짜 없는 소개 글·조회 실패 시 저장 표시).
