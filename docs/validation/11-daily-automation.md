# 매일 수집·사전 발행·결과 확인 연결

검증일: 2026-09-07. 매일 한국시각 09시에 최근 90일의 논산 방문 자료를 수집하고,
등록된 예측 발행과 결과 확인을 실행하는 기능을 구현했다. 기존 예측 2건은 원본 그대로 보존한다.
운영 배포는 검증된 이미지가 발행된 뒤 연결하며, 아래에 실제 실행 결과를 추가한다.
동작·호출 상한·실패 처리·복구 확인은 [운영 문서](../ops/forecast-automation.md)를 따른다.

## 변경 범위

- 기존 단일 Deployment·RWO PVC·API 자격 범위 안에서 별도 처리 컨테이너를 실행한다.
  처리 컨테이너는 예측 하위 디렉터리만 마운트하며 SQLite 파일에 접근하지 않는다.
- 날짜별 요청 시도를 먼저 보존하고 하루 20회 상한을 둔다. 재시작·중복 실행에서 같은 날 요청을 반복하지 않는다.
  정상 누락과 호출 실패를 구분하며 누락을 0으로 바꾸지 않는다.
- 공개 `/forecast/records`는 실행 상태·최신 자료·누락·예측·사후 결과·다음 발행 일정을 파일에서 읽는다.
  새 자료를 보여 주기 위해 앱을 다시 빌드할 필요가 없다. 처리 중단·요약 오류는 화면에 표시한다.
- 2026-09-28에 10월 5~8일 대상의 D-7 예측을 발행하도록 등록했다.
  지나간 날짜는 소급하지 않으며, 기존 D-7·D-28 기록은 새 수집본으로 덮어쓰지 않는다.
- 공휴일·축제 입력과 향후 시험 기준은 [다음 모델 계획](12-calendar-model-plan.md)에 정리했다.
  모델 v2나 새 정확도는 아직 제공하지 않는다.

## 실제 API를 사용한 로컬 확인

2026-09-07 20:03:42~20:03:53 한국시각, 격리된 `apps/web/output/daily-live/`에서
실제 worker의 `--once`를 실행했다. 2026-06-09~09-06의 90일을 **7회** 조회했다.
완료 61일·누락 29일·오류 0일이며 마지막 자료는 8월 8일이다. 실행 상태는 `partial`이다.
API 호출 실패가 아니며, 전체 날짜가 제공됐다는 뜻도 아니다.

수집본 버전은 `27b62290f60cf7d42e4886f043d0f6e8375bcfc9c34b668b0cdf86be680abab3`,
파일 전체 보관 해시는 `893488494d04afea9e176bc05c87b28dfc3351866bd0ecddb13b69c1737bca43`다.
기존 예측 2건의 ID·입력·계수는 유지했고 사후 결과는 둘 다 대상일 전이다.
이 확인은 운영 서버의 실제 실행과 구분한다.

## 운영 연결

코드 이미지 발행 → 원격 검증 → 이미지 digest 고정과 처리 컨테이너 연결 → 기존 등록 앱 sync →
첫 실제 실행·공개 화면 검증 순서로 진행한다. 이 절의 배포·실행 증거는 연결이 끝난 뒤 갱신한다.

관측 결과 도착과 내일 09시 실행은 아직 미래 사건이다. 첫 실행 성공만으로 장기 운영이나
예측 정확도를 확인했다고 기록하지 않는다. 2027년 엑스포는 기존 4일 축제와 기간이 달라
같은 예측 계약으로 자동 등록하지 않는다.
