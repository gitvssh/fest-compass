# 관광지 붐빔 예측과 함께 찾는 곳

상태: **사용 가능 — 공개 반영·공개 화면 검증 완료(아래 '공개 배포').** [설계28](../design/28-kto-spot-signals.md)과 [인수 기준 TS-FC-025](../sdlc/3-testing/scenarios/TS-FC-025.md)에 따른 변경이다.

## 사용자에게 달라지는 점

- 새 축제 `지역 관광자원`과 기존 축제 `주변 관광자원` 화면 아래에 두 카드가 생긴다.
  - **앞으로 30일 관광지 붐빔 예측:** 지역 관광지마다 앞으로 30일 동안 얼마나 붐빌지(공사 예측, 가장 붐비는 때 = 100). 날마다 관광지 평균,
    30일 평균이 높은 관광지, 날짜별 표. 예: 논산시 49곳, 30일 평균이 가장 높은 곳 강경근대거리.
  - **함께 찾는 곳:** 지역 중심 관광지를 찾은 뒤 내비게이션으로 이어서 찾은 관광지·음식점·숙박 순위(티맵 자료, 달마다).
    예: 논산시 2026년 8월 강경근대거리 → 탑정호출렁다리·선샤인랜드·미내다리.
- 개최 시기 화면은 그대로다(날짜 예측·추천 없음 기준 유지).

## 구현

- 조회 `lib/kto-signals/server.ts`: TourAPI 조회와 같은 경계(인증키·공급처 문구 비노출, 10초 제한, 크기·호출 수·동시 호출 제한, 메모리 보관만)로 두 서비스를 묻고
  쪽을 끝까지 읽는다(총건수가 바뀌면 쓰지 않음). 지역 코드 순서(이전 코드 → 현재 코드 → 시 전체), 엄격한 응답 검사.
- 주소 `/api/signals/crowd`, `/api/signals/related`(GET). 화면 `components/signals/CrowdForecast.tsx`·`RelatedSpots.tsx`, 두 관광자원 화면에 배치.
- 공통 `LoadState`에 다시 불러오기 단추 이름(`retryLabel`)을 더했다. 한 화면에 실패한 묶음이 여럿일 때 단추가 모두 `다시 불러오기`로 같아
  화면 낭독기와 자동 시험(`visitor-profile-e2e`)이 구분하지 못했다. 두 카드는 `붐빔 예측 다시 불러오기`·`함께 찾는 곳 다시 불러오기`를 쓴다.
