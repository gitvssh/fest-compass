# 관광데이터 표본 조사

앱 DB를 변경하지 않는 읽기 전용 CLI로 후보 축제와 6종 KTO API를 조사한다.
기존 실제 API 키를 환경변수 또는 Git 제외 .env에서 읽는다. 새 키 발급은 필요하지 않다.

```bash
cd apps/web
source ~/.nvm/nvm.sh
nvm use
npm run data:profile -- --output output/research/kto-profile-20260907.json
```

기본 검색어는 치즈·백제문화제·논산딸기다. 각 검색 첫 결과를 후보로 조회하며 최종 샘플을 자동 선정하지 않는다.
검색어는 `--keyword 치즈 --keyword 논산딸기`, 수요·연관 관광지 기준월은 `--month 202604`,
방문자 기간은 `--start 20260401 --end 20260403`으로 바꾼다. 기간은 최대 7일이다.
기본 날짜는 기존 8월 30일 검증과 대조하기 위한 과거 표본이며 최신 공개월을 뜻하지 않는다.

## 호출과 출력 계약

- 최대 3개 검색어, 전체 최대 32회, 각 요청 10초 제한. 인증·한도 오류는 추가 호출을 중지한다.
- 공통·축제 상세의 contentId와 날짜가 결합되고 KTO 법정동 코드가 유효할 때만 지역별 조회를 수행한다.
- 수요 API는 검증된 지역에 대해 시도 지정과 시군구 지정 각각을 표본 조회한다.
- 방문자는 전국 응답 첫 1000행, 나머지는 첫 50행(검색 5행·상세 1행)이다.
- `success`는 조회한 표본의 필수 필드 계약이 맞음을, `empty`는 인가된 0건 응답을 의미한다.
- `complete-response`는 이 요청의 totalCount와 받은 행이 같다는 뜻이다. 지역·과거 모든 기간의 자료 확보를 뜻하지 않는다.
- `sample-only`는 첫 페이지 표본이다. 행수·결측·날짜 범위를 전체 데이터 분포로 일반화하지 않는다.
- JSON에는 키·요청 URL·전체 응답 원문을 쓰지 않는다. 호출 조건·집계·공개 축제 식별정보만 기록한다.
- 보고서는 mode 0600, 새 파일 생성만 허용한다. 재실행 때 다른 파일명을 사용해 이전 증거를 보존한다.
- 오류가 하나라도 있으면 종료코드 1이며, 가능한 조사 결과는 보고서에 남는다. 빈 응답 자체는 오류가 아니다.

## 다음 조사

표본 결과로 빈 응답의 지역·시군구·월 조건을 좁히고, 최종 후보의 전체 페이징·다년 자료·측정 정의를
별도로 검증한다. 데이터 표본만으로 예측 가능성이나 실무 효용을 통과 처리하지 않는다.
