# 데이터랩 지역 4곳 — 해마다 합계 카드

상태: **사용 가능 — 공개 반영·공개 화면 검증 완료(아래 '공개 배포').** [설계30](../design/30-datalab-region-trends.md)과 [인수 기준 TS-FC-027](../sdlc/3-testing/scenarios/TS-FC-027.md)에 따른 변경이다.

## 사용자에게 달라지는 점

- `축제별 방문 자료`에서 강경젓갈축제·논산딸기축제(논산시), 석장리세계구석기축제(공주시), 원주다이내믹댄싱카니발·원주한지문화제(원주시),
  대구치맥페스티벌(달서구)에 개최지 카드가 생긴다: `○○ 관광 소비`(2020~2025 해마다·현지인/외지인·업종)와 `○○ 외지인 방문객`(2019~2025 해마다).
- 새 축제 `방문 흐름`에서 논산·공주·원주·달서구를 고르면 `연도별 방문 합계`(외지인, 2019~2025)와 `관광 소비` 카드가 보인다. 논산은 이 서비스의 시범 지역이다.
- 같은 시도 순위·읍면동·거주지는 이 자료에 없어 보이지 않고, 기준 팝업에 그렇게 적는다.

## 받은 자료 확인(원문, 2026-10-05)

| 확인 | 결과 |
|---|---|
| 공식 ZIP 9개·CSV 20개 | 소유자 `다운로드목록.csv`의 ZIP·CSV SHA-256과 행 수가 모두 같다. ZIP을 직접 풀어 풀어 둔 CSV와 바이트까지 같다 |
| 관광소비 4곳 × 6년 | 업종 대분류 합 = 전체, 내국인 = 현지인 + 외지인(1천 원 이내). 업종 대분류 7개는 처음 26곳의 대분류와 같은 이름 |
| 외지인 방문 4곳 × 7년 | 2019 비교 연도 + 2020~2025. 전년 값·증감률이 앞 행과 맞다(2020 행은 원문에서 전년 값이 비어 있음) |
| 일별 자료와 대조 | 논산·공주 2023~2025 = 앱의 한국관광공사 일별 외지인 방문 연간 합계(논산 2025 17,451,010, 공주 2025 25,786,708). 일별 원문의 반 단위 값 때문에 최대 0.5 차이 |
| 처음 26곳과 같은 지표인지 | 처음 가져오기 임실의 연간 외지인 값(2023~2025)도 일별 합계와 같다 → 같은 연도별 방문 합계 블록에 넣는다 |
| 논산 종합분석(AI 관광 분석 4개) | 보관만. 안내문대로 카드에는 쓰지 않음 |

## 구현

- 보관 `docs/research/imported/datalab-regions-2026-10/`([설명](../research/imported/datalab-regions-2026-10/README.md)), `scripts/datalab-owner-regions.mjs`.
- 생성 `scripts/build-datalab-region-trends.mjs` → `apps/web/data/datalab-region-trends.json`, 검토표 `apps/web/data/datalab-region-trend-ids.json`(코드·시도·축제 연결·ZIP).
  축제 연결은 목적지 순위로 정한 지역이 검토표 `addressPrefix`와 같을 때만, 처음 26곳 지역·연결과 겹치지 않게.
- 읽기 `lib/datalab/region-trends.ts`(엄격 검사, 원문 링크만 공개), 화면 `components/RegionTrend.tsx`. 축제 묶음 응답에 `hostTrend`, 새 축제 응답에 `regionTrend`,
  연도별 방문 합계는 처음 26곳 값이 없으면 이 4곳의 외지인 값으로(현지인·내국인 전체 열은 숨김).

## 검증

- `npm test` 502개 통과(47+402+53). 생성 시험 7개: 결정성, 9 ZIP·20 CSV와 보관만 하는 표, 4곳 코드·연결·원문 값, 일별 합계와 대조, 관광소비·방문 해석 거부 사례,
  ZIP·CSV 변조·목록 밖 파일·사용 표시 변경·연결 바꾸기·이중 연결·시도·ZIP 종류·지역 빠짐 거부. 읽기 시험 6개, 새 축제 응답 시험 1개(외지인만 연도 합계·카드·실패 격리).
- 모든 생성 결과 `--verify` 통과, 타입 검사·보안 점검·전체 빌드·인프라 시험 41건·등록 검사 통과(발행 사전 검증과 같은 순서).
- 전체 headless 32종 통과(최종 빌드, 새 시험용 DB). 처음 묶음에서 두 시험이 예전 상태를 기대해 실패했다: 공주 2026(일별 자료 없음)이
  이제 연도별 합계가 있어 `2026년 월·요일별 방문 자료가 없어요.`로, 논산 소개 줄이 임실처럼 `일평균 명/일` 없이 나오는 것은 기존 화면 규칙대로다.
  기대값을 고쳤고, `annual-trend-e2e`에 논산딸기축제·대구치맥페스티벌의 개최지 카드 값, `new-festival-e2e`에 논산 관광 소비 카드·종로 카드 없음,
  `visitor-context-e2e`에 논산 연도별 합계(원문 CSV에서 직접 읽은 기대값)와 외지인 열만 있는 표를 더했다.
