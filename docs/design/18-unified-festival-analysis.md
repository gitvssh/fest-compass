# 고른 축제 모두에 같은 분석 흐름 제공

**상태: 구현·로컬 검증 완료, 공개 반영 대기.** 실행 결과와 공개 상태는 [기록40](../validation/40-unified-festival-analysis.md)을 따른다.
인수 기준은 [TS-FC-015](../sdlc/3-testing/scenarios/TS-FC-015.md), 기존 흐름은 [UC-FC-009](../sdlc/1-analysis/usecases/UC-FC-009.md)를 따른다.

## 1. 사용자 정정과 목표

2026-09-26 사용자 정정: 특정 축제를 하나씩 추가하는 방식이 아니라 **담당자가 검색해 고른 축제라면 어떤 것이든**
같은 방문 흐름·주변 관광자원·개최 시기 경험으로 들어가야 한다. 새 축제를 지원하려고 축제별 코드 수정·재배포를 하지 않는다.

| 이전 방식 (2026-09-24까지) | 이번 방식 |
|---|---|
| 보관 회차가 있는 논산·임실 등 소수 축제만 방문 분석. 현재 등록만 있는 축제는 방문 화면에서 짧은 기록 없음 상태 | 모든 등록 축제가 자기 시군구의 외지인 방문 흐름을 기본으로 본다. 검토된 과거 회차가 있으면 같은 자리에서 회차 비교로 확장 |
| 전국 시군구 방문 이력 확대는 범위 밖 | 공식 API로 전국 시군구 일별 방문을 보관·갱신한다 |

축제 입장객·축제 효과·방문자 성·연령 같은 축제 단위 지표를 모든 축제에 약속하지 않는다.
이 흐름이 모든 축제에 보장하는 것은 **축제가 등록된 시군구 전체의 방문 흐름**, 현재 관광자원, 개최 시기 여건이다.

## 2. 공통 흐름과 보장 범위

| 메뉴 | 모든 등록 축제 (공통 핵심) | 검토된 과거 회차가 연결된 축제 | 하지 않는 것 |
|---|---|---|---|
| 방문 흐름 | 시군구 외지인 방문의 월별 일평균, 고른 월의 일별 선과 수치 표. 제공처에 실제 등록된 일정이 있으면 그 연월로 가는 바로가기 | 기존 회차 차트·요약(UC-FC-009 AC1~14)을 같은 화면 안에 그대로 표시 | 과거 개최일 추정, 같은 날짜의 전년도 가짜 기간, 방문 인원을 축제 실적으로 표시 |
| 관광자원 | 축제의 확인된 시군구의 관광지·문화시설 지도·목록(기존) | 같음 | 실제 이동 경로 단정 |
| 개최 시기 | 같은 시군구 월별 일평균 → 달력·공휴일·등록 행사·후보 기간(기존) | 같음 | 최적일 점수, 미래 방문 예측 |

임실의 개최 행정동 방문 구성·방문자 특성·두 회차 비교처럼 **특정 축제에서만 확보한 보조 자료**는 공통 핵심과 분리한다.
해당 축제에서 기존 방식대로 계속 제공하며, 다른 축제에 같은 영역이 없더라도 빈 카드나 사유 문구를 두지 않는다.
모든 축제에 과거 회차·방문자 특성·예시 자료를 제공한다고 약속하지 않는다.

## 3. 기본 배치

최종 시각 디자인은 사용자 작업이며 아래는 정보 순서·기본 배치다. 새 시각 시안은 만들지 않는다.

### 방문 흐름 · 과거 회차 연결이 없는 축제

```text
축제명 · 시도 시군구 · 2026.10.3–10.5 (현재 등록 일정)     관련 자료 검색
과거 방문 / 관광자원 / 개최 시기

○○군 외지인 방문 흐름
  시군구 전체 · 하루 평균 외지인 방문(명)
  관측연도 [2023] [2024] [2025]
  월별 하루 평균 막대 (값 없는 달은 비움)
  등록된 일정  2025.10.4–10.6 · 2024.10.5–10.7   [2025년 10월 보기]
  ── 선택한 달: 2025년 10월 ──
  일별 선 (값 없는 날은 끊음) · 날짜·요일·값 수치 표
  출처 보기
```

그림의 날짜·지역은 자리 표시다.

- 제목은 `<시군구> 외지인 방문 흐름`이다. 축제명은 머리에만 두고 방문값의 대상으로 쓰지 않는다.
- 선택한 월은 관측 탐색일 뿐이다. `개최기간`·`축제 기간` 음영이나 표시를 붙이지 않는다.
- `등록된 일정`은 그 축제 ID·지역으로 제공처에 실제 등록된 날짜만 보여준다. 누르면 그 연월을 연다.
  등록 일정이 없는 연도에 올해 날짜를 옮겨 과거 기간을 만들지 않는다. 월 일부만 관측된 경우 등록 기간 평균을 계산하지 않는다.
  등록 기록은 수집을 시작한 뒤 관측한 날짜부터 쌓이므로 그 이전 연도에는 바로가기가 없는 것이 정상이다.
- 연도·월 선택은 이 방문 화면 전용 조건으로 주소와 탭 기억에 남기며, 다른 메뉴의 연월·후보 선택을 덮지 않는다.
- 수집·보관·연결 방식, 지원 축제 목록 같은 내부 설명은 화면에 두지 않는다.

### 방문 흐름 · 검토된 과거 회차가 연결된 축제

현재 등록 축제의 이름·주소·메뉴 경로를 그대로 두고, 방문 본문만 기존 회차 비교 화면(회차 선택·회차 차트·보조 영역)으로 채운다.
별도의 보관 축제 화면으로 이동시키지 않는다. 연결은 제공처 콘텐츠 ID·지역·검토 근거가 기록된 연결표의 정확한 일치로만 만든다.
2026-09-26 기준 연결표는 임실N치즈축제(2031318)·논산딸기축제(525292)이며 서버·화면 연결을 검증했다.
이름·지역이 비슷하다는 이유로 자동 연결하지 않는다.

### 검색 결과

같은 축제로 검토된 현재 등록·보관 축제는 **현재 등록 카드 하나**로 합치고 확인된 과거 개최연도를 짧게 덧붙인다.
연결이 확인되지 않은 같은 이름의 결과는 지역·일정으로 구분한 별도 결과로 남긴다. 제공처 하나의 실패는 그 영역만 재시도하며
페이지 이어보기·기억한 선택을 유지한다. 검색어 없이 처음 열면 기존처럼 보관 축제를 시작 선택지로 보여줄 수 있다.

## 4. 상태와 복구

| 상황 | 화면 | 다음 행동 |
|---|---|---|
| 축제 확인 중 | 머리·메뉴 자리의 확인 중 상태 (`FestivalPending`) | 기다림. 확인 전에는 `지난 개최 기록이 없어요`를 보이지 않는다 |
| 시군구 방문 자료가 없음 | 방문 자리 한 곳에 짧은 자료 없음 | `주변 관광자원 보기`·`개최 시기 보기` |
| 일부 날짜 값 없음 | 선을 끊고 표 `—`. 불완전 월평균·기간 평균은 만들지 않음 | 다른 월·연도 |
| 방문 조회 실패 | 방문 자리만 실패·재시도 | 자원·시기는 계속 이용 |
| 등록 일정 기록 없음 | `등록된 일정` 줄을 생략 | 연도·월 직접 선택 |

## 6. 수집·보관 계약 요약

- 독립 수집기는 전용 경로 `/data/festival-sources`와 커널 파일 잠금으로 하루 한 번 실행한다. 공개 웹은 보관소에 쓰지 않는다. [운영 절차](../ops/festival-sources.md)를 따른다.
- 일상 갱신은 하루 최대 30회 호출로 최근·직전 90일 방문(약 12페이지)과 전국 축제 등록 조회(약 9페이지)를 나눠 쓴다.
  2023-01부터 전월까지의 최초 과거 채우기는 하루 최대 180회(같은 날 일상 갱신 포함), 중단 후 다음 날 이어서 진행한다. 무제한 재시도는 없다.
- 한 원천이 실패하면 그 원천의 마지막 정상 보관본을 유지하고 다른 원천은 계속 갱신한다. 불완전한 등록 조회는 적용하지 않는다.
- 보관 파일은 원자적으로 교체하고 크기 상한·읽기 시 검증을 둔다. 키·제공처 주소·원문 오류는 기록·출력하지 않는다.
- 등록 일정 기록은 같은 콘텐츠 ID·같은 지역에서 실제 관측한 날짜만, 시작 연도별 최신 관측 하나를 남긴다.
  지역이나 이름이 바뀐 이전 기록을 이어 붙이지 않는다.
- 기존 논산 예측 입력·모델 파일, 보관 회차 주소와 시험 자료는 바꾸지 않는다.

첫 실제 수집은 141회로 2023-01~2026-08의 44개월 자료·축제 등록 867건·현재 조회 단위 269곳을 보관했고,
당월 확인 1회는 정상 빈 응답이었다. 44개월이 모두 완전하다는 뜻은 아니다. 최신 관측일은 2026-08-27이며 미관측 날짜는 비워 둔다.
행정안전부 공식 법정동 코드 변경표로 확인한 전남·광주 27곳은 일대일로 연결한다. 분할·합병된 인천의 옛 3개 코드는
배분하지 않고 신설 지역 자신의 관측부터 제공한다. [원문·대조 근거](../research/imported/mois-2026-region-codes/README.md)를 보존했다.

## 7. 이전 설계와의 관계

- [기능 상세 §2·§5·§6](../sdlc/2-design/functional-spec.md)의 `현재 등록 정보만 있는 축제 → 짧은 조회 상태`와
  `국가 전체 이력 확대는 계획에 없음`은 이 문서가 대체한다. 당시 구현·검증 기록([기록34](../validation/34-existing-festival-journey.md))은 그대로 유효하다.
- 임실·논산 보관 회차와 기록37~39의 보조 영역은 그대로 사용 가능하다.
- 월별 일평균·결측 처리는 새 축제 기획(UC-FC-010) 지역 방문 흐름과 같은 규칙을 따른다.
  새 축제 화면의 전국 자료 연결 여부는 주 담당자의 검증 기록을 따른다.
