## UC-01. KTO 검색으로 축제 등록

- **주 액터**: A1 총괄기획 · **화면**: SCR-01 → SCR-02 · **관련**: ACT-01, ACT-02, API-EXT-A/B
- **사전조건**: `TOUR_API_KEY` 설정, 국문 관광정보 활용신청 승인
- **사후조건**: Festival 생성(labelLevel=L0), 기본 가정 4종·시나리오 3종 골격 생성, 근거 스냅샷 수집 시도, SCR-02로 이동

**기본 흐름**
1. A1이 SCR-01에서 축제 이름 키워드를 입력하고 검색한다.
2. 시스템이 `searchKeyword2`(contentTypeId=15)를 호출하고 결과 목록(이름·주소·기간)을 관측값 배지와 함께 보여준다.
3. A1이 목록에서 자기 축제를 선택("이 축제로 시작")한다.
4. 시스템이 `detailCommon2`로 상세를 보강해 Festival을 생성한다 — 이름·장소·기간·지역코드·좌표·contentId를 사전채움하고, 개요(overview)를 프로그램 필드에 180자까지 요약 저장한다.
5. 시스템이 UC-03(근거 새로고침)을 자동 실행한다.
6. SCR-02(근거·가정)로 이동한다.

**대안 흐름**
- 2a. 검색 결과가 비어 있으면: "검색 결과가 없습니다. 직접 입력으로 계속할 수 있습니다"를 표시하고 UC-02로 유도한다. 오류로 취급하지 않는다(정상 상태).
- 3a. 목록에 자기 축제가 없으면: UC-02로 진행하되 입력한 키워드를 이름 필드에 미리 채운다. [신규 — 현재는 미채움]

**예외 흐름**
- E1. 키 없음: 검색 폼 대신 "TOUR_API_KEY가 없어 검색을 건너뜁니다" 안내를 표시하고 UC-02만 가능하다. [구현됨]
- E2. API 오류(HTTP 오류·타임아웃·파싱 실패): 오류 종류를 `ApiCallLog`에 남기고, 화면에는 "관광정보를 불러오지 못했습니다. 직접 입력으로 계속하세요"를 표시한다. 재시도 버튼 1개. 자동 재시도는 하지 않는다.

## UC-02. 축제 직접 등록

- **주 액터**: A1 · **화면**: SCR-01 → SCR-02 · **관련**: ACT-02
- **사전조건**: 없음 (키·네트워크 불필요 — L0에서도 정직하게 작동하는 원칙)
- **사후조건**: UC-01과 동일 (스냅샷은 키 있을 때만 수집)

**기본 흐름**
1. A1이 SCR-01 우측 폼에 이름(필수)·운영조직·장소·프로그램·기간·지역코드·작성자를 입력한다.
2. 시스템이 Festival을 생성하고 기본 가정 골격(피크비율 0.35, 운영시간 8h 기본값 — 04 §FR-EVD-2)과 시나리오 3종 골격을 만든다.
3. UC-03을 자동 실행(키 없으면 결측 기록 후 통과)하고 SCR-02로 이동한다.

**예외 흐름**
- E1. 이름 없이 제출: 브라우저 required + 서버에서 거부("축제 이름은 필수입니다").
- E2. 시작일이 종료일보다 늦음: 서버에서 거부하고 폼 값을 유지한다. [구현·회귀검증됨]
- E3. 지역코드가 매핑 불가(`toStdAreaCd` null): 등록은 진행하되 DataQuality에 "지역코드 매핑 없음"을 기록하고 SCR-02 결측 패널에 노출한다. [구현됨]

## UC-03. KTO 근거 새로고침

- **주 액터**: A1 (버튼), 시스템(등록·복제 시 자동) · **화면**: SCR-02 · **관련**: ACT-08, API-EXT-A~F
- **사전조건**: Festival 존재
- **사후조건**: API별 최신 스냅샷 생성(기존 관측 스냅샷은 stale 처리), 호출 전건 ApiCallLog 기록

**기본 흐름** (조회 기간 정의는 05 §1.4 — D4 결정)
1. A1이 SCR-02에서 "KTO 다시 불러오기"를 누른다.
2. 시스템이 기존 관측 스냅샷을 stale=true로 표시한다.
3. contentId가 있으면 `detailCommon2` 호출 → 축제 메타 스냅샷.
4. 시작일이 있으면 `searchFestival2`로 동기간·동지역 행사를 조회, 자기 자신(contentId 동일)을 제외한 상위 5건을 겹침 스냅샷으로 저장.
5. 지역코드 매핑이 있으면: 지역별 방문자(전년 동기간+평시 기준선), 수요 강도(전년 동월), 집중률, 연관 관광지[신규 D9] 스냅샷 저장.
6. 각 스냅샷에 출처 URL·기준일·집계정의(aggregation)·허용 해석(interpretation)·금지 해석(prohibition)을 함께 저장한다.

**예외 흐름**
- E1. 키 없음: 호출을 전부 건너뛰고 DataQuality(`key_absent`)를 기록한다. 기존 스냅샷·수동 입력은 유지된다. [구현됨]
- E2. 개별 API 오류: 해당 스냅샷을 status="error"로 저장하고 나머지 API는 계속 호출한다. 이전 성공값이 있으면 stale 배지와 함께 계속 표시된다.
- E3. 빈 결과: status="empty"로 저장한다. 화면은 "없음"을 표기하고 0이나 이전 값으로 채우지 않는다.

## UC-04. 방문 규모 가정 입력·개정

- **주 액터**: A1 · **화면**: SCR-02 · **관련**: ACT-03, FR-EVD-3(D7)
- **사전조건**: Festival 존재
- **사후조건**: 가정 4종(유입 min/base/max, 체류, 운영시간, 피크비율)이 **같은 version으로** 새 행 추가(이력 보존), 시나리오 계산 재실행·저장

**기본 흐름**
1. A1이 근거 카드(지역 배경선·겹침 행사)를 확인한다. 화면은 "지역 방문자는 행사장 입장객이 아닙니다" 가드레일을 항상 표시한다.
2. A1이 최소·기준·최대 유입, 평균 체류시간, 운영시간, 피크비율, 가정 근거(rationale), 작성자를 입력하고 저장한다.
3. 시스템이 가정 세트를 version+1로 저장하고(기존 행은 남김), 모든 시나리오의 수용 계산을 갱신한다(FR-SCN).
4. 화면에 "v{n} 저장됨 · 작성자"를 표시한다.

**예외 흐름**
- E1. min > base 또는 base > max: 저장 거부, "최소 ≤ 기준 ≤ 최대 순서여야 합니다" 표시. [구현·회귀검증됨]
- E2. 음수·0 운영시간: 저장 거부. [신규]
- E3. 일부 필드만 입력: 저장은 허용하되 빈 필드는 null 유지(0 치환 금지). 계산은 입력이 갖춰진 항목만 수행된다.

## UC-05. 승인 수용량 기준 입력

- **주 액터**: A2 안전담당 · **화면**: SCR-02 · **관련**: ACT-04, FR-CAL-2
- **사후조건**: CapacityRule 갱신(구역·수용량·기준문서·승인자), 시나리오 계산 갱신

**기본 흐름**
1. A2가 구역명, 승인 수용량(명), 기준문서(예: "2026 지역축제 안전관리계획 §4"), 승인자를 입력한다.
2. 시스템이 저장하고 시나리오 계산을 갱신한다.

**핵심 규칙** (기획서 §6.4, 2026-08-30 교정 적용됨)
- 기준문서와 승인자가 **모두** 있어야 수용여유·점유율·경고가 계산된다(`hasApprovalBasis`).
- 없으면 화면은 "기준문서·승인자 미확인 — 안전 계산 꺼짐"을 명시한다. 수치 자체를 숨기는 것이 아니라 계산이 꺼진 이유를 보여준다.

## UC-06. 시나리오 비교·결정

- **주 액터**: A1(결정·승인 기록), A3(자원 검토) · **화면**: SCR-03 · **관련**: ACT-05, FR-SCN(D1)
- **사전조건**: 가정 세트 존재(없으면 계산 없이 자원 항목만 비교)
- **사후조건**: Decision 생성(선택 시나리오·변경 요약·이유·승인자·시각), 원장에 반영

**기본 흐름** (D1: 시나리오=자원 대안, 평가=유입 3값 전부)
1. 시스템이 시나리오 3종(보수·기본·확대)의 자원(셔틀·주차인력·회차·동선)과, 각 시나리오에 대해 유입 최소·기준·최대에서의 피크 동시체류·수용여유·점유율 매트릭스를 표시한다.
2. A1·A3이 확대안의 최악 케이스(최대 유입) 점유율이 임계 아래인지 확인한다.
3. A1이 시나리오의 자원 값을 수정할 수 있다(수정 시 즉시 재계산). [신규 — 현재는 고정값]
4. A1이 한 안을 선택하고 이유·승인자를 입력해 "이 안으로 결정"을 누른다.
5. 시스템이 Decision을 기록하고(변경 요약은 자원 전 항목 포함 — FR-SCN-4), 원장(SCR-04)에 나타난다.

**예외 흐름**
- E1. 이유 또는 승인자 누락: 저장 거부("선택 이유와 승인자는 필수입니다"). [구현됨]
- E2. 계산 불가(가정 결측): 매트릭스 셀에 "없음"을 표시하고 결정 자체는 허용한다 — 근거 없는 결정임이 기록에 남는 것이 원칙에 부합.
- E3. 이미 결정이 있는 상태에서 재결정: 새 Decision을 추가한다(이력 보존, 최신이 현재 결정). 기존 결정을 수정·삭제하지 않는다.

## UC-07. 대응 트리거 등록 [신규 D2]

- **주 액터**: A1, A2 · **화면**: SCR-04(트리거 섹션) · **관련**: ACT-09, FR-TRG
- **사전조건**: Festival 존재
- **사후조건**: OperationTrigger 생성(조건·임계 설명·대응 조치·책임자)

**기본 흐름**
1. D-3 시점에 A1·A2가 트리거를 등록한다. 예: 조건 "A구역 혼잡 임계 초과(점유율 85%)", 조치 "우회 동선 개방", 책임자 "현장총괄".
2. 시스템이 트리거 목록을 원장 상단에 표시한다.
3. 행사일에 UC-08에서 조치 기록 시 이 트리거를 선택해 연결할 수 있다.

**예외 흐름**
- E1. 조건·조치·책임자 중 누락: 저장 거부.

## UC-08. 현장 조치 기록

- **주 액터**: A5 현장총괄 · **화면**: SCR-04 · **관련**: ACT-06, FR-LGR-2
- **사후조건**: FieldAction 생성(트리거 연결은 선택), 원장·보고서에 반영

**기본 흐름**
1. A5가 발생 시각, 트리거(등록된 트리거 선택 또는 자유 입력), 조치 내용, 담당자를 입력한다.
2. 시스템이 기록하고 원장 타임라인에 표시한다.

**예외 흐름**
- E1. 시각 형식 오류: "YYYY-MM-DD HH:mm" 형식 안내 후 거부. [신규 — 현재 자유 텍스트]

## UC-09. 실측 입력과 라벨 전이

- **주 액터**: A4 성과담당 · **화면**: SCR-04 · **관련**: ACT-07, FR-LBL(D6)
- **사후조건**: Outcome 생성(계획값·실제값·출처·측정방식·granularity), 라벨 자동 전이

**기본 흐름**
1. A4가 지표명, 계획값, 실제값, 단위, 출처(예: "주최 측 일별 추정 총계"), 측정방식, **집계 단위(총계/시간대별/구역별)** 를 입력한다.
2. 시스템이 저장하고 라벨을 전이한다: 최초 실측 → L1, 시간대별 또는 구역별 실측 → L2.
3. 전이 시 SCR-02 라벨 게이트 문구가 바뀐다(03 §상태 매트릭스).

**예외 흐름**
- E1. 실제값 없이 계획값만: 허용(계획 미대조 상태로 표시). 실제값이 비면 "없음" 표기.
- E2. 출처 없는 실제값: 저장은 허용하되 보고서에서 "출처 없음"이 그대로 노출된다(고무줄 집계의 반대편 원칙 — 출처 없음을 숨기지 않고 보여준다).

## UC-10. 사후보고서 열람·출력
