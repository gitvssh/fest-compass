### 0.2 라벨 게이트 상태 매트릭스 [변경 — 현재 L0/L1만 구현]

라벨 게이트 배너(SCR-02 상단)와 기능 허용 범위. 기획서 §6.3의 화면 전개.

| 라벨 | 배너 문구 | 허용 | 차단(화면에서 노출 안 함) |
|---|---|---|---|
| L0 | "실측 라벨이 없습니다. 가정 범위와 시나리오만 사용합니다." | 가정·시나리오·결정·트리거 | 예측·오차 관련 일체 |
| L1 | "일별 총계만 있습니다. 시간·구역 정밀예측은 없습니다." | + 총량 계획 대비 실제 대조 | 시간·구역별 정밀 표시 |
| L2 | "시간/구역 단위 실측이 있습니다. 피크 재현과 수용량 검증에 사용합니다." [신규] | + 피크 시간대 재현 표시 | 인과효과 서술 |
| L3 | MVP 범위 밖 — 배너 없음 (도달 불가) | — | — |

전이 규칙은 04 §FR-LBL. 배너는 `festival.labelLevel`만으로 결정된다(파생 계산 금지).

### 0.3 카피(문구) 규칙

- 기획서 §8.4 표를 따른다. 특히 화면·코드 문자열에 다음을 절대 쓰지 않는다:
  "예측 정확도", "정확한 흥행 예측", "AI 안전판단", "완전 자동 최적화" (e2e가 "예측 정확도" 부재를 검사)
- 관측값 카드에는 항상 출처 API명·기준일·호출시각을 병기한다.
- 가상 시드 축제에는 "예시 시나리오" 배지를 유지한다(개선안 §7).
- 사용자 대상 문구는 발표체가 아닌 업무 안내체("~합니다")로 통일.

## SCR-02. 근거·가정 — `/festivals/[id]/evidence` [구현됨]

**목적**: 화면마다 하나의 결정 원칙 — 이 화면의 결정은 "유입 가정 범위 확정"이다.
레이아웃(위→아래): 안내행+새로고침 버튼 → 라벨 게이트 배너 → 근거 카드 4장(2×2) → 가정 폼 → 수용량 폼 → 결측 패널.

**근거 카드** (전부 observation 배지 + 출처·기준일·호출시각 + prohibition 문구)

| 카드 | 데이터 | 상태 표시 | 변경 |
|---|---|---|---|
| 확인된 사실 | 이름·장소·일정·프로그램 (detailCommon2/searchFestival2) | 결측 "없음" | [구현됨] |
| 동기간 인근 행사 | searchFestival2 겹침 상위 5건 | 빈 결과: "겹치는 행사 목록 없음. 일정 판단은 담당자 입력으로 이어갑니다" | [구현됨] |
| 지역 방문 배경선 | locgoRegnVisitrDDList 시계열 표(기준일·구분·순방문자, 6행) | Guardrail "행사장 입장객이 아닙니다" 상시 | [변경 D4] 전년 동기간·평시 기준선 두 구간을 구분 표시: 표에 `구간` 열 추가(평시/전년 동기간/당해) |
| 시기·분산 보조신호 | areaTarExpDsList 지수 + tatsCnctrRatedList | 빈: "없음" | [변경] 실응답 필드 확정 후 표시값 확정. [신규 D9] 연관 관광지 상위 3건 추가 |

**가정 폼** (ACT-03, assumption 배지)

| 필드 | name | 검증 [신규] |
|---|---|---|
| 최소/기준/최대 유입 | inflowMin/Base/Max | 숫자≥0, min≤base≤max |
| 평균 체류(시간) | dwellHours | 0<x≤24 |
| 운영시간 | operatingHours | 0<x≤24 |
| 피크비율 | peakRatio | 0<x≤1 |
| 가정 근거 | rationale | 권장(비면 저장 허용, 보고서에 "없음" 노출) |
| 작성자 | author | 기본 "총괄기획" |

저장 후: "가정 세트 v{n} 저장됨" 피드백 [신규 — D7 세트 버전 표시].

**수용량 폼** (ACT-04): 구역·승인 수용량·기준문서·승인자.
하단 고정 문구 "기준문서와 승인자가 없으면 안전 관련 자동 권고는 켜지지 않습니다." [구현됨 — 계산도 2026-08-30부터 일치]

**결측 패널**: DataQuality 행 나열(issue·note). key_absent·매핑 없음·정의 불일치 등. [구현됨]

## SCR-03. 시나리오 비교 — `/festivals/[id]/scenarios` [변경 D1]

**목적**: 이 화면의 결정은 "운영자원 대안 선택"이다.

**현재 구현**: 시나리오 카드 3장, 각 1개 유입값으로 계산(보수=최소, 기본/확대=기준) → **폐기**.

**변경 후 설계 — 매트릭스 표**:

```text
┌─────────────┬──────────────┬───────────────────────────────────────────┐
│             │ 자원(비교 변수) │        점유율 (유입 가정별 계산값)              │
│  시나리오     │ 셔틀 주차 회차  │   최소 1.2만   기준 1.8만    최대 2.6만        │
├─────────────┼──────────────┼───────────────────────────────────────────┤
│ 보수안       │  2   4   3   │    53% ok     79% ok      114% over       │
│ 기본안       │  2   4   3   │    53% ok     79% ok      114% over       │
│ 확대안 ✓선택  │  3   6   3   │    53% ok     79% ok      114% over       │
└─────────────┴──────────────┴───────────────────────────────────────────┘
```

주: 점유율은 유입·체류·운영시간·수용량의 함수라 시나리오 간 동일하다(자원은 점유율 계산에 안 들어감).
따라서 **매트릭스의 역할은 "어떤 유입 수준에서 경고가 켜지는가"를 보여주고, 자원 행은
그 위험에 대한 대응 수준을 비교하는 것**이다. 각 시나리오 카드에는 다음을 표시한다:

| 요소 | 내용 |
|---|---|
| 자원 항목 | 셔틀·주차 안내·회차·동선 메모(routeNote) — [신규] 인라인 수정 가능, 수정 시 재계산·저장(ACT-05a) |
| 위험 대응 요약 [신규] | "최대 유입(2.6만) 시 점유율 114% — 이 안의 대응: 셔틀 3대·우회 동선 예비" 형식. 자원과 위험을 한 문장으로 연결 |
| 경고 배지 | occupancyWarning: ok(여유)/watch(85%↑)/over(100%↑)/off(계산 꺼짐) — 문구는 현재 구현 유지("자동 안전판단이 아니라 비교 신호입니다") |
| 결정 폼 | 이유(필수)·승인자(필수) → ACT-05 |

**보조 요소** [구현됨 유지]: 안전 계산 꺼짐 배너, 기록된 결정 섹션(최신 결정 + [신규] 과거 결정 이력 접기), 계산식 섹션(3개 공식 노출).

## SCR-04. 결정·성과 원장 — `/festivals/[id]/ledger` [변경 D2]

**목적**: 계획(결정·트리거)과 실제(조치·실측)를 같은 기준으로 잇는다.
레이아웃: 타임카드 3장(D-3 결정 / 행사일 조치 / D+14 대조) → [신규] 트리거 섹션 → 현장 조치 섹션 → 계획 대비 실제 섹션 → 하단 버튼(보고서·복제).

**[신규] 대응 트리거 섹션** (ACT-09, UC-07)

| 필드 | name | 필수 |
|---|---|---|
| 조건(임계 설명) | condition | ✅ 예: "A구역 점유율 85% 초과" |
| 대응 조치 | plannedAction | ✅ 예: "우회 동선 개방" |
| 책임자 | owner | ✅ |

목록 행: "조건 → 조치 · 책임자 {owner}". 연결된 FieldAction이 있으면 "실행됨 {시각}" 배지.

**현장 조치 섹션** (ACT-06) [변경]

| 필드 | name | 변경 |
|---|---|---|
| 발생 시각 | occurredAt | [신규] `datetime-local` 입력으로 교체, 저장 형식 "YYYY-MM-DD HH:mm" |
| 트리거 | triggerId 또는 trigger | [신규] 등록된 트리거 셀렉트 + "직접 입력" 옵션. 선택 시 계획된 대응, 직접 입력 시 계획 밖 대응으로 구분 표시 |
| 조치 | action | 필수 [구현·회귀검증됨] |
| 담당자 | actor | |

**계획 대비 실제 섹션** (ACT-07) [변경 D6]

기존 필드(지표·계획·실제·단위·출처) + 측정방식(measureMethod),
집계 단위 셀렉트(granularity: 총계/시간대별/구역별 — 라벨 전이 근거) + 집계 구간(bucketLabel).
시간대별·구역별은 집계 구간이 필수이며, L2에서는 같은 지표·단위 안의 최대 행을 "피크 시간대" 또는 "최대 구역"으로 재현한다.
안내 문구 유지: "KTO 지역방문자를 입장객으로 넣지 마세요."
