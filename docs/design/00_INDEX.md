## 구현 현황 요약 (2026-08-30 기준)

`apps/web`은 Next.js 15(App Router, 서버 액션) + Prisma(SQLite) MVP로, 핵심 3화면 흐름
(근거·가정 → 시나리오 → 원장·보고서 → 복제)이 이미 동작한다. 이 설계문서는
**(a) 이미 구현된 부분의 명세화**와 **(b) 아래 결정에 따른 변경·신규 구현**을 모두 담는다.
각 문서에서 구현 상태를 `[구현됨]` / `[변경]` / `[신규]` 태그로 표시한다.

## 회귀 금지 원칙 (전 작업 공통)

기획서 §5.3·§6.4의 설계 원칙은 코드 리뷰 기준이다:

- 결측을 0으로 표시하지 않는다 (`EmptyValue` 컴포넌트 사용, "없음" 표기)
- 지역 방문자·입장객·예약자·체류자를 같은 필드에 저장하지 않는다
- API 관측값·사용자 가정·계산값·실측값의 4종 구분(`KindBadge`)을 모든 수치 표시에 유지한다
- stale 스냅샷(이전 성공값)은 최신값처럼 보이지 않게 한다
- 기준문서·승인자 없는 수용량으로 안전 계산을 켜지 않는다 (`hasApprovalBasis`)
- 금지 해석 문구(prohibition)를 스냅샷과 함께 저장·표시한다
- 모든 KTO 호출은 `ApiCallLog`에 기록한다 (키는 마스킹)
- 화면 문구에서 "예측 정확도", "정확한 흥행 예측" 등 기획서 §8.4 금지 표현을 쓰지 않는다 (e2e가 검사)
