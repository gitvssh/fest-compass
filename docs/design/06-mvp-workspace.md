# 축제 준비부터 다음 회차까지 직접 쓰는 MVP

2026-09-08 범위 명확화: 이 문서는 구현된 **개인 운영 계획·기록 기능**의 명세다.
지도 탐색·지자체 조회·주변/과거 축제 비교를 포함한 제품 전체 MVP의 목표·완료 기준은
[지자체 중심 제품 마일스톤](07-region-planning-milestones.md)을 따른다.

2026-09-07 사용자는 모델 정확도 개선보다 화면·기능과 전체 흐름의 완성을 우선했다.
기존 모델·수집·겨울 평가 계획은 유지하고, `/workspace`에서 개인 작업의 전체 흐름을 제공한다.

## 사용 가능 범위

| 화면 | 사용자가 하는 일 | 완료 확인 |
|---|---|---|
| 홈 | 실제 자료 탐색 또는 내 작업 시작 | 주 동선은 내 작업공간 |
| 자료·준비 | 논산 샘플/새 축제, 일정·장소·입장 건수 가정·근거 입력 | 지역 자료와 현장 가정 구분 |
| 운영안 비교 | 배치 인원·셔틀 차량·회차·전체 예산·운영 방법 비교 | 0과 미입력을 구분, 선택 이유·담당자 기록 |
| 결정·현장 기록 | 선택 당시 입력 조회, 대응 상황·내용·담당자·실행 여부 기록 | 결정 뒤 준비 정보 변경 알림, 과거 결정 보존 |
| 결과 비교 | 행사 전체 입장 건수와 출처·방법·배운 점 입력 | 마지막 결정 당시 같은 단위의 계획과 비교 |
| 보고·다음 회차 | 결과 보고서 인쇄/PDF, 가정을 복사해 다음 회차 준비 | 기존 회차 보존, 새 일정·결정·실측 재입력 |

전체 작업의 JSON 내보내기·가져오기, 여러 회차 선택, 사용 의견 파일 다운로드를 제공한다.
의견 파일은 작업 데이터 없이 입력한 의견만 포함하며 자동 전송하지 않는다.
논산 샘플의 2026년 일정은 검증된 달력 자료와 일치한다. 운영 가정·현장 대응·실측은 빈칸에서
사용자가 입력하는 연습 기록이다. 다른 축제에도 논산 지역 자료를 자동 적용하지 않는다.

## 공개 서비스와 저장

ADR-0001의 공개 서버 쓰기 차단은 그대로다. 기존 운영 기록의 편집 버튼과 모든 서버 쓰기·KTO
새로고침은 공개 모드에서 차단한다. 새 개인 작업공간은 서버 액션·DB 쓰기·API 호출 없이 브라우저
저장 공간만 사용한다. 개인 기록을 공인된 승인이나 공동 원장으로 표현하지 않는다.

- 저장 키 `fest-compass.workspace.v1`, 형식 버전 1. 회차 20개, 회차당 결정 30건·현장 대응 100건.
- 파일은 최대 1MB. 허용 필드만 복원하고 수치·날짜·ID·배열 길이·활성 회차 참조를 검증한다.
- 파일 교체 전 목록을 보여주고 확인받는다. 손상된 파일은 기존 기록을 덮어쓰지 않는다.
- 저장소 읽기·쓰기 실패는 화면에 표시하고 파일 보관을 제공한다. 손상된 저장 원본도 내려받을 수 있다.
- 다른 탭에서 변경하면 자동 저장을 멈춘다. 현재 입력 보관 또는 저장 내용 다시 읽기로 해결한다.
- 개인정보·분석 안내에 개인 저장 위치, 삭제·보관 방법을 설명한다. 입력을 분석 이벤트로 보내지 않는다.

## 기록의 의미

결정은 축제명·장소·일정·입장 가정·근거·운영안·이유·담당자·시각을 복사해 보관한다.
새 준비 입력은 기존 결정을 고치지 않는다. 결과를 기록한 후에는 결정을 추가하지 못하게 해
결과의 기준이 바뀌는 것을 막는다. 결과는 출처와 측정 방법이 있어야 차이를 표시한다.
계획이 0이면 비율은 계산하지 않는다. 지역 통계와 현장 입장 건수는 합치지 않는다.

다음 회차에는 가정·운영 대안만 복사하고 근거의 재확인을 표시한다. 일정·결정·현장 기록·실측은
비운다. 2027년 24일 엑스포는 자동 등록하거나 기존 4일 축제 예측을 적용하지 않는다.

## 피드백 후 개발할 기능

인증·팀별 저장·공동 편집·공식 승인, 다른 축제 지역 자료 연결, CSV 실측 가져오기와 시간·구역별
개인 결과 비교는 개발 필요다. 기존 편집 모드의 시간·구역 실측 기능은 유지한다.
셔틀·인력 변경에 따른 대기시간·안전·처리량 효과는 필요한 현장 자료가 없어 검증 필요다.
모델 추가 학습·정확도 개선은 사용자 검증 이후의 우선순위로 미룬다.

## 관찰할 사용자 과제

1. 논산 샘플을 시작하고 지역 방문자와 입장 건수의 차이를 설명한다.
2. 같은 행사 기준으로 운영안 둘을 입력하고 하나를 선택한다.
3. 현장 대응 한 건을 등록·실행 표시한다.
4. 실측을 출처와 함께 입력하고 계획과의 차이를 설명한다.
5. 결과 보고서를 저장하고 다음 회차를 만든 뒤 기존 기록이 남아 있는지 확인한다.

과제별 완료 여부·소요 시간·막힌 위치·용어 오해를 기록한다. 실제 사용자 관찰은 아직 실시하지 않았다.
