# 관광자원 사진·이용정보

2026-09-27 사용자 승인에 따라 기존 TourAPI의 대표사진·상세사진·이용정보를 공통 기능으로 연결한다.
대상은 지역 공무원의 PC 자료 조사·후보 비교다. 사진으로 장소의 모습을 파악하고 위치·이용 조건과
함께 축제 연계 가능성을 검토한다. 기록·저장을 이용 조건으로 요구하지 않는다.

## 확인한 자료와 적용 범위

- [국문 관광정보](https://www.data.go.kr/data/15101578/openapi.do): 현재 목록의 `firstimage/firstimage2`,
  `detailCommon2`, `detailImage2`, `detailIntro2`를 사용한다. 사진과 저작권 구분을 함께 보존한다.
- 9월27일 강릉 유형별 첫10건 표본40곳 중 대표사진33곳(관광지9·문화시설8·음식점7·숙박9)을 확인했다.
  전국 제공률이나 임의추출 표본으로 해석하지 않는다. 순포습지2775508은 대표사진1장과 추가사진7장,
  이용시간·휴무·주차가 조회돼 상세에서 중복 없는 사진8장을 확인했다.
- API 상세사진은 `contentId`로 요청한다. 이전 서비스의 `imageYN/subImageYN` 옵션은 현행 응답에서 거절되어 사용하지 않는다.
- [포토코리아](https://www.data.go.kr/data/15101914/openapi.do)는 촬영일·촬영지·촬영자·키워드가 있는
  지역 경관 조사용 후속 후보다. 이번에는 별도 가입·자격 발급·이름 기반 자동 사진 연결을 하지 않는다.

## 화면 구조와 선택

[설계21](21-desktop-research-experience.md)의 PC 목록·지도·상세3열과 연속 목록을 재사용한다.
큰 사진 카드로 목록을 바꾸면 동시에 비교할 수 있는 장소가 줄어들므로 작은 사진+텍스트 행을 선택했다.
지도 전체를 사진 핀으로 채우는 대신 선택 장소의 상세에 큰 사진을 둔다. 기존 화면·컴포넌트를 참조한
일상적인 배치 선택이며 새로운 브랜드 방향·외부 사용성 검증으로 주장하지 않는다.

```text
유형 · 지역 · 조건
┌ 목록 ──────────┬ 지도 ──────────────┬ 선택 장소 ──────────────┐
│ 작은 사진 이름 │ 위치·군집·선택    │ 이름 · 닫기             │
│           주소 │                   │ 원본 비율 사진 · 넘기기 │
│ 작은 사진 이름 │                   │ 사진 출처·이용조건      │
│           주소 │                   │ 주소·거리 / 이용정보    │
│ 텍스트만인 행  │                   │ 기준점·함께 보기·소개   │
└────────────────┴───────────────────┴─────────────────────────┘
```

- 목록 사진은 약64px, 전체 사진을 보존하는 `contain`으로 표시한다. 이름·주소를 주 정보로 유지한다.
- 상세 사진은 좌우 버튼·현재 순서로 탐색하며 자동 재생하지 않는다. 출처·공공누리 링크를 사진 가까이 둔다.
- 함께 보기에는 후보별 상세사진·주소·거리·이용정보·소개를 같은 순서로 배치한다.
  상세에서 확인한 사진과 이용조건을 우선하며 기존 목록 사진으로 덮어쓰지 않는다.
- 관광지도 `/regions`의 관광지·문화시설·음식점·숙박 선택에도 공통 상세를 연결한다.
  축제·행사15의 목록 사진은 표시할 수 있지만 네 관광자원 유형의 상세 API에 보내지 않는다.
- 유형별 등록된 이용시간·휴무·주차·요금·대표 메뉴·입퇴실 등만 짧은 이름과 값으로 보여준다.
  자료에 없는 조건을 추정하거나 사진으로 이용 가능·수용 인원·최신 운영 상태를 확정하지 않는다.
- 사진이 없으면 사진 영역을 생략한다. 조회 실패는 확인된 소개·사진·이용정보를 남기고 해당 영역에
  짧은 실패 안내와 재시도를 제공한다. 다른 장소를 고르면 이전 사진·펼침 상태를 이어붙이지 않는다.
- 좁은 창·200% 확대에서도 사진·버튼이 문서 폭을 넘지 않으며 키보드 선택·닫기 초점 복귀를 유지한다.

## 데이터·이용조건

1. 목록은 기존 지역·유형·전체 페이지 검증을 유지하며 사진은 선택 필드로 전달한다.
2. 상세는 공통정보의 식별자·유형·법정동 일치를 확인한 뒤 사진·소개정보를 조회한다.
   소개문이 없어도 사진 또는 이용정보를 표시할 수 있게 상태를 분리한다.
3. 상세 사진과 소개정보 각각의 실패가 다른 자료를 없애지 않게 처리한다. 갤러리는 선택 장소에 한해
   최대20장으로 요청하고 기존 캐시·시간·호출 제한을 유지한다. 전체 지역 사진 선조회는 하지 않는다.
4. 사진 주소는 확인한 관광공사 이미지 호스트와 이미지 경로·확장자만 허용하며 HTTPS로 표시한다.
   임의 URL 프록시·외부 HTML 실행·원천 키의 브라우저 전달은 추가하지 않는다.
5. 확인한 공공누리1·3유형 사진만 사용한다. [3유형](https://www.kogl.or.kr/info/licenseType3.do)의
   변경금지 조건을 반영해 잘라내기·필터·합성 없이 전체 사진을 표시한다. 출처·이용조건은 제품 정보로
   제공하고 내부 검증·허용 목록·개발 절차는 화면에 노출하지 않는다.

## 검증과 전달

실제 API 자료와 통제된 응답 시험을 구분한다. 사진 유무·이미지 로딩 실패·선택 변경·부분 조회 실패·
재시도·유형별 이용정보·키보드·PC/좁은 창을 확인한다. 최종 결과와 화면은
[검수44](../validation/44-tourism-media.md)에 기록하고 프로젝트 원본과 D 드라이브 확인용 사본을 함께 남긴다.

Opus5.5 설계 검토 호출은 사용 한도로 실행되지 않았다. 협업 에이전트에 서버·화면·관광지도·시험을
분담하고 주 담당자가 원천 확인·설계·통합·직접 검수를 맡는다.
