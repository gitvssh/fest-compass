# 방문 분석 동의 배너

2026-10-04 사용자 요청("pickDday도 같은 방식으로 진행해줘")에 따라, 두 자매 사이트(괜찮개·포트폴리오)에 먼저 반영해 실제 Zaraz로 확인한
사이트 자체 동의 배너를 pickDday에 옮긴다. 목표는 처음 온 사람(심사위원·처음 접한 담당자)이 영어 반 한국어 반의 창에 첫 화면을 빼앗기지 않고
바로 둘러보면서, 분석 동의는 서비스의 말로 짧게 고르게 하는 것이다.

## 1. 지금의 문제(2026-10-04 공개 화면 확인)

- Cloudflare Zaraz의 존 공용 기본 동의 창(`쿠키 설정 · analytics — Anonymous page and feature usage analytics.`)이 접속 약 1초 뒤 첫 화면 전체를 덮고 배경을 흐린다.
  창을 닫기 전에는 아무것도 할 수 없고, 서비스의 말투·디자인과 맞지 않는다.
- 첫 방문 소개 영상 안내([설계23](23-intro-video.md))는 이 창이 닫힌 뒤에야 나타나므로, 창이 첫 경험을 결정한다.

## 2. 결정

| 선택지 | 판단 |
|---|---|
| Cloudflare 콘솔에서 기본 창의 문구·모양만 바꾸기 | 채택하지 않음. 존 공용 창이라 다른 사이트에도 같이 적용되고, 전면 덮개·흐림·초점 가두기는 그대로다. |
| 사이트가 동의를 직접 저장(쿠키·브라우저 저장소) | 채택하지 않음. 동의 기록·목적 구분은 Cloudflare가 갖는다는 기존 경계([개인정보·분석 안내](../../apps/web/app/privacy/page.tsx), `appDefinesCmpPurposeId: false`)를 깨고 기록이 둘로 갈린다. |
| 기본 창은 Zaraz에 두고, 사이트 배너가 묻는 동안만 기본 창을 숨기고 선택을 Zaraz에 넘기기 | **채택.** 자매 사이트에서 실제 Zaraz로 검증된 방식. 앱은 purpose ID를 모른 채 전체 허용·거부(`setAll`)만 넘긴다. |

## 3. 동작

1. **준비:** 페이지는 `<html data-consent-takeover>`를 단 채로 와서 기본 창(`.cf_modal_container`)이 첫 화면부터 CSS로 숨는다(2026-10-04 보완 — 화면 스크립트보다
   기본 창이 먼저 열리는 첫 방문에서 약 0.1초 보였음). 화면 스크립트가 시작할 때 Zaraz 로더(`window.zaraz`)가 없으면 바로 숨김을 거두고, 로더는 있는데 동의 API가
   6초 안에 준비되지 않으면 그때 거둔다. 동의 API가 준비되면(`zaraz.consent.APIReady` 또는 `zarazConsentAPIReady` 이벤트) 50ms 간격 120번(약 6초) 동안
   `zaraz.consent.modal`이 `true`가 되는 순간을 지켜본다. 시간은 벽시계가 아니라 간격 횟수로 센다(시계 보정으로 창이 일찍 끝나지 않게). 공개 화면 측정에서 기본 창은 API 준비와 같은 순간에 열렸다.
2. **아직 고르지 않은 방문자:** 기본 창이 열리는 순간 창을 닫고(`modal = false`) 사이트 배너를 띄운다. 숨김은 배너가 닫힐 때까지 유지한다.
3. **이미 고른 방문자:** 6초 안에 창이 열리지 않으면 숨김을 거둔다. Zaraz 기본 동작을 영구히 막지 않는다.
4. **선택:** 배너를 먼저 닫고 숨김을 거둔 뒤, 열려 있을 때만 기본 창을 닫고(닫힌 창에 `false`를 넣으면 Zaraz가 예외를 던짐 — 2026-10-01 실측),
   `setAll(허용 여부)`를 넘긴다. 허용이면 대기 중이던 이벤트를 보낸다(`sendQueuedEvents`). 넘기는 중 예외가 나도 배너는 남지 않는다.
5. **다시 보기:** 모든 화면 아래(바닥글)와 개인정보·분석 안내의 `분석 동의 다시 보기`가 같은 배너를 다시 연다. 이때만 초점을 배너로 옮긴다.
   Zaraz가 없는 주소(개발·미리보기·차단 브라우저)에서는 `이 주소에서는 방문 분석을 쓰지 않아 고를 것이 없습니다`와 `닫기`만 보인다. 기본 창을 다시 여는 `showConsentModal`은 화면 경로에서 쓰지 않는다.

## 4. 화면 구성

- 화면 아래의 작은 카드 하나: PC는 왼쪽 아래(너비 최대 36rem), 휴대폰은 좌우 여백 12px의 한 장. 덮개·흐림·초점 가두기·첫 화면 밀림이 없고(`position: fixed`), 뒤의 모든 기능을 바로 쓸 수 있다.
  카드가 떠 있는 동안 바닥글 아래에 카드 높이만큼 자리를 더해, 끝까지 내리면 바닥글(`분석 동의 다시 보기`·개인정보 안내)이 카드 위로 올라온다(소개 영상 안내 카드도 같음, 2026-10-04 보완).
- 내용: 제목 `방문 분석을 허용하시겠어요?`, 무엇을 모으는지 한 문장(`어떤 화면을 열어 봤는지에 대한 이용 통계만 모읍니다. 축제 이름·입력 내용은 보내지 않고, 거부해도 모든 기능을 똑같이 쓸 수 있습니다.` —
  [허용 이벤트 사전](../../apps/web/lib/analytics-events.ts)과 같은 사실), `개인정보·분석 안내` 링크, `거부`(보조 단추) · `허용`(진한 단추).
- 공통 표현을 그대로 쓴다: 흰 표면·모서리 16px·옅은 테두리·카드 그림자(`shadow-card`), 단추 `region-button`·`region-primary`, 초점 고리 2px([디자인 시스템](../sdlc/2-design/design-system.md)).
  새 색을 만들지 않는다. 등장 움직임은 소개 영상 안내와 같은 300ms이며 움직임 줄이기 설정에서는 없다.
- 접근성: `section[aria-labelledby][aria-describedby]` 영역, 첫 방문 배너는 초점을 옮기지 않음, 링크 → 거부 → 허용 순 키보드 이동, 44px 이상 단추.

## 5. 소개 영상 안내와의 순서

첫 방문 소개 영상 안내([설계23](23-intro-video.md))는 **동의 질문이 화면에 있는 동안 기다린다** — 사이트 배너가 보이는 동안과 기본 창을 지켜보는 6초 동안.
질문이 사라진 채 2초가 지나면 나타나고(기존 규칙), 배너가 다시 열리면 비켜섰다가 닫힌 뒤 2초 후 돌아온다. 그래서 두 카드가 390px에서든 1440px에서든 같은 자리에 겹치지 않는다.
Zaraz가 없는 주소에서는 배너도 지켜보기도 없으므로 안내는 지금처럼 2초 뒤에 나온다. 예비로 기본 창의 열림(`dialog[open]`)도 계속 읽는다(최대 120초).

## 6. 저장·개인정보

- 앱은 쿠키·브라우저 저장소를 읽거나 쓰지 않는다. 미선택 여부는 Zaraz가 기본 창을 열려는 순간으로만 안다.
- purpose ID·측정 ID는 여전히 앱에 없다(단위 시험이 소스에서 확인). 동의 기록은 Cloudflare가 보관한다.
- 개인정보·분석 안내의 `선택 분석과 동의 경계` 문단을 작은 안내와 `분석 동의 다시 보기` 경로로 고쳤다. 안내 페이지에는 시행일 표기가 없으며, 고지·시행일 갱신 여부는 소유자가 판단한다.
- 보안 정책(CSP)과 분석 전송 경계는 바꾸지 않았다. 인라인 스크립트는 없다.

## 7. 운영 전제

- Zaraz Consent Management의 기본 창은 **켜 둔다.** 콘솔에서 창을 끄면 미선택 신호가 없어 배너도 뜨지 않는다([분석 연결 런북](../ops/seo-analytics-connection.md) §2).
- 실제 Cloudflare 동의 창과의 동작(기본 창 미표시, 선택 뒤 `zaraz-consent` 쿠키, 새로고침 시 배너·창 없음)은 공개 반영 뒤에만 확인할 수 있다.
  느린 기기에서 화면 스크립트가 준비되기 전에 기본 창이 잠깐 보일 가능성은 운영에서 관찰한다.

## 8. 범위 밖

- 동의 문구의 다국어, 목적별 세분 선택(앱이 purpose ID를 갖지 않는 한 전체 허용·거부만), 동의 이벤트의 분석 전송.
