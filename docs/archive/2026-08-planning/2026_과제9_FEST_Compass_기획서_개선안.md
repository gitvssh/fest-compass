# FEST Compass 기획서 개선안 — 발표자료 제작용 보강

> 대상 문서: `output/2026_과제9_FEST_Compass_분석설계_기획서.md`  
> 문서 성격: 기획서 검토에서 확인된 4개 공백을 보강하고, 심사위원 대상 발표자료(PPT)의 직접 원료를 제공한다.  
> 작성 기준일: 2026-08-18  
> 독자 설정: **발표자료의 독자는 실제 심사위원이다.** 내부 용어(가설 등급, 게이트, 배점, 수상 논리)는 발표 본문에 노출하지 않는다.

## 0. 검토 결론 요약

기획서의 판단 구조(증거등급, 라벨 게이트, 금지 해석, 의사결정 게이트)는 유지한다.
발표자료 제작 전 다음 4가지를 보강한다.

1. 문제의 크기를 보여줄 **A등급 정량 근거** (→ §1)
2. 처음부터 끝까지 관통하는 **대표 시나리오** (→ §2)
3. KTO 데이터가 없으면 안 되는 이유를 보여줄 **시그니처 사용례** (→ §3)
4. **공모전 기간 내 검증과 파일럿 검증의 구분 + 플랜B** (→ §4)

추가로 발표용 지표 번역표(§5), 발표자료 목차(§6), 톤앤매너 규칙(§7)을 정한다.

## 1. A등급 정량 근거 (2026-08-18 조사)

기획서에 없던 공식 정량 근거. **시장규모(TAM) 주장에 사용하지 않는다.**
문제의 크기와 설명책임 증가의 근거로만 사용한다.

| 사실 | 수치 | 출처 | 발표 사용처 |
|---|---|---|---|
| 전국 지역축제 수 | 2019년 884개 → 2024년 1,170개 (+32.35%) | 나라살림연구소, 「2024년 지역축제 현황 및 성과분석」(2025) / 서울신문 2025-01-09 | 문제의 크기 |
| 축제당 지역주민 참가율 | 최근 5년 평균 **−9.6%p** 감소 | 나라살림연구소, 같은 보고서 | 양적 증가·질적 하락 |
| 1인당 관광소비액 | **−12.72%** 감소 | 나라살림연구소, 같은 보고서 | 양적 증가·질적 하락 |
| 예산 1억~3억 원 축제 수 | 2019년 277개 → 2024년 366개 | 나라살림연구소, 같은 보고서 | 중소형 축제가 다수라는 세그먼트 근거 |
| 행사·축제 원가정보 공개 의무 | 광역 5억 원 이상, 기초 3억 원 이상 | 행정안전부, 지방자치단체 세출예산 집행기준 / 지방재정365 | 설명책임(예산) |

| 성과관리 제도 진단 | "현행 규정이 의무사항이 아니거나 지역 실정에 맞지 않아 실질적인 수단으로 작동하지 못함" | 나라살림연구소, 같은 보고서 | 계획–운영–평가 단절의 공적 진단 |

**사용 범위 결정 (2026-08-20 수정):**

> 전국 통계(1,170개, −9.6%p 등)를 문제 논증의 앵커로 쓰면 "기록이 안 남아서 참가율이 떨어졌다"는
> 증명 불가능한 인과 비약이 생긴다. **발표의 문제의식은 §1.1의 실제 보도 사례로 세우고,
> 전국 통계는 발표 본문에서 제외한다** (질의응답 대비 자료로만 유지).
> 법적 설명책임(원가공개·안전관리계획)은 유지 가능하나 부차 근거로만 쓴다.

### 1.1 뉴스 사례 근거 (2026-08-20 조사) — 발표 문제의식의 앵커

| 사례 | 사실 | 인용 | 출처 |

**세 사례가 만드는 논증 구조 (비약 없음):**

1. 임실 — 반복 개최 축제가 예측 가능했던 혼잡을 또 겪었다 → **학습이 안 되는 구조** (제품의 핵심 문제)
2. 고흥 — 수용량·동선 판단이 흔들리면 21만 명이 기다린다 → **운영 결정의 비용** (시나리오 비교의 필요)
3. 태화강 — 성과 숫자조차 출처 없이 만들어진다 → **집계·기록의 신뢰 문제** (출처 추적의 필요)

각 사례가 제품 기능(기록·학습 / 시나리오·수용량 / 출처 추적)에 1:1로 연결되므로
"사례 → 원인 → 제품"의 전개에 인과 비약이 없다.

## 2. 대표 시나리오 — 발표·데모를 관통하는 사례

발표와 시연 모두 이 하나의 사례로 진행한다.
**가상 사례임을 발표에서 명시한다** (화면·장표에 `예시 시나리오` 라벨).
사례 수치는 전부 사용자 가정 예시이며 실측 주장이 아니다.

### 2.1 사례 설정

- 가상의 **「○○군 봄꽃축제」**: 반복 개최 3일, 무료 개방형, 중소형(예산 2억 원대), 데이터 전담인력 없음
- 보유 자료: 전년도 일별 방문 추정 총계만 존재 → 라벨 준비상태 **L1(부분 라벨)**

### 2.2 시점별 워크스루

| 시점 | 담당자의 결정 | FEST Compass에서 일어나는 일 |
|---|---|---|
| D-90 | 일정·회차·프로그램 구조 | ① 축제 등록 → KTO `searchFestival2`로 기본정보 사전채움. ② 같은 기간 인근(예: 반경 30km) 행사 2건 겹침 자동 표시 → 회차·일정 판단. ③ 라벨상태 L1 표시 → 예측 기능 비활성화, 최소 1.2만 / 기준 1.8만 / 최대 2.6만 명 **가정 입력**(작성자·근거 기록) |
| D-30 | 인력·주차·셔틀 규모 | ① KTO 지역별 방문자 배경선: 전년 축제 주간 평시 대비 유입 증가 확인(축제 입장객 아님을 화면에 명시). ② 기본·보수·확대 3개 시나리오 비교: 확대안 = 셔틀 2→3대, 주차 안내인력 4→6명. ③ 확대안 선택 + 이유·승인자·시각 기록 |
| D-3 | 대응 트리거 확정 | 우천 시 셔틀 증편·잔디구역 폐쇄 조건과 책임자를 트리거로 등록 |
| 행사일 | 혼잡 대응 | 13:40 A구역 혼잡 임계 초과 → 우회 동선 개방. 조치·시각·근거가 계획과 연결돼 기록 |
| D+14 | 성과보고·다음 해 반영 | 계획 대비 실제 원장 자동 대조 → 보고서 출력(모든 수치 출처·계산식 역추적 가능) → 다음 해 워크스페이스에 초기값 복제 |

### 2.3 시연 90초 스크립트 (3화면)

1. **화면 1 — 근거·가정** (30초): KTO 사전채움과 경쟁행사 겹침 → "이 데이터는 축제 입장객이 아니라 지역 배경선입니다" 라벨 → 최소/기준/최대 가정 입력
2. **화면 2 — 시나리오 비교** (30초): 3개 시나리오의 수용여유 비교 → 확대안 선택, 이유 입력, 승인 기록
3. **화면 3 — 결정·성과 원장** (30초): 당일 조치 기록 → 계획 vs 실제 대조 → 보고서 1분 출력 → "다음 행사로 복제" 버튼

## 3. KTO 데이터 시그니처 사용례

기획서 §6.2(허용/금지 해석)는 방어 규칙이다. 발표에는 공격 논리가 필요하다:
**"이 데이터가 없으면 이 결정을 내릴 수 없다"**를 결정 단위로 말한다.

| 결정 | 사용하는 KTO 데이터 | 사용 방식 | 이 데이터가 없다면 | 금지 해석(유지) |
|---|---|---|---|---|
| 일정·회차 결정 | 국문 관광정보 `searchFestival2` + 상세 | 같은 기간·인접 지역의 행사 겹침을 자동 탐지해 일정·회차 조정 근거로 제시 | 담당자가 포털을 일일이 검색, 누락 빈발 | 타 행사의 흥행·경쟁 강도 단정 금지 |
| 셔틀·주차·인력 규모 | 지역별 방문자 수 | 평시 대비 행사기간 지역 유입 변화를 배경선으로 제공 → 가정 범위 설정의 출발점 | 전년 담당자의 체감 기억에 의존 | 축제 입장객 수로 해석 금지 |
| 분산 동선·연계 프로그램 | 관광지 집중률 + 연관 관광지 | 인근 관광지의 상대 피크와 연관 이동 패턴을 보조신호로 표시 → 분산 유도 동선 설계 | 인근 혼잡과의 상호작용을 고려하지 못함 | 행사장 실인원·절대 혼잡으로 해석 금지 |
| 시기·주제 적합성 (D-90) | 지역별 관광 수요 강도 / 관광 자원 수요 | 시기별 체류·소비 잠재력과 주제 적합성을 기획 초기 비교 근거로 제공 | 시기 선택이 관행에 고착 | 프로그램의 인과효과 주장 금지 |

발표 문장: "KTO 데이터는 화면 장식이 아니라, 위 4개 결정의 **첫 번째 근거층**입니다.
동시에 이 데이터를 축제 입장객 수로 해석하지 않는 것이 저희 설계 원칙입니다."

## 4. 검증의 구분 — 공모전 기간 내 vs 파일럿

발표에서 "검증했습니다"와 "파일럿에서 확인하겠습니다"를 반드시 구분해 말한다.

### 4.1 공모전 기간 안에 완결하는 검증

| 항목 | 방법 | 통과 기준 |
|---|---|---|
| KTO API 실사용 | 실제 인증키 호출·응답 로그 | 정상·빈결과·오류·페이징 확인 로그 보관 |
| 과거 축제 재현 | 공개 자료 기반 과거 1개 축제를 당시 시점 정보만으로 재현 | 수기 계산과 제품 계산 일치 |
| 실무 사용성 | 총괄·안전·교통 역할 테스트 | 도움 없이 핵심 흐름 10분 내 완료 |
| 데이터 의미 이해 | 화면 의미 이해 테스트 | 지역 방문자·축제 입장객 혼동 0건 |
| 수치 추적성 | 보고서의 모든 수치 역추적 | 출처·계산식 추적률 100% |

### 4.2 파일럿(실제 축제)에서 확인할 것 — 발표에서는 "확인 예정"으로 표현

- 시나리오 비교가 실제 운영 결정(인력·회차·셔틀·동선 중 1건 이상)을 바꾸는가
- 사후보고서 작성시간이 실제로 줄어드는가
- 다음 행사에서 원장을 복제·재사용하는가 (D+14 학습)

### 4.3 플랜B — 파일럿 협약 불발 시

- 문체부 지역축제 정보(공공데이터포털), 축제 백서·보도자료 등 **공개된 과거 자료**로 재현 데모를 완결한다.
- 서비스는 라벨 없음(L0) 상태의 **시나리오 전용 모드**로 정직하게 시연한다.
- 가을 축제 시즌(9~10월)이 공모전 개발 기간과 겹치므로, 반복 개최 중소형 축제 조직 접촉을 W1에 시작한다(기획서 §7.3 파일럿 조건 적용).

## 5. 발표용 지표 번역표

내부 북극성 지표("근거가 완결된 계획변경 의사결정 비율")는 내부용으로 유지하고,
발표에서는 체감 가능한 언어로 번역한다.

| 내부 지표 | 발표 언어 |
|---|---|
| 근거 완결 의사결정 비율 | "보고서의 **모든 수치를 출처까지 역추적**할 수 있습니다 (추적률 100%)" |
| 입력 완료 중앙값 | "핵심 입력은 **10분** 안에 끝납니다" |
| 보고서 생성 시간 | "사후보고서 초안이 **1분**에 나옵니다" |
| 계획변경 결정 수 | "파일럿에서 **실제로 바뀐 운영 결정 1건 이상**을 확인하겠습니다" |
| 재사용률 | "이번 축제의 기록이 **다음 해의 초기값**이 됩니다" |

## 7. 톤앤매너 규칙 (심사위원 독자)

- 정중한 발표체(~합니다). 헤드라인은 완결된 주장 문장.
- 다음 단어를 본문에 쓰지 않는다: 수상, 배점, 심사 대응, 가설 등급, 게이트, 내부 점수, PASS/CONDITIONAL.
- 검증되지 않은 수치(TAM·ROI·정확도)는 쓰지 않는다. 확인 전 항목은 "파일럿에서 확인하겠습니다"로 말한다.
- 가상 사례에는 `예시 시나리오` 라벨을 붙인다. 사례 수치는 가정임을 표기한다.
- 공식 통계에는 장표 하단에 출처를 병기한다.
- 피해야 할 표현/사용할 표현은 기획서 §8.4를 그대로 따른다.
