# 제품 목표와 범위

**pickDday**는 지방자치단체 축제 담당자가 공공 관광데이터로 지역 관광자원·방문 흐름·개최 시기를 살펴보고
관광 활성화를 위한 축제를 기획하도록 돕는 의사결정 지원 서비스다.
다양한 정부·공공기관 자료를 확보·정제하고 목적에 맞게 가공·연결·시각화해 판단에 쓰도록 제공한다.
지역 소비·주민 참여·인지도는 관광 활성화와의 관계 안에서 다룬다.

2026-09-23 사용자가 제품 표시명을 FEST Compass에서 **pickDday**(대소문자 그대로)로 확정했다.
프로젝트·배포 식별자 `fest-compass`, 공개 주소 `pickday.damecasol.com`, 저장소 이름과
과거 원문·검증 증거에 남은 옛 이름은 바꾸지 않는다.

첫 화면에서 **기존 축제 개선·새 축제 기획**을 구분하고 상황별 정보 탐색·비교 흐름을 설계한다.
두 목적은 각각의 전용 흐름이다. 새 축제 기획 전용 흐름은 두 번째 흐름으로 추가하며 기존 축제 개선 흐름을 대체하거나 없애지 않는다.
관광객·방문 이유·시기·장소·연계 관광·준비·성과에 관한 질문은 정보 설계 기준이다.
시스템이 데이터만으로 답을 확정하거나 사용자에게 답변 제출을 요구하지 않는다.

사용자의 답변·선택 이유·메모·기획안·결과 기록은 선택 사항이며 다음 회차 재사용을 돕는다.
기록 없이도 핵심 조회·비교·시각화를 이용할 수 있어야 한다. 목표 관광객·주제·축제명·기획안·전략·메모·기록은
탐색의 선행 조건이 아니다. 특정 조회·계산에 필요한 최소 조건(축제 또는 지역, 기간 등)과 전략적 답변·기획안 작성 의무를 구분한다.

현재 구현·검증: 두 목적 선택과 기존 축제 개선 흐름([UC-FC-009](../sdlc/1-analysis/usecases/UC-FC-009.md))은
[검증 기록34](../validation/34-existing-festival-journey.md)에서 구현·자동 시험·공개 반영을 확인했다.
새 축제 기획 전용 흐름([UC-FC-010](../sdlc/1-analysis/usecases/UC-FC-010.md))은 사용 가능하며 공개 운영 확인을 마쳤다.
지역 탐색·비교·기획·예산·출력·결과와 논산 추세 연구는 [기획 검수 기록](../review/2026-09-planning-review.md) 및 현재 코드를 확인한다.
축제·회차·지역·관광자원의 관련 자료 검색·외부 연결은 [검증 기록36](../validation/36-related-material-search.md)을 따른다.
후속: 최종 시각 디자인과 실제 담당자 관찰, 미연결 공공자료 연결, 기존 기록 필수값·동선 재검토와 AI 요약 검토.
이 문서의 목표 정의를 구현 완료나 실제 담당자 검증 완료로 표시하지 않는다.

공개 서버의 운영 기록은 읽기 전용이며 개인 작업은 브라우저에 저장한다.
공동 편집·공식 승인·다중 기기 자동 동기화는 후속 범위다. 기존 ADR의 권한 경계는 유지한다.
예측은 검증된 지역·지표·기간에서만 보조 자료로 제공하며 추가 모델 연구보다 기획 흐름을 우선한다.

앞으로의 기획 기준은 [관광 의사결정 지원 기획 기준](planning-principles.md)과 [비목표](non-goals.md)를 따른다.
[기존 기획서](../sdlc/0-planning/product-plan.md)와 [요구사항·기능목록](../sdlc/1-analysis/srs.md)의
기획안 작성·기록 중심 조건은 선택 기능의 기존 설계로 구분하고 후속 상세 검토에서 정렬한다.
