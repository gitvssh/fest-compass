# 관광 의사결정을 위한 데이터 확보·연결 현황

## 결론과 적용 범위

**현재 사용 가능한 기반은 관광자원·등록 축제 일정 조회, 일부 지역 방문 이력, 조사한 과거 회차 비교다.**
추가로 연결할 자료는 이미 있다. 한국관광 데이터랩 CSV에는 축제 방문 특성·지역 방문·소비 자료가 있고,
Foundry에는 관광 콘텐츠·축제·시도 방문·주차장 자료가 보관돼 있다. 다만 보관 사실만으로 현재 앱에서 제공하거나
최신 자료를 자동 갱신한다고 볼 수 없다.

**2026-09-23 통합 추가:** 데이터랩 CSV 304개와 관련 문서 5개를 이 저장소의
[원본 보관 폴더](imported/hkjin-plan-03/README.md)로 바이트 그대로 가져왔다. 그중 **축제 연도별 방문 추이 26개 파일(147행)만**
새 화면 `/compare/annual`에 연결했고, 이 화면은 로컬·공개 운영 검증을 완료했다([연결 범위](#축제-개최기간-연도별-방문-추이-연결)).
당시 나머지 278개 CSV(성·연령, 목적지 검색, 주요 지표, 지역 방문·소비)는 보존만 한 상태였다.

**2026-09-24 임실 추가:** 임실군 연간 방문 추이 1개 CSV(2018~2025년·3구분·24행)를 새 축제 방문 화면에 연결하고
공개 확인을 마쳤다. 축제 자료의 임실 2023~2025 회차는 기존 축제 방문 구성에 재사용한다. 현재 생성 목록은 소비 27개·보존 277개다.
실행·공개 상태는 [검증 기록37](../validation/37-visitor-context.md)을 따른다.
지역 연간 외지인과 기존 일별 보관본은 2023·2025년에 합계가 일치하고 2024년은 0.5 차이다.
공식 연간 값을 그대로 보존하며 일별 합계로 대체하지 않는다.

이전 CSV의 성·연령·거주지·목적지 순위는 원본과 수집 기록에 관측연도가 없어 **준비됐지만 기간 확인 필요**다.
공식 축제 화면의 연도 선택이 지표마다 따로 있으므로 다운로드 날짜·폴더 범위로 분석 기간을 추정하지 않는다.
현재 관광자원 정보가 있어도 과거 인기 순위와 바로 연결하지 않는다. 화면에서는 미확인 카드·내부 제약 문구를 추가하지 않는다.

**2026-09-24 임실 2025년 재조회:** [공식 원응답 5개와 조회 기록](imported/datalab-imsil-2025/README.md)을 별도 확보했다.
2025년 10월 8~12일·성수면·공식 축제 ID를 확인했으며, 성·연령 비율 16칸과 목적지 3구분 각 7곳을 제공할 수 있다.
현재 관광자원 목록과 이름·주소·ID가 일치하는 세 장소만 상세에 연결한다. 반복 수집에서도 원자료 다섯 파일이 일치했다.
축제별 거주지 영역은 공식 공개 화면에서 숨겨져 있어 미확보다. 지역 전체의 거주지를 축제 회차로 사용하지 않는다.
구현·실행·공개 상태는 [검증 기록38](../validation/38-visitor-profile.md)을 따른다. 이전 CSV의 소비 27개·보존 277개는 그대로다.

**2026-09-24 임실 2023·2024년 재조회:** 같은 공식 공개 화면에서 [2023년](imported/datalab-imsil-2023/manifest.json)과
[2024년](imported/datalab-imsil-2024/manifest.json) 원응답 각 5개(총 10개)를 바이트 그대로 보존했다.

정의 스크립트 두 개(`festival.js`·`festival_chart.js`)의 해시는 2025년 수집과 같다. 현재 임실군 관광지 54곳·문화시설 2곳 목록에서
임실치즈테마파크·상이암의 이름·주소·ID가 정확히 일치함을 확인했다. 목적지 식별자 173403은 2025년에 이름만 바뀌었으며
(성수산자연휴양림 → 성수산왕의숲자연휴양림) 식별자로만 같은 곳으로 본다. 축제별 거주지는 세 해 모두 공개 화면에서 숨겨져 미확보다.
상태는 **준비됐지만 연결 필요**이며 구현·공개 결과는 [검증 기록39](../validation/39-edition-profile-comparison.md)를 따른다.

같은 날 Foundry `silver.tourapi_content_master`에서 임실N치즈축제(2031318)·임실치즈테마파크(2718832) 등 실제 등록 자료를
확인했다. 조회어에 임실이 포함된 다른 시군구와 유사 이름의 서로 다른 ID가 함께 나오므로 이름만으로 합치지 않는다.
이 조회는 전국 수량·갱신 완전성이나 과거 순위의 관측연도를 입증하지 않는다. 아래 9월 22일 Foundry 전체 집계는 당시 기록이다.
통합 경계는 [저장소 통합 보고](../ops/repository-consolidation.md)에 있다.

이 문서는 [기획 기준](../product/planning-principles.md)에 따라 지역 공무원의 관광 의사결정을 지원할 자료를 점검한 결과다.
[현행 기능·문서 점검](../review/2026-09-current-state.md)과 함께 다음 설계를 시작할 때 사용한다.
기존 축제 개선·새 축제 기획의 확정 흐름은 각각 UC-FC-009·010과 현재 화면 설계를 따른다.
목표 관광객·방문 이유·선택 사유의 작성이나 저장을 자료 조회의 필수 조건으로 만들지 않는다.

후속 [기존 축제 데이터·화면 연결 설계](../sdlc/2-design/data-visualization.md)는 아래 기반 자료로
일별·월별 일평균과 세 핵심 화면을 구체화했다. Foundry에서 직접 확인한 논산 관광자원 3건도 시안 표본으로 연결했다.
새 시안의 존재가 이 문서의 앱 연결 상태나 아래 시점별 보유량을 바꾸지는 않는다.

### 확인 방법과 상태의 의미

- 2026-09-22 저장소 코드·작은 JSON/CSV 메타데이터를 읽고 기존 검증 기록과 대조했다. `cursor-agent`의
  Grok 4.6 High(`cursor-grok-4.6-high`)로 읽기 전용 조사를 위임한 뒤 파일·수치·표현을 직접 검수했다.
  아래 2~4절의 CSV 행수·Foundry 수량·공식 후보는 이 9월 22일 조사값이며 역사 기록으로 유지한다.
- 2026-09-23 통합에서는 가져온 원본의 [목록 파일](imported/hkjin-plan-03/manifest.json)(309개 파일의 크기·SHA-256·원본 URL)을
  실제 파일과 대조해 누락·불일치 0건을 확인했다. 이후 생성 자료·전체 단위 시험 239건·타입·빌드·headless 브라우저 16개 스크립트를 통합 검수했다. 검증 상태는 [통합 보고](../ops/repository-consolidation.md#검증-결과)를 따른다.
- Foundry 수량은 2026-09-22 MCP의 스키마 확인 후 `SELECT`로 실제 행과 콘텐츠 식별자를 집계했다.
  목록·주차장처럼 스냅샷이 있는 자료는 지정한 최신 스냅샷을 기준으로 했다. 카탈로그의 예상 행수는 사용하지 않았다.
- 공식 추가 후보는 제공처 설명을 확인한 상태다. 이번 점검에서 새 키 발급·실서비스 수집·앱 연결·배포는 수행하지 않았다.
- **사용 가능**은 현재 앱의 코드·보관 자료로 제공하는 범위다. 이번에 운영 환경을 다시 시험했다는 뜻은 아니다.
  **준비됐지만 연결 필요**는 실제 자료가 있으나 현재 제품에 연결되지 않았거나 활용 조건 검증이 남은 경우다.
  **개발 필요**는 자료 확보·갱신·정합 확인 또는 기능 개발이 필요한 경우다.

## 6. 연결·시각화 전에 지킬 데이터 기준

1. **방문과 관광 목적을 구분한다.** 통신 기반 지역 방문 통계는 방문 목적을 확정하지 않는다.
   일별·지역별 값을 더할 때 중복 가능성이 있으므로 고유 방문객·축제 입장객으로 표시하지 않는다.
   [한국관광 데이터랩 공식 데이터 설명](https://datalab.visitkorea.or.kr/datalab/portal/getMetaInfoList.do).
2. **공간·시간·지표 정의를 함께 맞춘다.** 시도 값을 시군구나 행사장으로 나누지 않고, 연간 값을 월·일로 분해하지 않는다.
   다른 기준의 자료는 나란히 설명할 수 있어도 같은 분모의 증감·구성비·효율로 자동 계산하지 않는다.
3. **원천 변경을 버전으로 남긴다.** 관광소비는 제공 기준 변경 공지가 있다. 2026년 자료를 기존 보관분과 연결하기 전에
   변경 전후의 제공자·범위·비교 가능성을 확인한다.
   [2026-05-26 관광소비 변경 안내](https://datalab.visitkorea.or.kr/site/portal/ex/bbs/View.do?bcIdx=310746&cbIdx=1135&pageIndex=1).
4. **지역코드는 제공처와 기준일을 포함한다.** TourAPI 조회코드, 행정코드, SGIS 경계코드, 지역명 CSV를 숫자나 이름만으로 합치지 않는다.
   원주 현재 회차 JSON의 조회코드는 `51/130`이며 과거 코드로 덮지 않는다. 미연결·개편 지역은 별도로 남긴다.
5. **일정 겹침·거리와 경쟁 효과를 구분한다.** 겹친 날짜·직선거리는 계산할 수 있지만 관객 감소·수요 전환·최적 시기를 증명하지 않는다.
6. **최신 수집과 최신 관측을 구분한다.** 조회한 날·원천 수정일·통계 기준일·다운로드 선택기간·스냅샷을 각각 기록한다.
   오류·미수집·결측을 0으로 바꾸지 않는다.
7. **공공자료와 사용자 기록을 분리한다.** 메모·가정·기획·현장 확인은 선택적 기록이며 공공 관측값을 대신하지 않는다.
   조회·비교·시각화는 필요한 지역·기간 등 최소 조건만으로 이용하는 방향을 유지한다.
