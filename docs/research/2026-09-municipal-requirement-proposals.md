# 공개 사례에 따른 요구사항·화면 보완안

**지역 지도와 비교검색을 중심에 두고, 그 결과로 예산 요구와 준비 규모를 설명하도록 보완한다.**
아래는 [사례 조사](2026-09-municipal-festival-cases.md)로 구체화한 검토안이다.
요구사항 정본의 기존 23개 FR·6개 NFR과 UC/TS, 와이어프레임 v1은 이번 조사만으로 변경하지 않았다.
이 문서는 두 번째 기능 대장이 아니라 **기존 요구의 어떤 부분을 어떻게 고칠지 설명하는 제안서**다.
구현·사용자 검수 완료를 뜻하지 않는다.

## 현재 설계에서 유지할 것

자기 지자체 우선, 지도와 같은 자료의 목록 제공, 주변·과거 회차 비교, 선택 근거 보관,
두 기획 대안, 미산정 예산 표시, 보관본 불변, 결과의 다음 회차 재사용은 유지한다.
추가 예측 정확도 연구를 선행 과제로 되돌리지 않는다.
관광 수요와 축제 성과의 인과를 자동으로 확정하지 않는다.

출처 번호는 [출처 대장](2026-09-municipal-festival-sources.md)의 SRC-MUN 번호다.

수행 관계는 서로 배타적인 선택 하나로 모두 표현하지 않는다.
예를 들어 재단 수행 안에 개별 용역 발주가 있을 수 있다.
관계가 불명확하면 ‘확인 필요’로 남기며 ‘재단=민간 보조’로 자동 분류하지 않는다.

## 예산 화면의 구체적인 구성 제안

SCR-FC-005의 기존 항목별 예산표를 유지하면서 위·아래에 필요한 설명을 더한다.
첫 화면부터 모든 행정 항목의 입력을 강제하지 않고, 선택한 업무 단계에서 필요한 부분을 펼친다.

| 화면 영역 | 표시·입력 내용 | 처음 쓸 때의 동작 |
|---|---|---|
| 기준 | 2027년도 / 후보 A / 예산 요구 초안 / 기준일 / 담당 부서 / 전체 사업 또는 부분 프로그램 | 연도·단계·범위를 먼저 설정. 날짜는 사용자 선택이며 실제 행사 자동 확정 아님 |
| 재원 계획 | 지방비·외부 지원·자부담 등 예상/확인 금액, 확보 상태, 출처 | 미정 재원은 미확인으로 표시. 예상 지원을 확보액에 더하지 않음 |
| 지출 산출 | 항목, 규격, 수량, 사용 일수·횟수, 단가, 세금, 금액, 견적·가정, 담당 조직 | ‘1식’도 허용하되 포함 과업을 적음. 기간을 단가에 포함했는지 명시해 중복 곱셈 방지 |
| 연도별 예산 분류 | 업무용 항목과 별도로 기관의 과목 코드/명칭·적용 기준·확인 상태 | 미확정 가능. 2027 분류로 2025 원문을 덮어쓰지 않음 |
| 비교·변경 이유 | 동일 범위의 전년 자료/다른 후보, 변경된 항목·차액·이유 | 정의나 범위가 다르면 숫자 차이 대신 확인할 차이를 표시 |
| 준비와 미확인 | 장소 협의, 견적 보완, 협조 부서 확인, 담당·기한·자료 상태 | 외부 확인 결과를 기록. 파일 존재만으로 완료 처리하지 않음 |

재원 합계와 지출 합계는 서로 대조하는 값이며 더해서 총사업비를 만들지 않는다.
‘요구액→확정 예산→계약액→집행액→정산 확인액’은 하나의 금액을 덮어쓰는 상태 변화도 아니다.
하나의 축제 아래 여러 계약·여러 차수 교부가 가능하므로 금액의 대상 범위를 각각 남긴다.

## 사업설명 자료의 출력 목차 제안

기관 공통 제출서식으로 보장하는 것이 아니라, 기관 서식에 옮겨 쓸 수 있는 검토 자료다.

1. **사업 개요:** 담당 지자체·부서·연도, 신규/계속, 목적·대상·규모·기간·위치·수행 관계.
2. **지역적 필요성:** 지도에서 선택한 자원, 방문 추세, 주민·상권 과제와 판단 근거.
3. **대안과 선택 이유:** 아이템·장소·기간별 대안, 유사 사례의 비교 조건과 한계.
4. **예산 요구:** 재원 확보 상태, 항목별 산출, 전년 기준·변경 이유, 제외/미산정 비용.
5. **추진 준비:** 일정·담당 조직·선행 조건·외부 확인·미해결 사항.
6. **성과 확인 계획:** 무엇을 어떤 방법으로 측정하고 전 회차 개선사항을 어떻게 확인할지.
7. **근거 목록:** 문서 종류·기관·대상 회차·작성/조회일·쪽·원문과 선택 당시 값.

기관의 공식 결재선, 예산 시스템 파일 형식, 계약·지급 기능은 포함하지 않는다.
국도비 공모 신청서·안전관리계획서 등 개별 전문 서식은 이 자료에서 자동 완성됐다고 표시하지 않는다.

## 문서 개정 때 추가할 인수 사례

아래는 아직 UC/TS에 반영하지 않은 **검증 후보**다. 실제 프로그램 실행 결과가 아니다.

| 사례 | 확인할 행동 | 기대 결과 |
|---|---|---|
| 논산의 무대 용역 기초금액과 타 축제 전체 결산을 선택 | 비교 조건 확인 | ‘부분 용역 기초금액 / 전체 축제 결산’ 표시, 증감·순위 보류 |
| 원주 자료처럼 보조금은 같고 자부담 집행만 증가 | 재원별 계획·집행 조회 | 자부담 차이로 표시하고 보조금 초과로 잘못 알리지 않음 |
| 정산 원문의 잔액 칸이 ‘-’ | 값 저장·출력 | 원문 표기와 미확인 상태 유지, 숫자 0으로 변환 안 함 |
| 공연 기간을 하루 늘린 가상 후보 | 변경 이유와 비용 재검토 | 임차·안전·청소 등 연결 항목의 재확인 목록을 보여주고 단가를 자동 추정하지 않음 |
| 과거 예산 분류와 다음 연도 분류가 다른 자료 | 새 회차로 복사 | 원문 코드·기준 연도 보존, 새 연도 분류는 확인 필요 |
| 견적 파일만 있고 규격·수량을 확인하지 않은 항목 | 준비 상태 변경 | ‘자료 있음 / 내용 확인 필요’ 구분. 정산 적정으로 판정하지 않음 |
| 초안을 기획안으로 보관한 뒤 확정 예산이 바뀜 | 새 버전 작성 | 이전 요구·근거 사본 보존, 새 버전에 외부 확정 근거와 조정 이유 연결 |
| 전 회차 결과에서 홍보 개선을 선택 | 다음 회차 후보 재사용 | 개선 이유가 새 홍보 예산 항목의 근거로 이어짐 |

## MVP에서 지원할 깊이

이번 보완은 **기획과 설명을 돕는 기록·비교·출력**에 집중한다.
M1 지도에 행정 서식을 먼저 입력하게 만들지 않는다. 탐색 자료를 담은 뒤 M3 기획 기본정보,
M4 예산, M5 검토 자료, M6 결과에 필요한 만큼 단계적으로 드러낸다.
외부 조직과의 실시간 공동 업무, 증빙 원본 저장소, 입찰·전자결재·회계 시스템 연동,
법령에 따른 자동 적법 판정, 자동 적정 단가는 추가하지 않는다.
증빙은 우선 종류·확인 상태·문서 참조로 관리하고 개인정보가 든 원문 업로드를 기본값으로 요구하지 않는다.

## 다음 문서 개정 순서

이 조사로 ‘MVP 전체 기능을 먼저 완성한다’는 기존 우선순위를 변경하지 않는다.
개발 전에 아래 문서 묶음을 함께 개정하는 것이 다음 작업이다.

1. 사업 흐름·자료 정의에 업무 단계·재원·사업 범위·연도·외부 확인 상태를 반영한다.
2. 기존 요구 ID를 보존해 위 8개 보완안을 SRS에 반영하고 UC/AC·TS를 함께 구체화한다.
3. SCR-FC-004~007을 중심으로 입력·출력 배치를 보완하고, 001~003에는 근거·범위 표시를 연결한다.
4. 실제 담당자에게 초안 작성→예산 설명→전년 결과 재사용 과제를 확인한다. 그 전까지 효율 개선은 가설이다.

담당자 확인에서는 ‘마지막으로 작성한 사업설명서의 반복 입력 항목’, ‘확정 예산을 받은 뒤 바꾸는 부분’,
‘다른 부서 비용의 포함 여부를 확인하는 방법’, ‘정산 지적을 다음 해로 옮기는 방법’을 우선한다.
공개 문헌의 절차와 실제 근무자의 행동이 같은지는 아직 확인되지 않았다.
