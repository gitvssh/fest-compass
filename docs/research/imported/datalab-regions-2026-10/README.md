# 데이터랩 지역 4곳 — 소유자 공식 내려받기 보관

이 디렉터리는 프로젝트 소유자가 2026-10-05 한국관광 데이터랩 지역 화면의 공식 내려받기 단추로 받은 **논산시·공주시·원주시·대구 달서구**
자료를 바이트 그대로 보관한다. 처음 가져오기([hkjin-plan-03](../hkjin-plan-03/README.md))의 지역 26곳에 없던, 축제가 열리는 지역이다.
`original/` 아래 파일은 고치지 않는다. 분류·해시는 이 README와 [`manifest.json`](./manifest.json)에만 둔다.

| 조회 | 연간 2020~2025(방문자 표에는 사이트가 함께 주는 2019년 비교 행이 있다) |

| 방문자 | `방문자 수(연인원) 추이` (연도별 외지인 방문, 전년 값·증감률) | 사용 |

처음 가져오기의 지역 표(관광소비 히트맵·업종별 지출액·지역별 지출액·방문자 거주지·방문자수 히트맵·지역별 방문자 수)는 이 내려받기에 없다.
그래서 이 4곳은 읍면동 비율·세부 업종·같은 시도 순위·거주지를 보이지 않는다.

## 보관 구조와 검증

- `original/zip/<공식 파일 이름>.zip` — 공식 ZIP 그대로(소유자 폴더의 `<지역>/공식ZIP/<항목>_<기간>.zip`에서 이름만 되살림). SHA-256은 목록의 `원본ZIP_SHA256`과 같다.
- `original/data/<공식 파일 이름>/<ZIP 항목>.csv` — ZIP 항목을 바이트 그대로 푼 사본. 목록의 `CSV_SHA256`·`데이터행수`와 같다.
- `original/다운로드목록.csv`, `original/읽어주세요.txt` — 소유자의 기록(보관용). 줄바꿈이 바뀌지 않도록 `original/** -text`.

`apps/web/scripts/datalab-owner-regions.mjs`가 목록을 기록하고, 생성할 때마다 파일에서 목록을 다시 만들어 저장본과 한 글자까지 같은지 본다.
ZIP은 직접 풀어(크기·CRC-32) 풀어 둔 CSV와 바이트까지 대조한다. 목록 밖 파일이 있으면 멈춘다.

## 앱에서 쓰는 범위

`apps/web/scripts/build-datalab-region-trends.mjs`가 16개 표로 `apps/web/data/datalab-region-trends.json`을 만든다. 지역 코드와 축제 연결은
`apps/web/data/datalab-region-trend-ids.json` 검토표다. 생성 결과와 기준은 [설계30](../../../design/30-datalab-region-trends.md),
실행 기록은 [검수52](../../../validation/52-datalab-region-trends.md)이다.

- 관광소비: 연도마다 업종 대분류의 합 = 전체, 내국인 = 현지인 + 외지인(연도·업종마다, 1천 원 이내)을 확인했다.
- 방문자: 2023~2025년 논산·공주 값은 앱이 이미 쓰는 한국관광공사 지역별 방문자 수(날마다 외지인)를 한 해 동안 더한 값과 같다
  (논산 2025년 17,451,010). 처음 가져오기 임실의 연간 외지인 값도 같은 관계라, 새 축제 `방문 흐름`의 연도별 방문 합계에 같은 지표로 넣는다.
