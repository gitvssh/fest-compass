## 갱신과 검증

`apps/web`에서 새 후보 폴더를 지정한다. 이미 존재하는 폴더에는 덮어쓰지 않으며 원본 다섯 개가 전부 성공해야
완료된 manifest가 생긴다. 조회 실패·공식 화면 변경·로그인 요구가 있으면 실패로 끝내며 이전 앱 자료는 유지된다.

```bash
node scripts/capture-datalab-visitor-profile.mjs --out ../../output/imsil-2025-refresh
node scripts/build-datalab-visitor-profile.mjs
node scripts/build-datalab-visitor-profile.mjs --verify
```

수집 명령은 후보만 만든다. 기존 원본과 새 후보의 기간·축제·개최지·정의·수치·현재 관광자원 관계를 확인한 뒤
프로젝트 원본을 갱신하고 생성·검사 명령으로 앱 자료를 만든다. 사람 재승인을 새로 요구하는 절차는 아니다.
생성기는 원본 해시, 조회 기간, ID·개최일·지역·비율·순위·연결 관계가 잘못되면 중단한다.
내부 경로·검증 메모·해시는 서버 자료에만 두고 공개 응답은 표시할 값과 출처만 제공한다.
